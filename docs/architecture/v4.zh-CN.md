## 1. 系统概览

### 1.1 框架身份（不变）

Synonz 是**显式、可控、可观测的 Agent 工程基础设施**（纯 Rust 库）。
四支柱（反过度抽象 / 行为可控 / 生命周期完备 / 内生可观测）与
High Level 优先原则（ADR-0010：80% 场景高层 API 解决，20% 原语自控）
共同构成一切设计的裁决标准。

### 1.2 分层结构（0.3.0 反应架构后）

```
┌─────────────────────────────────────────────────────────────┐
│ 模式层   ReAct / Research / Reflection 预设（配方打包）          │ ADR-0010
├─────────────────────────────────────────────────────────────┤
│ 组合层   Agent：执行配置（model+tools+prompt+budget）           │ ADR-0007/0015
│          持有 Runtime 引用 + observability 开关                 │
├─────────────────────────────────────────────────────────────┤
│ 执行面   Execution：叙事流（ExecutionEvent 交付）+ 终点 Future   │ ADR-0014
│          + 控制器（cancel / with_timeout / rounds）             │
├─────────────────────────────────────────────────────────────┤
│ 会话层   Conversation（真相：Turn + outcome 全入史 + 生命周期    │ ADR-0011/0015/0017
│          状态）/ TurnInput                                     │
├─────────────────────────────────────────────────────────────┤
│ 背景层   Context（pub(crate)）：背景引擎（组装），取材唯记忆      │ ADR-0012/0015
├─────────────────────────────────────────────────────────────┤
│ 策展层   MemoryCurator：订阅生命周期事实、执行记忆流转的行动者    │ ADR-0017
├─────────────────────────────────────────────────────────────┤
│ 记忆层   Memory 聚合（使用侧一体）＝ L1 / L2 / L3 三契约位        │ ADR-0017
│          （存储侧独立扩展）                                     │
├─────────────────────────────────────────────────────────────┤
│ 运行时层 SynonzRuntime（Bootstrap + 契约注册表 + 事件总线）+     │ ADR-0012/0017
│          Subject                                               │
├─────────────────────────────────────────────────────────────┤
│ 原语层   Model / Tool / SynonzEvent / canonical Message         │ ADR-0003/0005/0006/0017
├─────────────────────────────────────────────────────────────┤
│ 适配层   synonz-openai / synonz-anthropic / synonz-mcp         │ ADR-0008
└─────────────────────────────────────────────────────────────┘
  ═══════════════════════════════════════════════════════════
   事件总线（横切设施，非一层）：EventSource ──emit──→ EventBus
   ├ 观察车道（旁路·N 个 Observer·丢弃+lag）      ADR-0017
   └ 行动车道（同步·Curator 契约位单实例）
   交付路（横切，非总线）：EventTap ──consumer──→ ExecutionEvent
   （背压·per-run——交付不是事件驱动）             ADR-0014/0017
```

依赖方向永远向下。**Agent 持有 Runtime**：执行链全部服务自顶向下
流动；会话是纯数据实体（真相 + 身份 + 生命周期状态），跨 runtime
混用在结构上无法造成分裂写入。

**事件总线与交付路都是横切设施，不是层**：总线承载"事实发生→
订阅者反应"（观察 + 反应）；交付路承载"执行→产品消费者"（背压
点对点）。两者语义分离（§9.1 术语立法），互不隶属。

## 2. 运行时与主体

### 2.1 SynonzRuntime：显式 Bootstrap + 契约注册表 + 事件总线

```rust
let runtime = SynonzRuntime::builder()
    .conversation_store(store)   // 会话真相存取（缺省进程内）
    .l1_store(l1)                // L1 工作记忆（缺省内置内存实现）
    .l2_store(l2)                // L2 摘要层（缺省进程内；可换 Redis…）
    .l3_store(l3)                // L3 知识层（缺省进程内；可换向量库…）
    .context_assembly(strategy)  // 组装策略（缺省 LayeredMemory）
    .memory_curator(curator)     // 记忆策展（缺省 DefaultCurator；行动位单实例）
    .observer(exporter)          // 观察者（可多个；总线观察位）
    .idle_timeout(duration)      // 空闲超时（sweep_stale 兜底用）
    .build();
```

- 显式构造、同源保证：全部环境在同一个 Runtime 上装配；
- 契约位未注册即用进程内默认实现（零注册即用）；
- 默认策展便捷位：`memory_policies` / `topic_detector`（构造
  DefaultCurator 用；一旦显式设置 `memory_curator`，两者被忽略，
  文档写明）；
- **Observer 不注册 = 观察位为空**（总线仍在——Curator 行动车道
  与生命周期事实照常工作；观察位仅承载目击）；
- Runtime 持有**事件总线**（常驻派发器，随 Runtime 生灭）；
- `sweep_stale`：应用调度的空闲兜底，对超时会话调 `conv.end(self)`
  （IdleSwept）——失败经总线可见，ended 会话被过滤。

### 2.2 Subject：主体身份（不变）

`Subject = (SubjectType, id)`。`SubjectType::User` 现用；
`SubjectType::Agent` 为 S3 预留。会话必有主体。

### 2.3 Agent 与 Runtime 的容器关系（不变）

```rust
let agent = Agent::builder()
    .runtime(&runtime)      // 必选：Agent 知道自己活在哪个容器
    .model(model)           // 必选
    .tool(my_tool)
    .observability(true)    // 交付开关（默认 false）
    .build()?;
// 预设同构：Agent::react(&runtime, model, tools) / research / reflection
```

## 4. 公共 API 全景（0.3.0 形态）

### 4.1 执行（唯一入口，不变）

```rust
let mut execution = agent.run(conv.turn_input("北京天气？"));
let output: AgentOutput = execution.await?;      // 流自足
execution.cancel();
execution.with_timeout(Duration::from_secs(30));
execution.rounds();
```

`ExecutionEvent` 六变体不变（Delta/ToolRequested/ToolCompleted/
Failed/Cancelled/Completed）——它是 Turn 族事实的**交付投影**。

### 4.2 会话（生命周期三入口，全带环境）

```rust
let conv = Conversation::new(&runtime, &subject)?;       // 创建：构造+落库+emit Created
let conv = Conversation::with_id(&runtime, &subject, id)?;
let conv = Conversation::of(&runtime, &subject, id)?;    // 恢复（缺者报错）
conv.turn_input("...")            // 唯一执行入口的参数来源
let outcome = conv.end(&runtime).await;   // 终结：标记+落库+emit Ended（async，幂等）
conv.is_ended()                   // 生命周期状态查询
conv.export()?                    // 真相轮次导出（记忆层不随行）
conv.messages(); conv.turns(); conv.topic();
// push_turn / set_topic：pub(crate)——归框架
// 已删除：truncate_last / clear / fork / import / context()
```

三个生命周期入口同构（构造 / 恢复 / 终结 = 标记 + 持久化 + 发
事件——环境见证，非服务编排）。

### 4.3 Model 契约（不变）

`ModelRequest { messages, tools }`；params 绑定适配器构造。

### 4.4 Observer 契约（签名扩展）

```rust
pub trait Observer: Send + Sync + 'static {
    /// 全量事件目击（Turn/Conversation/Memory 三族）。实现必须快速返回。
    fn on_event(&self, ctx: &ObserverContext, event: &SynonzEvent);
    /// 观察队列溢出丢弃后，总线派发器追上时调用（累计丢弃数）。
    fn on_lagged(&self, ctx: &ObserverContext, dropped: u64) {}
}

#[non_exhaustive]
pub struct ObserverContext {
    /// run 源事件的执行归属（Turn 族=Some；run 外事实=None）。
    pub execution_id: Option<u64>,
}
```

### 4.5 MemoryCurator 契约（新增）

```rust
#[async_trait]
pub trait MemoryCurator: Send + Sync + 'static {
    /// 轮次完成（终态事件前被 await）。同步段应快速返回；
    /// 重维护（压缩/蒸馏）建议后台化（文档立法）。
    async fn on_turn_completed(&self, ctx: &TurnContext<'_>)
        -> Vec<MemoryFlowError>;
    /// 会话终结（总线行动车道 await；返回即促进完成）。
    async fn on_conversation_ended(&self, ctx: &ConversationEndContext<'_>)
        -> Vec<MemoryFlowError>;
}
```

- 载荷：`TurnContext { conversation, input, messages, memory:
  Memory<'_>, model, events }`；`ConversationEndContext` 同构；
  字段锁死（`#[non_exhaustive]`）；
- `DefaultCurator`（默认实现，trigger 逻辑零重写搬入）：
  - 构造：`DefaultCurator::new(policies, detector)`；
  - 配置面：`with_summary_prompt` / `with_summary_model`；
  - 步骤面：`advance_topic` / `archive_l1` / `compact_l1_to_l2` /
    `distill_l2_to_l3` / `promote_l2_to_l3`（owned Job 载荷，
    spawn 友好）；
  - 时序内化：同步段（归档+主题）/ 后台段（压缩+蒸馏，spawn +
    EventSink 克隆）；终结锚点先 drain 后台队列再促进；
  - 压缩改序：摘要→append→pop（无记忆空洞）。

### 4.6 Memory 存储契约（三层独立位 + 聚合视图，新增）

```rust
// 存储侧：三个独立契约位（每层伴随自己的存储扩展）
pub trait MemoryL1Store: Send + Sync + 'static {
    fn append(&self, subject: &Subject, conv_id: &str, topic: &str,
              messages: Vec<Message>) -> Result<(), MemoryStoreError>;
    fn len(&self, subject: &Subject, conv_id: &str) -> Result<usize, MemoryStoreError>;
    fn pop_oldest(&self, subject: &Subject, conv_id: &str, count: usize)
        -> Result<Vec<L1Entry>, MemoryStoreError>;
}
pub trait MemoryL2Store: Send + Sync + 'static { /* append/len/pop_oldest */ }
pub trait MemoryL3Store: Send + Sync + 'static { /* upsert/query… */ }

// 使用侧：Memory 聚合视图（领域概念落位，调用形态不变）
pub struct Memory<'a> {
    pub l1: &'a dyn MemoryL1Store,
    pub l2: &'a dyn MemoryL2Store,
    pub l3: &'a dyn MemoryL3Store,
}
impl Memory<'_> {
    pub fn l1_append(&self, ..) -> .. { self.l1.append(..) }   // 转发
    pub fn l2_append(&self, ..) -> .. { self.l2.append(..) }
    pub fn l3_upsert(&self, ..) -> .. { self.l3.upsert(..) }
    // …
}
```

L1 默认内置内存实现（纯内存是工作记忆唯一合理介质——可换但无
现实动机）；L2/L3 替换是真实场景（Redis / 向量库 / 图库）。
统一 `MemoryStore` 退役。

### 4.7 事件总线与 SynonzEvent（词汇表全量）

```rust
impl EventBus {
    /// 入参类型锁死：非框架事件编译期无法上总线。
    pub async fn emit(&self, event: SynonzEvent) -> DispatchOutcome;
}
```

```rust
#[non_exhaustive]
pub enum SynonzEvent {
    Turn(TurnEvent),                 // 轮次执行叙事（原 AgentEvent）
    Conversation(ConversationEvent), // 会话生命周期
    Memory(MemoryEvent),             // 记忆流转与失败
}

pub enum TurnEvent {
    Lifecycle(LifecycleEvent),   // Started / Completed / Failed / Cancelled
    Model(ModelEvent),           // Requested / StreamDelta / Responded
    Tool(ToolEvent),             // CallRequested / CallCompleted
}

pub enum ModelEvent {
    Requested { purpose: CallPurpose, messages: Vec<Message>, round: Option<usize> },
    StreamDelta { delta: ModelDelta, round: Option<usize> },
    Responded { message: Message, usage: TokenUsage, round: Option<usize> },
}
pub enum ToolEvent {
    CallRequested { call: ToolCall, round: Option<usize> },
    CallCompleted { call_id: CallId, result: ToolResult, round: Option<usize> },
}
// round：推理循环序号（1-based）；None=循环外维护调用（与 purpose 互证）

pub enum ConversationEvent {
    Created { conversation_id: String, subject_id: String },
    Ended { conversation_id: String, subject_id: String, reason: EndReason },
    TopicShifted { conversation_id: String, from: String, to: String },
}
pub enum EndReason { Explicit, IdleSwept }

pub enum MemoryEvent {
    TurnArchived { conversation_id: String, subject_id: String, topic: String },
    Compacted  { conversation_id: String, count: usize },   // L1→L2
    Distilled  { conversation_id: String, count: usize },   // L2→L3
    Promoted   { conversation_id: String, count: usize },   // 终结促进
    FlowFailed { stage: MemoryFlowStage, detail: String,
                 moment: FlowMoment },
}
pub enum FlowMoment { AfterTurn, AtConversationEnd, Background }
```

全部 `Serialize + Deserialize`（两级 tag：顶层实体族 / 族内变体）；
`non_exhaustive`；事件需 `Clone`（重载荷用 `Arc` 包裹内部）。

## 5. 执行模型：单一执行面 + 交付/发布

### 5.1 一次交互的完整执行流

```
agent.run(conv.turn_input(input))
  │ 派生背景：ctx = Context::for_conversation(conv, agent 的 runtime)（内部）
  ├─ 时刻① 组装：ctx.assemble(input) → 叙事背景（经 Memory 聚合读三层）
  ├─ emit Turn::Started（交付 + 总线发布）
  ├─ 推理循环（≤ max_rounds，缺省 16；round 序号 1-based 入载荷）：
  │    Model::Requested(Reasoning, round) → 流式调用
  │    StreamDelta(round) ×N → ToolCall → 并行执行（完成序事件 / 调用序回填）
  │    └ 结果回填 → 下一轮（round+1）
  ├─ 完成后：
  │    conv.push_turn(Turn { input, messages, outcome })           ← 真相归档（内存）
  │    runtime.conversation_store().save(conv.state())            ← 持久化（显式驱动）
  │    curator.on_turn_completed(TurnContext).await               ← 终态事件前
  │       同步段：主题推进（TopicShifted 判定经总线）+ L1 归档
  │               （TurnArchived 经总线；FlowFailed{AfterTurn} 可见）
  │       后台段 spawn：压缩（Compacted）/ 蒸馏（Distilled）
  │               （EventSink 克隆保活；失败 Background 上报）
  ├─ emit 终态：Completed(output)（失败→Failed；中断→Cancelled）
  └─ 每次发射双路：交付路（背压→ExecutionEvent）+ 总线（先感知）
```

### 5.2 语义要点

- **流自足**：`Completed` 携带 `AgentOutput`；终态不变量：终态
  事件必为交付流最后一项，之后流关闭；
- **round 载荷**：消费者免除推导（不再数 Requested、不再处理
  辅助调用干扰——`None` 与 `ContextManagement` 互证）；
- **环境流向**：执行链服务全部来自 Agent 的 runtime；会话纯数据；
- **取消四入口一信号**（不变）：cancel() / drop RAII / with_timeout
  / run_with(token) → `Cancelled(CancelReason)`。

## 6. 对象生命周期与编程范式

事件视角的执行流见 §5.1；本节是**对象与范式**视角——每个对象何时
诞生、何时消亡、应用代码如何组织。两者合读即为完整原理。

### 6.1 生命周期五阶段

**阶段一：Bootstrap（应用启动，一次）**

```rust
let runtime = SynonzRuntime::builder().build();      // 零注册即用
// 或逐位注册：.l3_store(vector_store).observer(exporter)…
```

| 对象 | 诞生 | 寿命 | 死亡 |
|---|---|---|---|
| SynonzRuntime | `build()` | 应用全程 | 应用退出 |
| 事件总线 + 常驻派发器 | 同 runtime | 同 runtime | 同 runtime |
| 服务实例（store×4 / assembly / curator / observers） | 注册或缺省 | 同 runtime | 同 runtime |

**阶段二：Configure（每个 Agent 角色，一次）**

```rust
let agent = Agent::react(&runtime, model, tools)
    .observability(true)
    .build()?;
```

| 对象 | 诞生 | 寿命 | 死亡 |
|---|---|---|---|
| Agent | `build()` | 长存（克隆廉价） | dropped——无运行时状态，无泄漏面 |

**阶段三：Session（每个用户会话）**

```rust
let conv = Conversation::new(&runtime, &subject)?;      // 创建（三动作）
let conv = Conversation::of(&runtime, &subject, id)?;   // 从 store 恢复
```

| 对象 | 诞生 | 寿命 | 死亡 |
|---|---|---|---|
| Conversation | new / of | 长存（克隆 = 同一会话） | dropped——**落账状态在 store 里活得比它久** |

**阶段四：Turn（每次执行——对象最密集）**

```rust
let mut execution = agent.run(conv.turn_input("问题")); // ①②③ 瞬时发生
```

`run()` 的同步部分瞬时完成三件事：拆包 TurnInput → 派生执行机器
（交付通道、tap、任务、runner）→ 返回句柄；随后后台任务开始推理
循环。

| 对象 | 诞生 | 寿命 | 死亡 |
|---|---|---|---|
| TurnInput | `conv.turn_input()` | 一条语句 | 被 `run()` 消费（**可变借用**串行化同会话轮次） |
| Execution | `run()` 返回 | 消费者持有 | dropped（**drop = RAII 取消**） |
| AgentLoopTask | `run()` spawn | 单次 run | 终态 / 取消 |
| Context | 循环内派生 | 单次 run | run 结束（pub(crate)，无状态绑定器） |
| 交付 tap | `run()` | run + 清空交付通道 | 消费者消失后退出 |
| Turn | run 终态 | **永存**（会话内 + store） | 数据删除 |

**阶段五：Teardown（可选）**

```rust
conv.end(&runtime).await;   // 三动作 + 总线行动车道 → Curator 促进（返回即完成）
runtime.sweep_stale();      // 应用调度的空闲兜底（IdleSwept）
```

| 对象 | 诞生 | 寿命 | 死亡 |
|---|---|---|---|
| 后台维护任务 | Curator spawn（每轮） | 压缩/蒸馏完成 | EventSink 释放后退出（失败经总线 Background 上报） |

### 6.2 执行流原理图（主链 + 交付路 + 总线双车道）

```
┌──────────── 主执行链 ─────────────┐
│ L0 应用层                          │
│  turn_input → run → next/await    │
│  /cancel                          │
└─────┬──────────────────────────────┘
      ▼
┌ L1 入口 · Agent::run（同步）───────────────┐

```

### 6.3 退出路径全表（生命周期的"死法"）

| 路径 | 触发 | 落账 | 终态事件 | 观察面 |
|---|---|---|---|---|
| 完成 | 模型无工具调用收尾 | Turn::completed + 持久化 | Completed(output) | ✅ 全量含装配载荷 |
| 失败 | 模型流 Err / 无 Finish / max_rounds 耗尽 | Turn::failed | Failed | ✅ |
| 取消-1 | token / cancel() / timeout（三挂起点） | Turn::cancelled | Cancelled | ✅ |
| 取消-2 | 预循环抢跑（取消先于循环） | Turn::cancelled | Cancelled | ✅ |
| 取消-3 | **drop(Execution)**（RAII：消费者消失） | Turn::cancelled | 消费者已不在——仅观察面收到终态 | ✅ 终态不丢 |

### 6.4 编程范式

1. **声明式配置 + 命令式执行**：runtime / agent 是声明式长存配置，
   会话是数据，每个 turn 是一次命令式执行；
2. **借用检查器即轮次串行器**：同会话并发轮次在编译期被拒绝
   （`turn_input` 的可变借用），不是运行时锁；
3. **组合自由**：多 Agent 续同一会话（各 run 各落账）/ 一个 Agent
   并行多会话（Agent 无状态、克隆廉价）；
4. **RAII 即取消**；错误路径的设计取向是"错误不可表达"优先于
   "报错拦截"；
5. **反应即订阅**：观察位自由注册（下游自由），行动位立法扩展
   （新契约 = 新 ADR，非破坏）——扩展性的两条路径分层表达；
6. **交付与订阅分离**：产品消费者接收交付（背压），订阅者目击/
   反应（旁路/同步）——两种契约永不混用。

所有权与并发规则：

| 规则 | 机制 |
|---|---|
| 同会话并发轮次 | 编译期拒绝（可变借用） |
| 一个 Agent × 多会话并行 | Agent 无状态，每次 run 独立 |
| 多 Agent × 同一会话续写 | 会话纯数据；每个 run 记录自己的轮次 |
| 跨 runtime 混用 | 结构上无法腐败（会话不带环境，服务来自操作者） |
| 同一会话重复终结 | 结构上幂等（ended 状态 + 首次判定收口） |
| 取消 | 四入口一信号（§10.1） |

## 7. 会话与真相

| 语义 | 决策 |
|---|---|
| 落账 | **全入史**：`Turn { input, messages, output, outcome }`，outcome ∈ {Completed, Failed, Cancelled} |
| 写入点 | `push_turn` 唯一（pub(crate)，框架所有） |
| 记忆触发面 | **仅成功轮写入 L1**（失败轮不污染记忆层） |
| 持久化 | 经 ConversationStore 自动保存；失败可见（never-silent） |
| 生命周期 | 三入口全带环境：new/with_id（构造+落库+emit Created）/ of（恢复）/ end（终结三动作，幂等） |
| 状态 | `ConversationState` 含 ended——重复终结结构上收口，sweep 过滤 |
| 两终结时机 | `EndReason::{Explicit, IdleSwept}`：用户主动（调用者在场，EndOutcome 携带软失败）/ 程序兜底（无人在场，失败经总线） |
| 导出 | export = 真相轮次（可迁移）；记忆层是三契约位事务，不随行 |
| 工厂 | new = 创建 / of = 恢复（缺者报错）/ ensure = get-or-create（S3） |

真相与背景的归档对称：**Conversation 归档真相（Turn，含失败），
Curator 归档背景（记忆层，仅成功）**——两种归档，互不越界。

## 8. 背景与记忆

### 8.1 Context：背景引擎（pub(crate)，组装行为）

| 行为 | 时机 | 内容 |
|---|---|---|
| 组装 `assemble` | 模型调用前 | 按策略装配叙事背景（每次新鲜） |

- **归档与压缩已整体移交 Curator**（经总线行动车道）——Context
  不再是"三行为引擎"，只剩组装；v3 的"背景引擎三行为"由
  "组装（Context）+ 策展（Curator）"取代，边界更纯：Context
  管"模型看到什么"，Curator 管"记忆怎么流转"；
- Context 从公开面**内部化**（`Conversation::context()` 删除）：
  "模型看到什么"的可信证据是 Turn::Model::Requested 载荷，
  "策略拼出什么"可直接调 `ContextAssembly` 契约，"记忆层诊断"
  可直读各层 store——三个候选场景均被更优公开面覆盖；
- **取材唯记忆**：`AssemblyRequest { memory: Memory<'_>, subject,
  conversation_id, topic, input }`——策略读会话实体在类型上
  不可表达；
- 装配格式（不变）：`[System 人格] [System: Memory recall] [L2
  摘要] [L1 窗口] [User 本轮输入]`；
- 装配联动主题漂移：`AssemblyRequest.topic` 每轮现读（既有机制）
  ——漂移后下一轮装配自然切换检索焦点，无需事件驱动。

### 8.2 记忆存储：三契约位与聚合视图

```
工程层（存储侧）：三个独立契约位——每层伴随自己的存储扩展
  MemoryL1Store（默认：内置内存——纯内存是工作记忆唯一合理介质）
  MemoryL2Store（默认进程内；可换 Redis…）
  MemoryL3Store（默认进程内；可换向量库/图库…）
  RuntimeBuilder 三个注册位；运行时 Runtime 持有三个位

领域层（使用侧）：Memory<'a> 聚合视图
  Curator / ContextAssembly 拿到聚合；memory.l1_append(..)
  调用形态不变（转发）——概念一体与独立替换兼得
```

- **感知延迟梯度**（分层设计核心 rationale）：记忆感知延迟 =
  记忆产生后 Agent 感知到它的速度——L1 即时 > L2 近期 > L3
  长期。各层 rustdoc 写明性能特征引导（插件自带非功能特征责任，
  同 Model/Tool 插件原则）；
- **边界立法：存储位不得策展**——存储插件不得在 append 时
  压缩/蒸馏（策展时机由生命周期事实驱动，存储位感知不到；
  可见性立法在 Curator 层）；
- 扩展轴正交：换策展哲学改 Curator；逐层换存储改对应 `MemoryL*Store`
  位；互不影响。

### 8.3 记忆策展：MemoryCurator

- **契约双重中立**：分层哲学（L1/L2/L3、楼层、递进）不下沉契约；
  时序工程（后台化、顺序、延迟）不下沉契约——契约只锚定两个
  领域事实（轮次完成、会话终结）；
- **时序语义**（实现者可依赖 + 实现自由两层）：

| 锚点 | 框架保证 | 同步段（方法体内直接执行） | 后台段（方法体内 spawn） |
|---|---|---|---|
| `on_turn_completed` | 终态事件前 await | 即时感知档：下一轮装配必见 | 近期感知档：滞后生效，实现者自管完成与回收 |
| `on_conversation_ended` | 总线行动车道 await，返回即促进完成 | —（drain 后台 + promote） | — |

- **DefaultCurator 三档定制**：零扩展（默认）/ 浅定制（配置面：
  with_summary_prompt / with_summary_model）/ 深定制（组合委托：
  步骤面公开零件，自管后台与顺序——文档明确此责任）；
- **入册原则**：事实发生即可见——Curator 的每次真实流转
  （TurnArchived/Compacted/Distilled/Promoted）都通知总线。

## 9. 事件总线（ADR-0017 核心）

### 9.1 概念模型与术语立法

| 概念 | 定义 |
|---|---|
| **EventBus** | Runtime 持有的派发设施——感知事件（被 emit 通知）→ 派发给订阅位；与发射端是使用关系而非组成关系，对"谁在告知"零知识 |
| **EventSource** | 通知总线的主体（执行循环、`Conversation::new`/`end`、sweep、Curator 流转）——**定义性动作只有一个：emit** |
| **EventListener（订阅位）** | 观察车道订阅者（N 个 Observer）与行动车道契约位（单实例 Curator） |
| **Event（SynonzEvent）** | 总线承载的事实类型，入参类型锁死（封闭枚举，非框架事件编译期无法上总线） |

**术语立法（唯一性）**：

- **事件驱动模型 = 总线体系，有且仅有**。凡事件驱动皆经总线；
- **交付不是事件驱动**：产品消费者接收交付（ExecutionEvent 流，
  点对点、背压、per-run）是执行面固有的输出管道——如同函数
  返回值不叫事件驱动。交付不经总线，不因总线存在与否而变化；
- 执行循环有两个无关身份：作为执行面交付叙事（非事件驱动）；
  作为 EventSource 通知总线（事件驱动）；
- `ExecutionEvent` 是 Turn 族事实的**交付投影**（类型复用不是
  体系混淆：总线派发=事件驱动，投影交付=输出管道）。

### 9.2 双车道与订阅位

```
EventSource ──emit──→ EventBus（Runtime 持有·常驻派发器）
                        ├── 观察车道：旁路·异步·丢弃+lag 计数·N 个
                        │   Observer（熔断隔离·保序·终态后 drain）
                        └── 行动车道：同步 await·契约位单实例
                            MemoryCurator 位（未来新行动位=新 ADR 立法）
```

- **双车道语义**：行动者同步等（结果可回收），观察者旁路看
  （绝不拖慢执行）；
- **订阅位制**：观察位 N 个（下游自由注册）；行动位每契约单
  实例（记忆策展唯一哲学——两个 Curator 同时促进即重复执行）；
- **发射顺序立法**：总线先感知（订阅者不落后于交付）；
- **通道内保序**（单观察者按发射序）；跨事件族时序不承诺；
- **后台失败可见性**：Curator 后台任务携带 EventSink 克隆——
  失败投 `MemoryEvent::FlowFailed { moment: Background }`，
  观察位可见、交付流不可见（终态不变量保持）——分层可见性。

### 9.3 发射源 × 订阅位矩阵

| EventSource | emit | 观察位 | 行动位 | 交付 |
|---|---|---|---|---|
| 执行循环 | Turn 三子族 | ✅ | — | ✅ ExecutionEvent 投影 |
| 执行循环（同步段失败） | MemoryEvent::FlowFailed{AfterTurn} | ✅ | — | — |
| `Conversation::new`/`with_id` | ConversationEvent::Created | ✅ | — | — |
| `Conversation::end`/sweep | ConversationEvent::Ended | ✅ | ✅ `on_conversation_ended` | — |
| Curator（`advance_topic` 判定漂移） | ConversationEvent::TopicShifted | ✅ | — | — |
| Curator 各流转/失败回收 | Memory 四流转/FlowFailed | ✅ | — | — |

治理原则：**行动位只对生命周期事实反应**（记忆业务边界）；Turn
事件只被目击与交付（不驱动记忆——记忆反应锚在 Curator 契约的
时刻上）。

### 9.4 扩展点生效时序（全景契约）

| 扩展点 | 调用时机 | 生效边界 | 失败语义 |
|---|---|---|---|
| `Model` | 推理循环每轮 | 直接决定本轮输出 | 终态 Failed |
| `Tool` | 模型请求时（并行） | 结果回喂，影响本轮后续 | 软失败回喂 |
| `ContextAssembly` | 每 run 装配 await | 决定模型看到什么 | 降级可见 |
| `ConversationStore` | record! / 创建 / 终结时刻 | 真相持久化 | 软失败可见 |
| `MemoryL1/L2/L3Store`（经 `Memory` 聚合） | 被 Curator/Assembly 调用 | 跟随调用者时序 | MemoryEvent::FlowFailed |
| `TopicDetector` | Curator 同步段内 | 主题标签+漂移判定 | 纯计算无失败 |
| `Observer` | 事件 emit 时 | **永不影响执行** | 熔断+lag |
| `MemoryCurator::on_turn_completed` | 终态事件前 await | 同步段=下一轮必见；后台段=滞后 | 同步段返回值；后台段经总线 |
| `MemoryCurator::on_conversation_ended` | 总线行动车道 await | 返回即促进完成 | 软错误返回+总线 |

## 10. 横切语义

### 10.1 取消与超时（不变）

四入口一信号（ADR-0004）：cancel() / drop RAII / with_timeout /
run_with(token) → `CancelReason::UserRequested | Timeout`
（Parent 为 S3 预留）。agent 级 `default_timeout`（显式 opt-in）
+ per-run `with_timeout` 覆盖。

### 10.2 错误分诊

| 层级 | 形态 | 行为 |
|---|---|---|
| 工具级（软失败） | `ToolError` / `ToolResult::Err` | 喂回模型，run 继续 |
| run 级（硬失败） | `AgentError` | Failed 事件；await Err；入史（outcome=Failed） |
| 取消 | `AgentError::Cancelled` | Cancelled 事件；非失败；入史（outcome=Cancelled） |
| 记忆流失败 | `MemoryEvent::FlowFailed`（moment 载荷） | **不中断 run、不再静默**；经总线可见 |
| 装配失败 | 降级可见（AssemblyOutput.failures + stage: AssembleRead） | 背景缺失但 run 继续 |

### 10.3 序列化

`SynonzEvent`（全族）/ `Turn` / `ConversationState` 全 serde——
录制回放、真相迁移、确定性测试三大用途共享同一形状。版本演化
遵守 serde 兼容性惯例（加字段带默认值，不删不改名）。

| **TurnEvent** | 轮次执行叙事事件族（原 AgentEvent；Lifecycle/Model/Tool 三子族，round 载荷） |
| **ConversationEvent** | 会话生命周期事件族（Created/Ended/TopicShifted） |
| **MemoryEvent** | 记忆流转事件族（TurnArchived/Compacted/Distilled/Promoted/FlowFailed） |
| **EndReason** | 终结时机 `{Explicit, IdleSwept}` |
| **FlowMoment** | 记忆失败时刻 `{AfterTurn, AtConversationEnd, Background}` |
| **round** | 推理循环序号（1-based；`Option<usize>`，None=循环外维护调用） |
| **EventBus** | 事件总线：Runtime 持有的派发设施（双车道） |
| **EventSource** | 通知总线的主体（定义性动作只有一个：emit） |
| **观察位 / 行动位** | 订阅位两形态：旁路目击（N 个）/ 同步反应（契约位单实例） |
| 交付 / 订阅 | 两种投递契约：背压点对点（产品消费者）/ 总线派发（订阅者）——交付不是事件驱动 |
| Observer | 总线观察位契约（`on_event(&SynonzEvent)`；熔断+lag） |
| ObserverContext | 观察者投递上下文（`execution_id: Option<u64>`——run 源归因） |
| 双面 | 产品叙事面（ExecutionEvent 交付）↔ 工程观测面（Observer 目击） |

## 14. 边界与未来

- **S3（多 Agent 编排）**：维持后置，无时间表；预留面已标注触发
  条件（`CancelReason::Parent` / `CallPurpose::Classification` /
  `SubjectType::Agent`）；Agent 间通信（④）另立 ADR——总线
  词汇表为其留缝（顶层加实体族变体，非破坏）；
- **控制流影响**（③：拦截/改写执行，middleware 性质）：另立 ADR，
  暂无场景（IDE 路由等按执行前普通代码处理）；
- **后台工作专用模型**（Runtime 注册，承担压缩/摘要/主题检测预算）：
  **已触发**，0.3.0 后优先落地（DefaultCurator 的
  `with_summary_model` 已预留注入位）；
- **ended 状态门**（终结后拒绝续写）：状态依据已就位
  （`is_ended` + state.ended），场景出现时带 ADR 立法；
- **刻意不做**（无触发不引入）：组装策略覆灭入口、事件过滤/采样
  配置、动态观察者注销、无场景驱动的模式层抽象、下游自定义事件
  上总线（推迟——订阅位制下无反应者可认领，触发条件：下游自定义
  事件+自定义反应者的真实场景）；
- **纯回放配置**（LayeredMemory L1 全窗 + L3 预算 0）：用户真实
  需求出现再表达。
