## 1. 系统概览

### 1.1 框架身份（不变）

Synonz 是**显式、可控、可观测的 Agent 工程基础设施**（纯 Rust 库）。
四支柱（反过度抽象 / 行为可控 / 生命周期完备 / 内生可观测）与
High Level 优先原则（ADR-0010：80% 场景高层 API 解决，20% 原语自控）
共同构成一切设计的裁决标准。

### 1.2 分层结构（0.7.0 记忆组件化后）

```
┌─────────────────────────────────────────────────────────────┐
│ 模式层   ReAct / Research / Reflection 预设（应用模板：        │ ADR-0010
│          model+tools+配方打包）                                │
├─────────────────────────────────────────────────────────────┤
│ 组合层   Agent（应用）：执行配置 + Runtime 引用                 │ ADR-0007/0022

   ├ 观察车道（旁路·N 个 Observer·丢弃+lag）      ADR-0017
   └ 行动车道（同步·契约位立法，S3 预留）

   （背压·per-run——交付不是事件驱动）             ADR-0014/0017

```

**微操作系统图景**（irylex）：框架 = 微型操作系统——
- **Runtime = 系统**（全局单例——逻辑角色：一个应用一个系统环境；
  框架不强制单实例、不提供全局访问器，测试与嵌入场景可多实例并存
  且相互隔离）：系统资源（记忆 provider、真相库、观测）+ 系统设施
  （会话表、事件总线、系统调度器、终结收尾 init）；
- **系统调度器 = 系统进程**（内核态）：时间生命随 build 启动；
  Monitor 空闲清扫为其首个注册任务；开发者至多只读其快照；
- **用户调度器 = 用户态组件**：公开 `Scheduler::new`——开发者自建、
  绑定自己的执行环境（共享池或自建池），与系统调度互不侵占；
- **Agent = 应用**（实例化）：只配执行面与读侧扩展（rewriter）；
  状态引擎是**内核内置**（crate 内部），多应用差异经 provider 与
  rewriter 表达；
- **Conversation = 独立实体**：1~N 个 Agent 参与（各自 run 各落
  Turn），S3 多 Agent 编排在此之上扩展；
- **记忆 = 可替换能力**：核心随附进程内默认 provider（零配置即用）；
  官方组件 `synonz-layered-memory` 按《上下文记忆系统全链路技术
  方案》实现分层记忆（L1 按轮条目 / L2 批量压实 / L3 图谱+向量+
  蒸馏；存储契约、策略、embedding 均在组件侧；ADR-0028 重定）；
- 后台维护任务 = 进程产生的 IO 任务，系统调度执行（任务由流水线
  模板派生，句柄登记进系统会话表）。

依赖方向永远向下；行为与数据分离（实现经上下文语义入口读取状态，
见 §8）。

## 2. 运行时与主体

### 2.1 SynonzRuntime：系统装配（主位 + 系统设施）

```rust
let runtime = SynonzRuntime::builder()
    .conversation_store(store)   // 系统资源：会话真相存取（缺省进程内）
    .memory_provider(provider)   // 记忆能力：MemoryProvider（缺省 = 核心进程内默认；命名以实施为准）
    .observer(exporter)          // 系统观测：总线观察位（可多个）
    .conversation_idle_timeout(duration) // 配置：会话空闲超时（Monitor 清扫阈值）
    .build();
```

> 记忆 provider 的装配方式（构建器形态/命名）属实现设计（ADR-0026
> 前提）；`conversation_idle_timeout` 为系统空闲清扫的阈值——
> **配置即点火**：build 时注册 Monitor 任务（系统调度器，Skip 策略、
> 立即首触发，见 §2.4）。

`build()` 内部一次性完成（系统装配）：

1. **记忆能力解析**：从 `MemoryProvider` 取得 `Arc<dyn Memory>` /
   `MemoryContextAssembler` / `MemoryPipeline`，Runtime 持有
   （`runtime.memory()` 暴露条目级管理面，ADR-0022 §9/§11）；未配置
   provider 时使用**核心进程内默认 provider**（非分层，零配置即用，
   ADR-0023）；
2. **会话表创建**：会话归属登记 + `conversation_id → 后台维护任务
   句柄`（系统调度后台 IO；见 §7）；
3. **事件总线常驻派发器 spawn**（随 Runtime 生灭）；
4. **系统调度器创建**：捕获宿主 Executor Handle（W1；在宿主 async
   上下文内 build 自动捕获，同步构建场景经 builder 显式注入；配置
   `conversation_idle_timeout` 而两者皆无 = 配置错误，build panic
   并指明修复方式）；配置 `conversation_idle_timeout` 时注册 Monitor
   空闲清扫任务（立即首触发）；计时线程随即启动（见 §2.4、§6）；
5. 终结收尾行为就绪（init 模式：有界排空会话任务 +
   `finalize_conversation` 钩子，见 §7）。

主位：会话真相存储 / 记忆 provider / 观察位（N）；**零便捷位**；
未配置 provider = 核心进程内默认（零注册即用）；Observer 不注册 =
观察位为空（总线照常工作）；系统调度器不是注册位（内核态、不可注册；
开发者只读快照）。

### 2.2 Subject：主体身份（不变）

`Subject = (SubjectType, id)`。`SubjectType::User` 现用；
`SubjectType::Agent` 为 S3 预留。会话必有主体。

### 2.3 Agent：应用装配（读侧扩展）

```rust
let agent = Agent::builder()
    .runtime(&runtime)          // 系统引用（必选）
    .model(model)               // 必选（Provider/Rewriter 未配模型时的回退 = agent 模型）
    .tool(my_tool)
    .rewriter_provider(provider) // 读侧唯一扩展点：RewriterProvider（可选；缺省 = 不改写）
    .build()?;
// （总线无条件发布——observability 开关已退役）
// 预设 = 应用模板：Agent::react(&runtime, model, tools) 打包 react
// 配方，research / reflection 同构
```

- **Agent 不再配置 Context**：状态引擎是 crate 内部的内置引擎
  （ADR-0022 §3）——读相位（rewriter → assembler）与写相位（流水线
  模板）由核心编排；Agent 只保留执行配置与读侧 rewriter 扩展；
- **多 Agent 差异**：经 provider（记忆能力）与 rewriter（输入预处理）
  表达；多 Agent 参与同一会话时共同维护同一记忆——**策略一致性是
  应用/编排层的责任**（框架提供机制不强制，no magic）；
- Agent 克隆廉价。

### 2.4 Scheduler：时间调度（系统调度器与用户调度器）

**组件边界**：Scheduler 是「时间驱动的任务调度组件」——决定「何时
产生执行机会」；执行交给宿主 Executor（决定「在哪运行」）；任务
客户端决定「执行什么」。Timer（时间等待）是 Scheduler 的内部机制；
线程池不属于 Scheduler；任务到达触发时间只意味着应被提交执行，
不意味着已开始运行（触发准时 ≠ 开始准时）。

**双层主权**（微 OS 内核态 / 用户态）：

| 形态 | 创建 | 注册 | 开发者接触面 |
|---|---|---|---|
| 系统调度器（内核态） | Runtime build 内部创建；计时生命随 build 启动 | 仅框架内部（Monitor 等系统任务） | 只读快照（/proc 风格：任务名/周期/策略/距下次触发/运行中） |
| 用户调度器（用户态） | 开发者自建（`Scheduler::new(executor)`） | 开发者自有任务 | 全部公开 API |

**时间模型**：计时线程（单条轻量系统线程：登记 / deadline / 等待 /
触发 / 提交，不执行任何业务；不形成 worker pool）；立即首触发
（注册即触发一次，之后每周期）；固定速率 + 追赶保护（过载后按
周期倍数跳到当前时间之后，不一次补发积压触发）；触发与提交为
非阻塞 handoff——执行慢不阻塞触发、任务 panic 不杀死计时线程。

**并发策略（OverlapPolicy，每任务一个）**：

| 策略 | 上次未完成时 | 积压上限 | 适用 |
|---|---|---|---|
| Skip | 丢弃本次触发 | — | 清扫/巡检（错过一次无妨） |
| Concurrent | 立即再起一层 | 无界（池容量兜底） | 每次都必须执行的独立作业 |
| Queue（合并） | 记一次 pending，完成即续跑 | **1** | 必须完成、不可自并发（自动保存等） |

**宿主模型（W1）**：执行提交经宿主的共享 Executor
（`tokio::runtime::Handle`）——Scheduler 不自持执行池、不与
应用形成双池。详见 ADR-0018 §2-5。

## 4. 公共 API 全景（0.7.0 形态）

### 4.1 执行（唯一入口，不变）

```rust
let mut execution = agent.run(conv.turn_input("北京天气？"));
let output: AgentOutput = execution.await?;      // 流自足
execution.cancel();
execution.with_timeout(Duration::from_secs(30));
execution.rounds();
```

`ExecutionEvent` 六变体不变——Turn 族事实的**交付投影**。

### 4.2 会话（生命周期三入口，全带环境）

```rust
let conv = Conversation::new(&runtime, &subject)?;       // 创建：构造+落库+emit Created
let conv = Conversation::with_id(&runtime, &subject, id)?;
let conv = Conversation::of(&runtime, &subject, id)?;    // 恢复（缺者报错）
conv.turn_input("...")            // 唯一执行入口的参数来源
let outcome = conv.end(&runtime).await;   // 终结：标记+落库+emit Ended（async，幂等）
conv.is_ended()                   // 生命周期状态查询
conv.export()?                    // 真相轮次导出（记忆层不随行）
conv.messages(); conv.turns(); conv.topic();
// push_turn / set_topic：pub(crate)——归框架
// 已删除：truncate_last / clear / fork / import / context()
```

三个生命周期入口同构（构造 / 恢复 / 终结 = 标记 + 持久化 + 发
事件——环境见证，非服务编排）。

`ModelRequest { messages, tools }`；params 绑定适配器构造。

### 4.5 记忆契约族与内置引擎（ADR-0022/0023/0025/0027）

> ADR-0022：记忆能力由**核心契约族**定义——三个抽象（条目管理 /
> 读 / 写）+ 两个工厂；ADR-0023：核心提供进程内默认实现，读通道为
> 条目级只读投影；ADR-0025：读/写相位获得**叙述 LLM**、读相位产出
> **完整消息帧**（含空帧兜底）、管理面增**作用域寻址**；ADR-0027：
> **主题检测独立成 Agent 级扩展点**（`TopicDetectorProvider`），
> `MemoryPipeline` 钩子四 → 三；`Context` 收为 crate 内部的内置引擎，
> 不再公开。下列签名展示形状（命名与细节以实施为准），语义以 ADR
> 为准。

```rust
// —— 条目级管理抽象（应用面；由 provider 的实现提供）——

/// 条目管理（subject 按调用传递）。runtime.memory() 返回它。
pub trait Memory: Send + Sync + 'static {
    fn list(&self, subject: &Subject, query: MemoryQuery)
        -> Result<MemoryPage<MemoryItem, MemoryListCursor>, MemoryStoreError>;
    fn get(&self, subject: &Subject, id: &str)
        -> Result<Option<MemoryItem>, MemoryStoreError>;
    fn edit(&self, subject: &Subject, id: &str, content: impl Into<String>)
        -> Result<MemoryItem, MemoryStoreError>;     // 原地更新，id 不变
    fn forget(&self, subject: &Subject, id: &str)
        -> Result<MemoryForgetResult, MemoryStoreError>;
    fn forget_matching(&self, subject: &Subject, query: MemoryQuery)
        -> Result<MemoryForgetResult, MemoryStoreError>;
}

/// 条目视图（核心最小集，ADR-0023）：层无关、可解释、跨实现可担保。
/// memory_type 与组件语义字段不在核心（组件富管理面，ADR-0026 §7）。
pub struct MemoryItem {
    pub id: String,
    pub content: String,
    pub source: MemorySource,      // { conversation_id, topic }——最近一次写入
    pub scope: MemoryScope,        // 记忆分区（不透明字符串；ADR-0025 §5）
    pub created_at: u64,
    pub updated_at: u64,           // 新鲜度键（列表/游标统一）
}

/// 条目级只读投影（由 dyn Memory::reader() 派生；策略实现经载荷获得）。
pub struct MemoryReader<'a> { /* 条目 list/get/query（只读） */ }

// —— 读抽象：上下文组装（完整消息帧）——

pub trait MemoryContextAssembler: Send + Sync + 'static {
    fn assemble<'a>(&'a self, input: MemoryContextAssembleInput<'a>)
        -> BoxFuture<'a, MemoryContextAssembleOutput>;
}

#[non_exhaustive]
pub struct MemoryContextAssembleInput<'a> {   // 原料域可扩展
    pub reader: MemoryReader<'a>,             // 条目级只读代理（ADR-0023）
    pub subject: &'a Subject,
    pub conversation_id: &'a str,
    pub topic: &'a str,                       // 核心会话属性
    pub input: &'a str,                       // 本轮原始输入（真相域）
    pub rewritten_input: Option<&'a str>,     // 模型视图（rewriter 输出）
    pub model: Arc<dyn Model>,                // ★ 叙述 LLM（ADR-0025 §1）
}

#[non_exhaustive]
pub struct MemoryContextAssembleOutput {
    pub messages: Vec<Message>,               // ★ system 之后的完整消息帧（含本轮模型可见用户消息；ADR-0025 §2）
    pub failures: Vec<MemoryFailure>,         // 降级可见
}

// —— 写抽象：记忆流水线（抽象类：模板 + 三个业务钩子）——

/// 模板方法由核心提供（机制内置：写回 topic、发生命周期事实、派生
/// 后台任务、会话终结先有界排空再调钩子）；实现者只提供三个业务钩子。
pub trait MemoryPipeline: Send + Sync + 'static {
    fn archive_turn<'a>(&'a self, ctx: &'a PipelineTurnContext<'a>)
        -> BoxFuture<'a, ()>;
    fn spawn_task<'a>(&'a self, ctx: &'a PipelineTurnContext<'a>)
        -> BoxFuture<'a, ()>;
    fn finalize_conversation<'a>(&'a self, ctx: &'a PipelineConversationContext<'a>)
        -> BoxFuture<'a, ()>;
}

/// 上下文语义入口（框架提供的契约）：数据读取（含本轮 topic 变更）+
/// set_topic + spawn + report_failure + 叙述 LLM（写侧 LLM 调用，
/// ADR-0025 §4）；EventSink / ConversationTaskSpawner 不出现在实现者
/// 可见面。
pub struct PipelineTurnContext<'_> { /* 读取（含 topic_change）+ set_topic + spawn + report_failure + model */ }
pub struct PipelineConversationContext<'_> { /* 同上（会话级） */ }

// —— 主题检测（独立扩展点；Agent 级，ADR-0027）——

pub trait TopicDetectorProvider: Send + Sync + 'static {
    fn topic_detector(&self) -> Arc<dyn TopicDetector>;
    fn model(&self) -> Option<Arc<dyn Model>>;    // 可选；规则同 RewriterProvider
}

/// 轮末检测（写相位前）：材料（输入 / 真相域历史 / 当前 topic /
/// 可选模型）→ 新 topic（None = 保持）；核心负责写回、`TopicShifted`
/// 事实与变更传递（经管线上下文）。
pub trait TopicDetector: Send + Sync + 'static {
    fn detect<'a>(&'a self, input: TopicDetectInput<'a>)
        -> BoxFuture<'a, Option<String>>;
}

// —— 工厂（两个）——

pub trait MemoryProvider: Send + Sync + 'static {
    fn memory(&self) -> Arc<dyn Memory>;
    fn context_assembler(&self) -> Arc<dyn MemoryContextAssembler>;
    fn pipeline(&self) -> Arc<dyn MemoryPipeline>;
    // 上下文管理模型配置（可选；模型访问方法形态属机械性补齐）
}

pub trait RewriterProvider: Send + Sync + 'static {
    fn turn_input_rewriter(&self) -> Arc<dyn TurnInputRewriter>;
    fn model(&self) -> Option<Arc<dyn Model>>;    // 可选
}

/// 输入改写（读相位预处理）：材料对象入参（含模型句柄——核心在使用
/// 时解析 Provider 模型 → 回退 Agent 模型，并统一包叙述）。
pub trait TurnInputRewriter: Send + Sync + 'static {
    fn rewrite<'a>(&'a self, input: RewriteInput<'a>)
        -> BoxFuture<'a, Result<Option<String>, MemoryFailure>>;
}

// —— 失败表示（统一；读/写两侧）——

pub struct MemoryFailure { pub stage: String, pub detail: String }
```

- **Context 内部化**：`Context` 及其旧策略槽不再公开（ADR-0022 §3）；
  内置引擎编排读相位（rewriter → assembler）与写相位（流水线模板），
  并完成模型解析与叙述；
- **读通道（ADR-0023）**：载荷 `reader` 是 `Memory` 的**条目级只读
  投影**；组件分层模型类型（L1 按轮条目 / L2 事件条目 / L3 实体与
  边等）不在核心公开面（归组件，ADR-0026/0028）；
- **模型访问（ADR-0025）**：assembler 材料与 pipeline 上下文均带
  **叙述 LLM**；`Provider 模型 ?? Agent 模型` 在**使用时**解析；
  交给实现者的模型句柄是 crate 内部叙述包装（自动
  `Requested`/`Responded`、无 `StreamDelta`）；推理循环保持手动
  叙述不变；实现者不持 `EventSink`（流程事实由模板发）；
- **完整消息帧（ADR-0025 §2）**：assembler 产出 `system(Agent)` 之后
  的完整消息帧（含本轮模型可见用户消息），核心**不再追加原始 input**；
  角色约定——system 只放 Agent 指令，记忆上下文与增强输入进 user 侧；
  真相归档 `Turn.messages` = 完整帧 + 本轮后续消息，`Turn.input` 仍为
  原始文本；
- **空帧兜底（ADR-0025 §3）**：assembler 必返含本轮用户消息的可用帧
  （失败自行降级 + `failures`）；空帧时核心用原始 input 组帧并发
  失败事实（never-silent）；
- **rewriter history（ADR-0025 §7）**：核心从**真相域**取最近成功轮
  作为 `RewriteInput.history`（可过滤失败/取消）；
- **主题检测（ADR-0027）**：独立 Agent 级扩展点 `TopicDetectorProvider`
  （可选模型，规则同 rewriter）；核心轮末调用 → 写回 `Conversation.topic`
  → 变化时发 `TopicShifted` → 本轮变更经管线上下文传给后续钩子；
  检测失败保留旧 topic + `Failed` 事实（不阻断后续）；
- **异步形态**：生命周期行为（模板、三钩子、检测器、assembler、
  rewriter）统一 async；管理动词与工厂行为保持同步；
- **模板失败语义**：尽力而为——每个钩子独立执行，失败经
  `report_failure` 上报后继续后续步骤（归档失败仍派生后台任务；
  检测失败保留旧 topic，ADR-0027）；
- **终结收尾不在引擎**：Runtime 结构行为（§7）——有界排空后调用
  `finalize_conversation` 钩子。

### 4.6 管理面：核心最小视图与组件富管理面（ADR-0023/0025/0026）

```rust
/// 核心条目视图（最小集）：只含框架可解释、跨实现可担保的内容。
pub struct MemoryItem { /* id / content / source / scope / created_at / updated_at（见 §4.5） */ }

/// keyset 分页（与 ConversationStore 同构）；limit 必须有界。
pub struct MemoryQuery { /* 会话 / topic / scope / 时间范围 / 关键字 / after / limit */ }
pub struct MemoryCursor { /* updated_at + id：单源位置 */ }
pub struct MemoryListCursor { /* position: Option<MemoryCursor>（扁平列表） */ }
pub struct MemoryPage<T, C = MemoryCursor> { pub items: Vec<T>, pub next: Option<C> }
// 核心列表扁平（新鲜度 + id keyset）；scope: Option<MemoryScope>（None = 全部合并；ADR-0025 §5）
```

- **核心最小视图（ADR-0023 收口 + ADR-0025 §5）**：
  `memory_type` 与组件语义字段不在核心；`MemoryType`、相位列表
  （`MemoryListCursor.memory_type`）、`memory_type` 过滤移出核心
  （**修订 ADR-0020 相应部分**）；新增 `scope`（条目暴露、查询可选
  过滤、`forget_matching` 可按 scope 批量）；核心默认（非分层）模型
  与组件都实现同一最小视图；
- **组件富管理面（ADR-0026 §7 / ADR-0028 §4）**：L2 条目与 L3 实体
  进核心条目视图（Summary / Knowledge 的映射为文档描述）；富面经
  组件句柄 `LayeredMemoryActuator` 暴露文档类型（`L2MemoryEntry` /
  `L3MemoryGraphEntity` / `L3MemoryGraphEdge`），并提供关系遗忘
  （`forget_l3_memory_relation`）；`runtime.memory()` 仍给核心最小视图
  （组件面为附加）；
- **subject 隔离**：管理面与组件富面一律按 subject 收窄——会话归属
  **随 L2 条目持久化**（条目携带 `subject`，存储经 `scopes(subject)`
  枚举分区；组件不持内存索引，重启后管理面仍完整），显式
  `scope` / `conversation_id` 过滤同样校验归属；L3 分区按
  `MemoryScopeResolver` 解析归属；管理面无创建动词（新增恒来自
  对话沉淀，ADR-0020 §8）；
- **管理语义（ADR-0020 保持）**：写入不分来源（用户编辑 / 系统
  写入）都是原地更新同一条（id 不变）；内核不设内容优先级——错误
  覆盖归策略质量，框架以事实保证可发现；
- **保证边界（ADR-0020 保持）**：操作返回后所有后续读路径不可见；
  在途维护不回写（写入前按 id 重校验来源，§8.3）；重观测算新证据；
  物理删除/副本/备份归存储实现；
- **注入边界（ADR-0020 保持）**：不提供日常新增（`add`）；新增恒
  来自对话沉淀；批量导入/迁移由应用自持存储句柄在框架外完成；
- **新鲜度（ADR-0020 保持）**：统一 `updated_at`（创建时 =
  `created_at`；任何更新刷新）。

分层记忆（L1 双轨消息 / L2 事件摘要 / L3 图谱+向量）、策略契约
（批量压实摘要 / 实体提取 / 上下文改写）、存储契约
（L1 消息 / L2 条目 / L3 图 / L3 向量）与 embedding 端口均在
**组件公开面**（ADR-0026/0028）；主题检测独立于组件（`TopicDetectorProvider`，
组件的检测器实现经它注册，ADR-0027）；持久化 / 向量库实现挂在组件
存储契约下（ADR-0023 决策 4）。

### 4.7 事件总线与 SynonzEvent（词汇表全量）

```rust
impl EventBus {
    /// 入参类型锁死：非框架事件编译期无法上总线。
    pub fn emit(&self, event: SynonzEvent);   // 同步 try_send：非阻塞立法
}
```

```rust
#[non_exhaustive]
pub enum SynonzEvent {
    Turn(TurnEvent),                 // 轮次执行叙事（原 AgentEvent）
    Conversation(ConversationEvent), // 会话生命周期
    Memory(MemoryEvent),             // 记忆流转与失败
}

pub enum TurnEvent {
    Lifecycle(LifecycleEvent),   // Started / Completed / Failed / Cancelled
    Model(ModelEvent),           // Requested / StreamDelta / Responded
    Tool(ToolEvent),             // CallRequested / CallCompleted
}

pub enum ModelEvent {
    Requested { purpose: CallPurpose, messages: Vec<Message>, round: Option<usize> },
    StreamDelta { delta: ModelDelta, round: Option<usize> },
    Responded { message: Message, usage: TokenUsage, round: Option<usize> },
}
pub enum ToolEvent {
    CallRequested { call: ToolCall, round: Option<usize> },
    CallCompleted { call_id: CallId, result: ToolResult, round: Option<usize> },
}
// round：推理循环序号（1-based）；None=循环外维护调用（与 purpose 互证）

pub enum ConversationEvent {
    Created { conversation_id: String, subject_id: String },
    Ended { conversation_id: String, subject_id: String, reason: ConversationEndReason },
    TopicShifted { conversation_id: String, from: String, to: String },
}
pub enum ConversationEndReason { Explicit, IdleSwept, Shutdown }

pub enum MemoryEvent {
    TurnArchived { conversation_id: String, subject_id: String, topic: String },
    Updated    { subject_id: String, scope: MemoryScope, id: String },       // 管理：编辑（无内容）
    Removed    { subject_id: String, scope: MemoryScope, ids: Vec<String> }, // 管理：遗忘（无内容）
    Failed     { stage: String, detail: String, moment: MemoryFailedMoment },
}
pub enum MemoryFailedMoment { AfterTurn, AtConversationEnd, Background, Creation }
```

全部 `Serialize + Deserialize`（两级 tag）；`non_exhaustive`；事件
需 `Clone`（重载荷用 `Arc` 包裹内部）。

- **失败事实（ADR-0023）**：`FlowFailed` → `Failed`；`stage` 为
  字符串（核心不解释实现方阶段）；`moment` 枚举随改名；读侧
  （assembler / rewriter）与写侧（流水线钩子 / 后台任务）失败统一
  走它，不静默；
- **分层机制进展不在核心（ADR-0022/0023）**：`Compacted` /
  `Distilled` / `Promoted` 移出核心词汇 → 组件自有观察面（分层
  进展事实由组件观察面上报，ADR-0026 §6）；
- **管理事实（ADR-0020；ADR-0025 §6 修订）**：`Updated` / `Removed`
  不含内容，携带 **`scope`**（删除事实事后可定位分区）；批量 ids
  受分页 `limit` 有界；
- **叙述归属（ADR-0019/0022）**：推理循环手动叙述不变（`Requested`
  确定、`emit_turn` 消费端掉线终止）；内置引擎发起的辅助调用由
  crate 内部叙述包装自动叙述（`Requested`/`Responded`、`round: None`、
  `purpose: ContextManagement`，**永不发 `StreamDelta`**）；实现者
  不持 `EventSink`（流程事实由模板发）。

### 4.8 Scheduler 与生命周期 API（ADR-0018）

```rust
// 系统侧：只读快照（无注册入口——系统机制不接受开发者调度）
runtime.scheduler_snapshot();      // 任务名/周期/策略/距下次触发/运行中

// 退出期：显式收尾（应用以 select! 接线信号触发；框架不截获信号）
runtime.shutdown().await;          // 停调度 → 终结所属会话 → 观测 flush

// 用户侧：公开 Scheduler 组件（自建实例、绑定自己的执行环境）
let scheduler = Scheduler::new(executor_handle);
let handle = scheduler.schedule(
    Schedule::every(Duration::from_secs(30)),
    OverlapPolicy::Queue,
    || async { /* 执行体 */ },
);
handle.cancel();
scheduler.tasks();                 // 自有任务只读信息
```

- `shutdown()` 幂等（首次执行、并发调用等待完成）；终结本 runtime
  拥有的会话（`ConversationEndReason::Shutdown`）；不等待在途前台
  turn；崩溃孤儿由下次启动的 Monitor 对账；
- 用户调度器与系统调度器同实现类型；自建池 = 传入自己 runtime 的
  Handle（配套便利为后续项）。

## 5. 执行模型：单一执行面 + 交付/发布

### 5.1 一次交互的完整执行流

```
agent.run(conv.turn_input(input))
  ├─ emit Turn::Started（交付 + 总线发布）
  ├─ 时刻① 装配（run 开始，仅一次；内置引擎）：
  │     rewriter 预处理（RewriteInput{text, history（真相域成功轮）, model} → 模型视图）
  │     → MemoryContextAssembleInput { reader（条目级只读代理）,
  │         topic, input, rewritten_input, model（叙述 LLM）, … }
  │     → assembler 产出 system(Agent) 之后的完整消息帧（含本轮模型可见用户消息；
  │        空帧时核心用原始 input 组帧 + 失败事实——ADR-0025）
  ├─ 推理循环（≤ max_rounds，缺省 16；round 序号 1-based 入载荷）：
  │    Model::Requested(Reasoning, round) → 流式调用
  │    StreamDelta(round) ×N → ToolCall → 并行执行（完成序事件 / 调用序回填）
  │    └ 结果回填 → 下一轮（round+1）
  ├─ 完成后：
  │    conv.push_turn(Turn { input, messages, outcome })           ← 真相归档（内存）
  │        （messages = 完整帧 + 本轮后续消息；input 仍为原始文本）
  │    runtime.conversation_store().save(conv.state())            ← 持久化（显式驱动）
  │    内置引擎写相位（终态事件前 await）：
  │      同步段：TopicDetector（Agent 级，轮末；核心写回 topic +
  │              变化时 TopicShifted 经总线）→ 变更经上下文传给钩子 →
  │              archive_turn（钩子）；TurnArchived 经总线；
  │              Failed{moment: AfterTurn} 可见
  │      后台段：spawn_task（钩子经上下文 spawn；句柄登记会话表）
  ├─ emit 终态：Completed(output)（失败→Failed；中断→Cancelled）
  └─ 每次发射双路：交付路（背压→ExecutionEvent）+ 总线（先感知）
```

### 5.2 语义要点

- **流自足**：`Completed` 携带 `AgentOutput`；终态不变量不变；
- **round 载荷**：消费者免除推导（`None` 与 `ContextManagement` 互证）；
- **环境流向**：执行链服务全部来自 Agent 的 runtime；**行为与数据
  分离**——内置引擎经契约（provider 产出）访问记忆，Runtime 为
  编排点；
- **取消四入口一信号**（不变）。

## 6. 对象生命周期与编程范式

事件视角的执行流见 §5.1；本节是**对象与范式**视角。两者合读即为
完整原理。

### 6.1 生命周期五阶段

**阶段一：Bootstrap（应用启动，一次）**

```rust
let runtime = SynonzRuntime::builder().build();      // 零注册即用
```

| 对象 | 诞生 | 寿命 | 死亡 |
|---|---|---|---|
| SynonzRuntime | `build()` | 应用全程 | 应用退出（推荐 `shutdown()` 显式收尾） |
| 记忆能力（provider 产出：Memory / assembler / pipeline） | build()（缺省 = 核心进程内默认） | 同 runtime | 同 runtime |
| 会话表 | build() | 同 runtime | 同 runtime |
| 事件总线 + 常驻派发器 | build() | 同 runtime | 同 runtime |
| 系统调度器 + 计时线程 | build()（宿主 Handle 捕获/注入） | 同 runtime | shutdown / Runtime 消亡 |
| 服务实例（conversation store / memory provider / observers） | 注册或缺省 | 同 runtime | 同 runtime |

**阶段二：Configure（每个 Agent 角色，一次）**

```rust
let agent = Agent::react(&runtime, model, tools)
    .rewriter_provider(provider)                     // 读侧扩展（可选）
    .build()?;                                       // （observability 开关已退役）
```

| 对象 | 诞生 | 寿命 | 死亡 |
|---|---|---|---|
| RewriterProvider 产出（可选） | 应用构造 | 随 Agent（克隆共享） | 随 Agent |
| Agent | `build()` | 长存（克隆廉价） | dropped |

**阶段三：Session（每个用户会话）**

```rust
let conv = Conversation::new(&runtime, &subject)?;   // 创建（三动作）
let conv = Conversation::of(&runtime, &subject, id)?; // 恢复
```

| 对象 | 诞生 | 寿命 | 死亡 |
|---|---|---|---|
| Conversation | new / of | 长存（克隆 = 同一会话） | dropped——落账状态在 store 里活得比它久 |

**阶段四：Turn（每次执行——对象最密集）**

```rust
let mut execution = agent.run(conv.turn_input("问题"));
```

| 对象 | 诞生 | 寿命 | 死亡 |
|---|---|---|---|
| TurnInput | `conv.turn_input()` | 一条语句 | 被 `run()` 消费（**可变借用**串行化同会话轮次） |
| Execution | `run()` 返回 | 消费者持有 | dropped（**drop = RAII 取消**） |
| AgentLoopTask | `run()` spawn | 单次 run | 终态 / 取消 |
| MemoryContextAssembleInput | 行为时刻构造（内置引擎） | 单次行为 | 行为返回（**载荷即汇合点**——引擎 × 实现） |
| 交付 tap | `run()` | run + 清空交付通道 | 消费者消失后退出 |
| Turn | run 终态 | **永存**（会话内 + store） | 数据删除 |

**阶段五：Teardown（运行期自动 + 退出期显式）**

```rust
// 运行期：Monitor 自动空闲清扫（系统调度器周期任务，Skip、立即首触发）
//   空闲超时会话 → end(IdleSwept)；崩溃孤儿由下次启动的立即首扫对账
conv.end(&runtime).await;          // 显式终结（三动作 + emit Ended，幂等）

// 退出期：应用（select! + 信号）显式收尾
runtime.shutdown().await;          // 停调度 → 收尾所属会话（Shutdown）→ 观测 flush
// 终结内部：Runtime 收尾（init）——有界排空会话任务 + finalize_conversation 钩子
```

| 对象 | 诞生 | 寿命 | 死亡 |
|---|---|---|---|
| 后台维护任务 | 流水线模板 spawn（句柄登记会话表） | 维护任务完成 | drain 时收口（有界）；失败经 `Failed{moment: Background}` 上报 |
| Monitor 任务 | build 注册（配置 idle_timeout） | 同 runtime | shutdown / Runtime 消亡 |
| 计时线程 | build 启动 | 同 runtime | shutdown / Runtime 消亡 |

| 路径 | 触发 | 落账 | 终态事件 | 观察面 |
|---|---|---|---|---|

| 取消-1 | token / cancel() / timeout（三挂起点） | Turn::cancelled | Cancelled | ✅ |
| 取消-2 | 预循环抢跑（取消先于循环） | Turn::cancelled | Cancelled | ✅ |
| 取消-3 | **drop(Execution)**（RAII：消费者消失） | Turn::cancelled | 消费者已不在——仅观察面收到终态 | ✅ 终态不丢 |

### 6.4 编程范式

1. **声明式配置 + 命令式执行**：runtime / agent 是声明式长存配置，
   会话是数据，每个 turn 是一次命令式执行；
2. **借用检查器即轮次串行器**：同会话并发轮次在编译期被拒绝；
3. **组合自由**：多 Agent 续同一会话（各 run 各落账）/ 一个 Agent
   并行多会话——多 Agent 差异经 provider/rewriter 表达，**策略
   一致性归应用/编排层**；
4. **RAII 即取消**；错误路径取向"错误不可表达"优先于"报错拦截"；
5. **反应即订阅**：观察位自由注册；扩展点按策略轴立法（新槽 =
   新 ADR）；
6. **行为与数据分离**：内置引擎不持有存储，Runtime 为编排点，
   契约即汇合点——构造零耦合，时序自然正确。

所有权与并发规则：

| 规则 | 机制 |
|---|---|
| 同会话并发轮次 | 编译期拒绝（可变借用） |
| 一个 Agent × 多会话并行 | Agent 无状态（引擎内置），每次 run 独立 |
| 多 Agent × 同一会话续写 | 会话独立实体；每个 run 记录自己的轮次 |
| 跨 runtime 混用 | 结构上无法腐败 |
| 同一会话重复终结 | 结构上幂等（ended 状态 + 首次判定收口） |
| 取消 | 四入口一信号（§10.1） |

## 7. 会话与真相

| 语义 | 决策 |
|---|---|
| 落账 | **全入史**：`Turn { input, messages, output, outcome }`，outcome ∈ {Completed, Failed, Cancelled} |
| 写入点 | `push_turn` 唯一（pub(crate)，框架所有） |
| 记忆触发面 | **仅成功轮进入归档钩子**（失败轮不污染记忆） |
| 持久化 | 经 ConversationStore 自动保存；失败可见（never-silent） |
| 生命周期 | 三入口全带环境：new/with_id（构造+落库+emit Created）/ of（恢复）/ end（终结三动作，幂等） |
| 状态 | `ConversationState` 含 ended——重复终结结构上收口，Monitor 过滤 |
| 三终结时机 | `ConversationEndReason::{Explicit, IdleSwept, Shutdown}`；终结收尾 = **Runtime 结构行为**（init 模式：有界排空会话任务 + `finalize_conversation` 钩子；排空先于钩子）——与 Agent 无关 |
| 归属登记 | 会话表：new/with_id/of 登记，任何 end 路径移除；`shutdown` 的收尾名单 |
| 自动终结 | Monitor 空闲清扫（系统调度器 Skip 周期任务）：`list_stale` 下推 → end(IdleSwept)；崩溃孤儿由下次启动的立即首扫对账 |
| 退出期收尾 | `runtime.shutdown().await`：停调度 → 终结本 runtime 所属会话（Shutdown）→ 观测 flush；幂等 |
| 查询面 | `list_stale(before, cursor, limit)`（清扫下推）+ `list(ConversationQuery)`（元数据关键字 + 游标分页）→ `ConversationSummary`（不含 turns） |
| 自定义终结 | 走**观察位**（订阅 `ConversationEvent::Ended` 自行处理）——扩展走已有机制 |
| 导出 | export = 真相轮次（可迁移）；记忆是 provider 能力，不随行 |
| 工厂 | new = 创建 / of = 恢复（缺者报错）/ ensure = get-or-create（S3） |

真相与记忆的归档对称：**Conversation 归档真相（Turn，含失败），
内置引擎归档记忆（仅成功轮进入归档钩子）**——两种归档，
互不越界。

> `sweep_stale` 公开入口已退役（ADR-0018 开放项决议）：Monitor 为
> 唯一清扫路径；内部 sweep 逻辑为任务体，不开公开面。

## 8. Agent 状态模型与状态引擎

### 8.1 上下文 = Agent 的状态（统合概念）

> **上下文（Context）= Agent 的状态 = 叙事背景——它是让 Agent
> 变成有状态的关键部分。**

```
Agent（有状态的运行体）
  = 决策循环（Loop） + 上下文（状态） + 运行时（环境服务）

上下文（Agent 状态 · 统合概念）
  ├── 记忆（官方分层组件形态：L1+L2+L3）—— 沉淀的状态【持久部分】
  ├── 环境感知结果（Loop 内的模型响应、Tool 调用结果）—— 即时部分
  └── 运行时要素 —— 环境衍生的感知（未来原料位：工具目录/系统状态…）

状态的物化循环：
  上下文（状态流）──每轮物化──→ 工作载荷（run 内 messages·瞬时快照）
       ▲                              │ 循环增长（模型响应+工具结果=新感知）
       └── 沉淀维护（归档→L1→L2 事件摘要→L3 图谱）←──┘
```

- 记忆 ⊂ 上下文（包含关系，非并列）——记忆是上下文的持久沉淀；
- **装配 = 完整上下文的物化**：记忆为主原料 + 回合材料
  （`MemoryContextAssembleInput` non_exhaustive 开放）；
- 编辑器对齐：编辑器的上下文 = 对话 + 文件感知 + 记忆的统合——
  同一个"Agent 状态"概念；其 compaction（上下文压缩）= 我们的
  L1→L2 流转（维护行为，非"记忆压缩"的窄义）；
- 分层新鲜度 = 上下文新鲜度的分级沉淀（§8.4）。

### 8.2 内置引擎（crate 内部）

| 维度 | 决策 |
|---|---|
| 引擎形态 | **crate 内部内置引擎**（ADR-0022 §3）：`Context` 收为内部类型、不再公开；入口不对外 |
| 读相位 | rewriter（`RewriterProvider` 产出，可选；history 取真相域成功轮，ADR-0025 §7）→ `MemoryContextAssembler::assemble`（provider 产出；材料带**叙述 LLM**）→ **完整消息帧**（含本轮用户消息；空帧兜底，ADR-0025 §1–§3） |
| 写相位 | **流水线模板**（`MemoryPipeline` 默认方法，核心持有）：发核心事实、派生后台任务；业务钩子三个：`archive_turn` / `spawn_task` / `finalize_conversation` |
| 主题检测 | **Agent 级独立扩展点**（`TopicDetectorProvider`，ADR-0027）：核心轮末调用 → 写回 `Conversation.topic` → 变化时发 `TopicShifted` → 变更经上下文传给后续钩子 |
| 上下文语义入口 | `PipelineTurnContext` / `PipelineConversationContext`：数据读取（含本轮 topic 变更）+ `set_topic` + `spawn` + `report_failure` + **叙述 LLM**（ADR-0025 §4）；`EventSink` / `ConversationTaskSpawner` 不出现在实现者可见面 |
| 纯行为 | 引擎无实例状态（后台任务句柄登记 Runtime 会话表）；provider、rewriter 与检测器即全部构造内容 |
| 默认实现 | 核心随附**进程内默认 provider**（非分层，零配置即用，ADR-0023）：每会话有界消息窗口（完成轮写入、读相位重放）——**管理面恒空**（无条目、`edit`/`forget` 无操作）、无持久化、忽略 scope；分层实现归官方组件（ADR-0026） |
| 模型角色 | `Provider 模型 ?? Agent 模型` 在**使用时**解析并统一包叙述；记忆跟随上下文（无独立记忆模型） |
| 失败表示 | `MemoryFailure { stage: String, detail: String }`；读/写两侧失败统一为 `Failed` 事实；模板尽力而为（失败上报后继续后续步骤） |
| 终结 | 不独立于编排：Runtime 先有界排空会话任务，再调用 `finalize_conversation` 钩子 |

**维护编排的时序语义**（官方分层组件实现）：

| 段 | 内容 | 感知档位 |
|---|---|---|
| 同步段（终态事件前 await） | 主题检测（Agent 级检测器；核心写回/事实/变更传递）+ 回合归档（钩子：L1 双轨消息） | 即时感知档：下一轮装配必见 |
| 后台段（spawn + 登记会话表） | 组件维护任务（L2 事件判断更新；主题切换时结构化摘要 + 实体提取/归一化/图谱写入） | 近期感知档：滞后生效，drain 时收口 |
| 终结（Runtime 结构行为） | 有界排空 + `finalize_conversation` 钩子（会话结束批量同步） | 终结语义：返回即收口完成 |

**维护写入的并发纪律（ADR-0020）**：写入前按 id 重读来源，只
处理仍存在的来源；写前再校验一次，来源集合有变则**丢弃本次产物**
并发无内容事实——策略零改动（见 §8.3）。

```
官方组件 synonz-layered-memory（ADR-0026，按《上下文记忆系统
全链路技术方案》）
  L1 工作记忆：双轨原始消息（user/agent 分存、10 轮、会话级）
  L2 事件摘要：事件单元（LLM 判断更新/创建、≤5 事件、仅 user_track）
  L3 长期记忆：实体关系图谱 + 向量（锚点先行多跳、Schema 约束、
             alias 合并、跨会话、scope 隔离）
  四阶段管线：指代消解 → 召回评分去重冷启动 → 上下文改写成帧 →
             保存与异步写（批量压实 → 蒸馏）
  存储契约：L1 消息 / L2 条目 / L3 图 / L3 向量（进程内默认 + 真实
           后端适配）；embedding 端口；语义策略 + 参数配置
  组件观察面（进展事实）；富面文档类型（L2MemoryEntry /
  L3MemoryGraphEntity / L3MemoryGraphEdge）

管理面（ADR-0023/0025/0026/0028）
  核心最小视图：id/content/source/scope/时间戳；扁平列表 + keyset
               分页；scope 过滤（None = 全部合并）
  组件富面：经 LayeredMemoryActuator（l2_memory_entries /
           l3_memory_entities / l3_memory_relations /
           forget_l3_memory_relation；按 subject 收窄）
```

- **行为与数据分离**：内置引擎不持有存储（经契约访问）；数据
  权威在实现（provider）；无人能自行构造内部对象；
- **边界立法**：存储端口不得策展（策展时机由生命周期事实驱动）；
- **写权限收口**：实现者只经上下文语义入口写（`set_topic` /
  `spawn` / `report_failure`）——编译期拒绝越界；
- **管理写入与系统写入同权**（ADR-0020 保持）：原地更新、id 不变、
  无优先级；内容质量归策略质量；
- **并发纪律（ADR-0020）**：维护写入前按 id 重校验来源
  （重读 → 只处理幸存者 → 写前再校验 → 一致则写并按 id 认领，
  不一致则丢弃产物 + 事实）——"遗忘不回写"由机制保证；
- **注入边界（ADR-0020）**：不提供应用日常新增（`add`）；批量
  导入/迁移由应用自持存储句柄在框架外完成（文档化边界）；
- 扩展轴正交：模型轴换 provider（业务/语义）；存储轴与 embedding
  在组件内换实现（持久化/向量库）；rewriter 换 Agent 级预处理。

### 8.4 分层新鲜度（组件模型的 rationale）

> 以下为官方分层组件的模型（ADR-0026）；核心默认 provider 为进程内
> 非分层，不适用此梯度。

分层新鲜度 = 记忆产生后 Agent 感知到它的速度：

```
L1（会话即时）：本轮归档 → 下一轮装配即可读
L2（会话内事件）：事件判断更新后即可读（会话期间滚动）
L3（跨会话长期）：摘要与图谱写入后可读（异步、更慢）
```

各层 rustdoc 写明性能特征引导（插件自带非功能特征责任，同
Model/Tool 插件原则）；L2/L3 缺失时 L1 兜底最近记忆（记忆流软
失败立法的深层理由）。

## 9. 事件总线（ADR-0017 核心）

### 9.1 概念模型与术语立法

| 概念 | 定义 |
|---|---|
| **EventBus** | Runtime 持有的派发设施——感知事件（被 emit 通知）→ 派发给订阅位；与发射端是使用关系而非组成关系 |
| **EventSource** | 通知总线的主体（执行循环、`Conversation::new`/`end`、Monitor 清扫、`shutdown`、内置引擎维护段）——**定义性动作只有一个：emit** |
| **EventListener（订阅位）** | 观察车道订阅者（N 个 Observer）与行动车道契约位（立法，S3 预留） |
| **Event（SynonzEvent）** | 总线承载的事实类型，入参类型锁死（封闭枚举） |

**术语立法（唯一性）**：

- **事件驱动模型 = 总线体系，有且仅有**。凡事件驱动皆经总线；
- **交付不是事件驱动**：产品消费者接收交付（ExecutionEvent 流，
  点对点、背压、per-run）是执行面固有的输出管道；
- 执行循环有两个无关身份：执行面交付叙事（非事件驱动）/ EventSource
  通知总线（事件驱动）；
- `ExecutionEvent` 是 Turn 族事实的**交付投影**（类型复用不是
  体系混淆）。

### 9.2 双车道与订阅位

```
EventSource ──emit──→ EventBus（Runtime 持有·常驻派发器）
                        ├── 观察车道：旁路·异步·丢弃+lag·N 个 Observer
                        │   （熔断隔离·保序·终态后 drain）
                        └── 行动车道：同步 await·契约位立法（S3 预留；
                            0.3.0 无派发点——终结收尾为 Runtime 结构行为）
```

- **观察车道语义**：绝不拖慢执行；通道内保序（跨事件族不承诺）；
  熔断隔离；终态后 drain；
- **后台失败可见性**：流水线后台任务失败投
  `MemoryEvent::Failed { moment: Background }`——观察位可见、
  交付流不可见（终态不变量保持）——分层可见性；
- **观测 flush（内部）**：`shutdown()` 返回前经队列屏障等待已发
  事实全部投递（终局事实不丢）；屏障是内部机制，不属公开面。

### 9.3 发射源 × 订阅位矩阵

| EventSource | emit | 观察位 | 行动位 | 交付 |
|---|---|---|---|---|
| 执行循环 | Turn 三子族 | ✅ | — | ✅ ExecutionEvent 投影 |
| 执行循环（同步段失败） | MemoryEvent::Failed{AfterTurn} | ✅ | — | — |
| `Conversation::new`/`with_id` | ConversationEvent::Created | ✅ | — | — |
| `Conversation::end` / Monitor 清扫 / `shutdown` | ConversationEvent::Ended | ✅ | —（收尾=Runtime 结构行为） | — |
| 核心（主题检测器判定漂移，ADR-0027） | ConversationEvent::TopicShifted | ✅ | — | — |
| 内置引擎维护段（钩子 / 任务失败） | MemoryEvent::TurnArchived / Failed | ✅ | — | — |
| `Memory` 管理操作（list/get/edit/forget） | MemoryEvent::Updated / Removed（无内容、无类型） | ✅ | — | — |

治理原则：Turn 事件只被目击与交付；记忆反应锚在流水线契约的时刻上
（同步段 / 后台段）；终结收尾是系统行为（与 Agent 无关）。分层机制
进展（事件更新 / 摘要 / 图谱写入等）不在总线——归组件自有观察面
（ADR-0022/0026）。

### 9.4 扩展点生效时序（全景契约）

| 扩展点 | 调用时机 | 生效边界 | 失败语义 |
|---|---|---|---|
| `Model` | 推理循环每轮 | 直接决定本轮输出 | 终态 Failed |
| `Tool` | 模型请求时（并行） | 结果回喂，影响本轮后续 | 软失败回喂 |
| `TurnInputRewriter`（读侧） | 每 run 装配前（内置引擎） | 决定组装输入（召回模型视图） | 可见降级（保留原文，`Failed`） |
| `MemoryContextAssembler`（读） | 每 run 装配（内置引擎） | 决定模型输入（完整消息帧） | 降级可见（Output.failures） |
| `ConversationStore` | record! / 创建 / 终结时刻 | 真相持久化 | 软失败可见 |
| `Memory` 实现（provider 产出） | 被引擎读/写；管理经 `runtime.memory()` | 跟随调用者时序 | `MemoryEvent::Failed` |
| `TopicDetector`（写侧预处理，Agent 级，ADR-0027） | 轮末（写相位前） | 决定会话 topic；核心写回 + 事实 + 变更传递 | 保留旧 topic + `Failed` |
| `MemoryPipeline` 三钩子（写） | 轮末同步段 / 后台段 / 会话终结 | 归档、维护任务、收尾 | 尽力而为 + `report_failure`（`Failed`） |
| `Memory` 应用面（list/get/edit/forget） | 应用调用时（同步） | 立即对所有读路径生效；在途维护按 id 重校验不回写 | 单条失败不中断批（返回失败清单） |
| 组件存储端口（L1 消息 / L2 事件 / L3 图 / L3 向量） | 组件实现读/写 | 组件内部时序 | 组件观察面 / `Failed` |
| 组件语义策略（事件判断 / 摘要 / 实体提取 / 上下文改写） | 组件维护段 / 读相位 | 组件内容变换 | 组件内降级纪律（不丢数据） |
| 组件 embedding 端口 | 组件召回 / 判断 / 归一化 | 组件内部时序 | 组件观察面 |
| `Observer` | 事件 emit 时 | **永不影响执行** | 熔断+lag |
| 内置引擎读相位 | run 开始一次 | 决定本轮模型输入（完整消息帧） | 降级可见（空帧兜底） |
| 内置引擎写相位（模板） | 终态事件前 await | 同步段=下一轮必见；后台段=滞后 | 同步段 `Failed`；后台段经总线 |
| 辅助模型调用（叙述包装） | 引擎维护段 | 调用自动叙述（无 StreamDelta） | 各自实现的失败语义 |

## 10. 横切语义

### 10.1 取消与超时（不变）

四入口一信号（ADR-0004）。agent 级 `default_timeout`（显式
opt-in）+ per-run `with_timeout` 覆盖。

### 10.2 错误分诊

| 层级 | 形态 | 行为 |
|---|---|---|
| 工具级（软失败） | `ToolError` / `ToolResult::Err` | 喂回模型，run 继续 |
| run 级（硬失败） | `AgentError` | Failed 事件；await Err；入史（outcome=Failed） |
| 取消 | `AgentError::Cancelled` | Cancelled 事件；非失败；入史（outcome=Cancelled） |
| 记忆失败 | `MemoryEvent::Failed`（stage 字符串 + moment 载荷） | **不中断 run、不再静默**；经总线可见 |
| 装配失败 | 降级可见（Output.failures；空帧兜底） | 帧降级但 run 继续 |

### 10.3 序列化

`SynonzEvent`（全族）/ `Turn` / `ConversationState` 全 serde——
录制回放、真相迁移、确定性测试三大用途共享同一形状。版本演化
遵守 serde 兼容性惯例。

## 11. 扩展点与插件化（全景）

| 契约位 | 层级 | 职责 | 注册 | 缺省 |
|---|---|---|---|---|
| ConversationStore | Runtime | 会话真相存取 + 查询面（`list_stale` / `list`） | RuntimeBuilder | 进程内 |
| **MemoryProvider** | Runtime | 记忆能力工厂：`memory` / `context_assembler` / `pipeline`（+ 上下文管理模型配置） | RuntimeBuilder | 核心进程内默认（非分层） |
| **RewriterProvider** | Agent | 读侧输入预处理工厂：`turn_input_rewriter`（+ 可选 `model`） | AgentBuilder | 无改写 |
| **TopicDetectorProvider** | Agent | 写侧主题检测工厂：`topic_detector`（+ 可选 `model`，规则同 rewriter；ADR-0027） | AgentBuilder | 无检测（保持 topic） |
| Observer（N 个） | Runtime | 全量事件旁路目击 | RuntimeBuilder | 无（观察位为空） |
| **Memory**（条目管理抽象） | 实现 | `list`/`get`/`edit`/`forget`（subject 按调用传） | provider 产出 | 进程内默认实现 |
| MemoryContextAssembler | 实现 | 完整消息帧组装（条目级只读代理 + 回合材料 + 叙述 LLM；ADR-0025） | provider 产出 | 进程内默认实现 |
| MemoryPipeline | 实现 | 写相位模板 + 三钩子（`archive_turn` / `spawn_task` / `finalize_conversation`；上下文带叙述 LLM 与 topic 变更） | provider 产出 | 进程内默认实现 |
| MemoryReader | 载荷门面 | 条目级只读投影（由 `dyn Memory::reader()` 派生、构造内部化，ADR-0023） | （非注册位） | — |
| 组件语义策略（事件判断 / 摘要 / 实体提取 / 上下文改写） | 组件 | 语义环节内容变换（提示词随策略；参数集中配置） | 组件配置（实现设计） | 组件内置 |
| 组件存储端口（L1 消息 / L2 事件 / L3 图 / L3 向量） | 组件 | 分层存储（Redis / MongoDB / Neo4j / Milvus 实现挂此） | 组件配置（实现设计） | 组件进程内实现 |
| 组件 embedding 端口 | 组件 | 向量化（召回 / 判断 / 归一化） | 组件配置（实现设计） | 组件进程内实现 |
| 组件观察面（Observer） | 组件 | 分层进展事实（事件更新 / 摘要 / 图谱 / 归一化 / 跳过） | 组件 provider 构建器 | 无（观察位为空） |

统一模式：业务实体不耦合插件；**编排在框架，存取/决策在实现侧**；
系统资源 Runtime 级、读侧预处理 Agent 级（微 OS 分层）。工具另有
`#[derive(Tool)]` 类型化壳。

**读写不对称（ADR-0022/0027）**：读侧经 `MemoryContextAssembler`（只读、
不可腐化状态）；写侧模板由核心持有，实现者只提供三个业务钩子
（写权限经上下文语义入口）；主题检测独立为 Agent 级扩展点（核心
写回/事实/变更传递）。

**管理面（ADR-0023/0025/0026）**：核心 `Memory` 抽象提供条目管理
（最小视图 + `scope` 寻址）；组件富面按文档类型暴露（L2 事件 →
`Summary`、L3 实体 → `Knowledge`）；不提供应用日常新增（批量导入/
迁移为框架外边界）；管理写入与系统写入同权（原地更新、id 不变）。

系统调度器不是注册位：内核态、不可注册（开发者只读快照）；开发者
自定义定时经公开 `Scheduler` 组件自建（用户态；共享池或自建池）。

| Executor（执行环境） | 宿主 worker pool——Scheduler 只提交执行请求，不执行 |

| Monitor | 系统调度器首个注册任务：空闲清扫（Skip、立即首触发、崩溃孤儿对账） |
| shutdown / flush | 显式退出期收尾（停调度 → 终结所属会话 → 返回）/ 内部观测队列排空屏障 |
| ConversationSummary 等查询类型 | 会话查询面类型（Summary / Query / Cursor / Page）——摘要 + 元数据关键字 + keyset 分页 |
| Conversation | 独立实体（1~N Agent 参与）：真相 + 生命周期状态（ended） |
| Turn / TurnInput | 一轮执行记录 / 轮次输入参数对象（唯一入口 `conv.turn_input`） |
| Execution / ExecutionEvent | 执行三合一 / 交付投影六变体 |
| **SynonzEvent** | 总线统一事件（Turn/Conversation/Memory 三实体族，non_exhaustive，serde） |
| TurnEvent | 轮次执行叙事事件族（原 AgentEvent；Lifecycle/Model/Tool 三子族，round 载荷） |
| ConversationEvent | 会话生命周期事件族（Created/Ended/TopicShifted） |
| MemoryEvent | 核心记忆事实族（TurnArchived/Updated/Removed/Failed；管理事实不含内容、携带 scope；分层进展不在核心，ADR-0023/0025） |
| ConversationEndReason / MemoryFailedMoment / round | 终结时机 {Explicit, IdleSwept, Shutdown} / 失败时刻 {AfterTurn, AtConversationEnd, Background, Creation} / 推理循环序号（1-based，Option） |
| EventBus / EventSource | 事件总线（双车道派发设施）/ 通知总线的主体（动作仅 emit） |
| 观察位 / 行动位 | 订阅位两形态：旁路目击（N 个）/ 同步反应（契约位立法，S3 预留） |
| 交付 / 订阅 | 两种投递契约：背压点对点（产品消费者）/ 总线派发（订阅者）——交付不是事件驱动 |
| Observer / ObserverContext | 总线观察位契约（`on_event(&SynonzEvent)`）/ 投递上下文（`execution_id: Option<u64>`） |
| 终结收尾（init） | Runtime 结构行为：有界排空会话任务 + `finalize_conversation` 钩子（与 Agent 无关） |
| 分层新鲜度 | 官方分层组件的模型：会话即时 L1 > 会话内事件 L2 > 跨会话长期 L3（ADR-0026） |

## 14. 边界与未来

- **S3（多 Agent 编排）**：维持后置，无时间表；Conversation 独立
  实体（1~N Agent 参与）为编排奠基；预留面已标注触发条件
  （`CancelReason::Parent` / `CallPurpose::Classification` /
  `SubjectType::Agent`）；**总线行动车道**（同步反应契约位）立法
  保留，0.3.0 无派发点；**Turn 增加 Agent 标识** = S3 开放项（多
  Agent 会话的审计/编排需要）；Agent 间通信（④）另立 ADR——总线
  词汇表为其留缝（顶层加实体族变体，非破坏）；
- **控制流影响**（③：拦截/改写执行，middleware 性质）：另立 ADR，
  暂无场景（IDE 路由等按执行前普通代码处理）；
- **Monitor 机制**：由 ADR-0018 落地并并入正式架构（见 §2.4、§6、
  §7）——原延期记录关闭；资源状态监督拒收（无消费者）；后台维护
  任务健康并入前提工程（排空有界化 + panic 可见化）；
- **调度扩展（ADR-0018 暂缓项）**：pause/resume/status、cron 类
  规则、一次性/延迟任务、自定义执行池配套便利、正文检索、
  Scheduler 专用事件词条——均为非破坏性可加；
- **记忆模型（原“引擎上下文模型”）**：由 ADR-0022/0023/0025 落地——
  上下文管理模型配在 `MemoryProvider`，使用时解析
  （`Provider 模型 ?? Agent 模型`）并统一包叙述；不设独立记忆模型；
- **ADR-0022/0023/0025 边界（实现设计，不阻塞）**：provider 装配
  方式（构建器形态/命名）、组件包装、`MemoryProvider` 的模型访问
  方法（机械性补齐）；核心不引入项目/工作区概念、不定义 scope 的
  来源/推导/注入（应用层决定）、不引入回合序号；
- **ADR-0026 边界（无当前需求，触发再立项）**：scope 转换
  （后续经组件富面加性引入 `move`/`promote`/`demote`）；观察事件
  清单与命名、L2 缓存/持久化拆分（实现细节）；L1 留存与会话级
  清理另行立项；语义搜索、跨单元矛盾消解、事实聚合归组件策略层；
  数据迁移工具（无旧数据）；
- **ADR-0028 边界（无当前需求，触发再立项）**：单查询邻域
  （`neighborhood`，当前用 `edges_of` + `get_entity` 组合）；L1/L3 的
  真实重要度字段（当前 L1/L3 用中性常量，仅 L2 条目携带）；真实
  后端独立包（Redis / MongoDB / Neo4j / Milvus，随 ADR-0023 决策 4
  保持）；
- **ADR-0020 边界（保持；类型/相位部分经 0025/0026 修订）**：应用
  日常新增（`add`）——新增恒来自对话沉淀，批量导入/迁移由应用自持
  存储句柄在框架外完成（无事实/无有序保证，文档化边界）；严格
  全局时间序为可加性后续；错误覆盖的内容质量归策略（内核不设
  优先级）；物理删除/副本/备份/加密擦除归存储实现；
- **ended 状态门**（终结后拒绝续写）：状态依据已就位，场景出现时
  带 ADR 立法；
- **刻意不做**（无触发不引入）：事件过滤/采样配置、动态观察者
  注销、无场景驱动的模式层抽象、下游自定义事件上总线（推迟——
  订阅位制下无反应者可认领）、组装策略覆灭入口；
- **纯回放配置**（核心默认 provider + rewriter 关闭）：用户真实
  需求出现再表达。
