## 1. 系统概览

### 1.1 框架身份

Synonz 是**显式、可控、可观测的 Agent 工程基础设施**（纯 Rust 库）。

四支柱是全部设计的验收标准：

| 支柱 | 含义 | 主要落点 |
|---|---|---|
| 反过度抽象 | 最小公开概念集、无框架魔法 | 词汇表（§3）、no-magic 原则 |
| 行为可控 | 状态显式、prompt 显式、行为可推理 | 无状态 Agent（§3.3）、事件全量可见（§4） |
| 生命周期完备 | 取消一等公民、传播有语义、资源清理 | 取消引擎（§5.2） |
| 内生可观测 | 执行即事件、可回放 | 事件流（§4） |

### 1.2 分层结构

```
┌─────────────────────────────────────────────────┐
│ 模式层    ReAct / plan-execute / research 等      │ S3 场景驱动，v1 不预设抽象；
│           （v1：用户自行组合实现）                  │ 应用层业务 EVENT TYPE 也在这层
├─────────────────────────────────────────────────┤
│ 组合层    Agent：一种罐装组合                       │ ADR-0007
│           （model + tools + prompt + 推理循环）     │ 服务 90% 场景；插件消费者
├─────────────────────────────────────────────────┤
│ 原语层    Model / Tool / 事件流 / Message          │ 全部公开——自定义引擎
│           （契约集合 + 数据词汇）                    │ 的出口；契约定义者 ★
├─────────────────────────────────────────────────┤
│ 适配层    synonz-openai / synonz-anthropic /       │ 外部协议 → 核心契约
│           synonz-mcp（+ synonz-derive 宏支持）      │ 的桥接；插件实现者
└─────────────────────────────────────────────────┘
```

依赖方向永远向下：适配层 → 原语层；模式层 → 组合层 → 原语层。

插件化三角色（契约定义于原语层 / 插件实现于适配层 / 组合层消费）与
契约晋升标准见 ADR-0009。

### 1.3 v1 范围

- 锚定场景：**S1 单 agent 循环**（LLM + tools 的推理-行动-观察循环）
- 形态：纯库（5 crates + examples），无 CLI/服务端
- 后置：S2 会话/记忆、S3 编排、S4 嵌入形态、多模态、重试 utility、
  embeddings（后置追踪见各 ADR Consequences）

```
synonz/                        ← Cargo workspace（虚拟清单）
├── crates/
│   ├── synonz/                ← 核心：全部契约类型 + Agent + 循环 + 取消引擎
```

## 3. 公共 API 全景

S1 用户心智词汇表：**`Model` / `Tool` / `Agent` / `AgentEvent`**。
其余类型按用途分为事件载荷类型与原语契约类型，全部可被用户触达但不必
逐个学习。所有公开 enum/struct 均 `#[non_exhaustive]`（下文不再逐个标注）。

### 3.1 Agent 与运行（组合层）

```rust
// ── 组装（无状态配置体；builder 为 Rust 构造惯例）──
let agent = Agent::builder()
    .model(gpt4o)               // Arc<dyn Model>，必填
    .system_prompt("...")       // 可选；语义 = 每个 run 的首条 System 消息，
                                //   不设则整个 run 无 System 消息（无隐藏默认）
    .tool(weather)              // 单个 / .tools([...]) 批量
    .max_rounds(16)             // 显式预算，默认 16，超限 → Failed
    .build()?;                  // 缺 model 等 → AgentError::InvalidConfiguration

// ── 运行（双层 API：事件流为核，ask 为壳）──
let mut run = agent.run(input).await?;              // RunStream：drop 即取消
let mut run = agent.run_with(input, token).await?;  // 外部 token 也可取消
let mut run = agent.run(input).with_timeout(dur).await?;  // CancelReason::Timeout 来源

while let Some(event) = run.next().await { /* 消费 AgentEvent */ }
// run.rounds() —— 轮次推导辅助 API（推导，非存储）

let output = agent.ask(input).await?;               // 便捷层：消费流至终止事件
// Completed → Ok(AgentOutput)；Failed/Cancelled → Err(AgentError)
```

```rust
// ── 输入 / 输出 / run 级错误 ──
struct AgentInput;        // v1：用户消息（&str 语法糖）
struct AgentOutput {
    message: Message,     // 最终 Assistant 消息（完整 blocks）
    usage: TokenUsage,    // 整个 run 累计
}
impl AgentOutput { fn text(&self) -> Option<&str>; }

enum AgentError {
    Model(ModelError),
    MaxRoundsExceeded,
    Cancelled(CancelReason),
    InvalidConfiguration,
}
```

Agent **无状态**：同一 Agent 可并发多个 run，互不可见、互不污染。

### 3.2 事件体系（可观测契约）

```rust
enum AgentEvent {
    Lifecycle(LifecycleEvent),
    Model(ModelEvent),
    Tool(ToolEvent),
}

enum LifecycleEvent {
    Started   { input: AgentInput },
    Completed { response: AgentOutput },
    Failed    { error: AgentError },
    Cancelled { reason: CancelReason },
}

enum CancelReason { UserRequested, Timeout, Parent }   // Parent：S3 预留，v1 不产生

enum ModelEvent {
    Requested   { purpose: CallPurpose, messages: Vec<Message> },
    StreamDelta { delta: ModelDelta },                  // v1 仅文本增量
    Responded   { message: Message, usage: TokenUsage },
}

enum CallPurpose { Reasoning, ContextManagement, Classification }
// v1 框架唯一产生 Reasoning（no-magic：框架不内置摘要/意图识别）

enum ToolEvent {
    CallRequested { call: ToolCall },
    CallCompleted { call_id: CallId, result: ToolResult },
}

struct TokenUsage { input_tokens: u64, output_tokens: u64 }
```

**不变量**（消费者可依赖的结构保证）：

1. 每个 run 的最后一个事件是 `Lifecycle` 终止变体（三选一，恰好一次），
   随后流关闭；
2. 事件流是**单一有序叙事流**：仅凭事件流可完整重建 run 的行为（回放、
   审计、调试、确定性测试）；
3. 轮次 = 两次 `Requested { purpose: Reasoning }` 之间的事件区间，
   由 `rounds()` 推导。

**载荷自足原则**：每个事件携带理解该步骤所需的一切（全量 messages、
token 用量、调用参数与结果），无需查询外部状态。

**序列化**：全部事件可序列化（serde tag 表示，如
`{"type":"model.requested", ...}`），服务录制/回放与嵌入服务时的传输。

### 3.3 规范消息形态（canonical Message）

```rust
struct Message { role: Role, blocks: Vec<ContentBlock> }

enum Role { System, User, Assistant, Tool }

enum ContentBlock {
    Text       { text: String },
    ToolCall   { call_id: CallId, name: String, arguments: Value }, // 仅 Assistant
    ToolResult { call_id: CallId, result: ToolResult },             // 仅 Tool
}

struct CallId(..);        // provider 生成的不透明 ID，用于调用/结果配对
```

**合法性不变量**（agent 循环维护；provider 翻译层双向保持）：

1. `ToolCall` 块只出现在 `Assistant` 消息；
2. `ToolResult` 块只出现在 `Tool` 消息；
3. 每个 `ToolResult.call_id` 引用先前出现的 `ToolCall.call_id`。

规范形态隔离全部 provider 差异（Anthropic 顶层 system、tool_result 并入
user 消息、OpenAI arguments 为 JSON 字符串等——见 ADR-0006 对照表），
核心层与循环只认识规范形态。

### 3.4 Tool 契约（原语层）

```rust
// 核心 trait：动态、dyn 兼容（MCP 桥接与进程内工具同一契约）
trait Tool: Send + Sync {
    fn name(&self) -> &str;
    fn description(&self) -> &str;
    fn parameters_schema(&self) -> &Schema;
    fn execute<'a>(&'a self, args: Value, ctx: ToolContext)
        -> BoxFuture<'a, Result<ToolResult, ToolError>>;
}

#[non_exhaustive]
struct ToolContext {
    cancel: CancelSignal,     // v1：工具内可感知取消；后续场景加字段非破坏
}

enum ToolResult {
    Ok  { content: ToolContent },
    Err { message: String },  // 软失败：喂回模型，不终止 run
}

enum ToolContent { Text { text: String }, Json { value: Value } }
```

```rust
// 类型化壳（synonz-derive，经 synonz re-export）
#[derive(Tool)]
struct Weather {
    /// 城市名                // description ← doc comment
    city: String,             // schema ← 字段类型；Value → Weather 自动反序列化
}
impl Weather {
    async fn run(&self) -> Result<ToolResult, ToolError> { /* 全类型安全 */ }
}
```

**软失败语义**：`ToolError`/`ToolResult::Err` 不终止 run——错误内容作为
`ToolResult::Err` 喂回模型，模型自行重试/调整/放弃；只有框架级错误
（模型不可达、循环超限）才产生 `Failed`。

**并行执行**：模型单次回复发起多个 `ToolCall` 时并行执行（spawn + join，
取消时全部 abort），事件按完成序以 `CallId` 配对。

### 3.5 Model 契约（原语层）

```rust
trait Model: Send + Sync {
    fn stream(&self, request: ModelRequest)
        -> BoxFuture<'_, Result<ModelStream, ModelError>>;
}

struct ModelRequest {
    messages: Vec<Message>,
    tools: Vec<ToolSpec>,       // ToolSpec { name, description, parameters_schema }
    params: ModelParams,        // temperature / max_tokens（最小集）
}

type ModelStream = BoxStream<'static, ModelStreamItem>;

enum ModelStreamItem {
    Delta  { text: String },                          // 非流式 provider 不产生
    Finish { message: Message, usage: TokenUsage },   // 恰好一次，终结项
}

// 便利函数（非 trait 方法）：非流式 = fold 至 Finish
async fn complete(model: &dyn Model, req: ModelRequest)
    -> Result<(Message, TokenUsage), ModelError>;

enum ModelError { Transport, Api, RateLimited, InvalidRequest }
```

- **非流式是 stream 的退化实现**（内部一次 HTTP 调用，只 yield 一个
  `Finish`）——单方法覆盖两种用法；
- 持有方式 `Arc<dyn Model>`：跨 run、跨并发 run 共享；
- **无隐藏重试**：默认不做任何自动重试（重试是用户策略）；
- **取消契约**：future 被 drop = 放弃请求，provider 实现保证 drop 安全。

## 4. 一次 run 的执行流

### 4.1 正常路径（含一次工具调用）

```
agent.run("北京天气怎么样？")

Started { input }
│ 第 1 轮
├─ Requested { purpose: Reasoning, messages: [System?, User] }
├─ StreamDelta { "让我查一下" } …                （流式 provider）
├─ Responded { message: Assistant[Text, ToolCall{x1, weather}], usage }
├─ CallRequested { call: ToolCall{x1, weather, {city:"北京"}} }
├─ CallCompleted { call_id: x1, result: Ok(Text("晴，28°C")) }
│   messages += Assistant 消息 + Tool 结果消息（canonical 不变量保持）
│ 第 2 轮
├─ Requested { purpose: Reasoning, messages: […含工具结果] }
├─ Responded { message: Assistant[Text("北京今天晴，28 度")], usage }
│   无 ToolCall → 跳出循环
Completed { response: AgentOutput { message, usage(累计) } }
流关闭
```

### 4.2 取消传播路径

```
取消入口（三选一，汇同一内部信号）：
  drop 流 ──────────┐
  token 触发 ────────┼──→ 内部取消信号
  with_timeout 到期 ─┘
                          │ agent 循环每个 await 点 select
                          ├─ model future 被 drop → 连接关闭
                          │   （服务端可能已推理/计费——不可控，Requested 已记录）
                          └─ 工具 task 被 abort → 工具代码下一个 await 点停止
                              （同步段跑完；spawn_blocking 跑完丢弃结果）
Cancelled { reason: CancelReason } → 资源清理 → 流关闭
```

取消是**协作式中断**（Rust 无安全强杀原语）：取消延迟由"到下一个 await
点的距离"决定，取消安全分级契约见 ADR-0004。

### 4.3 失败路径

- 模型调用失败 → `Failed { error: AgentError::Model(_) }`
- 循环超预算 → `Failed { error: AgentError::MaxRoundsExceeded }`（非静默截断）
- 工具软失败**不走此路径**（喂回模型，见 §3.4）

## 5. 横切语义

### 5.1 错误分层

| 层级 | 类型 | 效果 |
|---|---|---|
| 工具级（软失败） | `ToolError` / `ToolResult::Err` | 喂回模型，run 继续 |
| run 级（硬失败） | `AgentError` | `Failed` 终止事件；`ask()` 返回 Err |
| 取消 | `AgentError::Cancelled(CancelReason)` | `Cancelled` 终止事件；非失败 |

### 5.2 可观测性

- **执行即事件**：事件流是唯一信息通道（`ask()` 也构建于其上——完备性
  结构证明）；
- **成本可见**：每次 `Responded` 带 `TokenUsage`，`AgentOutput` 带累计；
- **录制/回放**：事件可序列化 → 完整重建 run；mock Model 按录制回放
  即确定性测试（P7 免费副产品）。

## 6. 扩展点与插件化模型

### 6.1 插件化扩展模型（ADR-0009）

**插件化 = 原语层的契约集合 + 适配层的实现形态 + 组合层的自由消费。**

- **边界**：能力维度可插拔（模型、工具、记忆(S2)、上下文处理(S2)、
  将来的存储/观测后端……）；执行语义不可插拔（Agent 循环、事件类型
  封闭性、生命周期语义）——**适配一个契约，永远不会碰到执行语义变更**；
- **契约晋升五标准**：场景驱动 / 实现多样性 / 消费点明确 / 无泄漏 /
  演进算术；降级信号——只有一个实现且看不到第二个的"契约"重新评估；
- **绑定形态与契约正交**：编译期 crate（v1）/ 进程外协议（MCP 即
  Tool 契约的进程外绑定）/ 运行时动态加载（未来，作为又一个适配器）；
- **契约随场景晋升**：不提前设计；Memory/Context 契约随 S2，机制
  挂起项（循环 Hook 点、契约粒度、跨插件状态流、版本策略）见
  ADR-0009 挂起表。

### 6.2 扩展点

| 扩展点 | 方式 | 层 |
|---|---|---|
| 自定义工具 | `#[derive(Tool)]`（推荐）或直接 impl 动态 trait | 原语 |
| 自定义模型提供方 | impl `Model` trait（如内部网关、mock、未适配厂商） | 原语 |
| 多模型路由 / 混合模型 | 实现 `Model` trait 的路由器（fallback、多 provider 分发——契约不变，实现多样）；per-purpose 模型映射与 purpose 进 `ModelRequest` 随 S2 决策 | 原语 |
| 模式预设 / 第三方模式 | `Agent::react` / `Agent::research` / `Agent::reflection` 预设（prompt+参数配方，返回 AgentBuilder，全部可覆盖）；**第三方模式 = 任意函数返回 `AgentBuilder`**，可发布为 crate——零注册机制（ADR-0010） | 组合 |
| MCP 工具接入 | `synonz-mcp` 桥接，MCP 工具即 `Tool` | 适配 |
| 自定义执行引擎 | **绕过 Agent，直接组合 Model/Tool/事件原语**（框架不设墙；自行维护 canonical 不变量） | 原语 |
| 结构化最终输出 | 应用层模式：定义 `submit_result(type, data)` 类工具（schema 强保证）或 prompt 约定（概率性） | 模式/应用 |
| 业务 EVENT TYPE / envelope | 应用层：消费事件流自行包装（`{"type":"CARD",...}`）；框架中立 | 应用 |

## 7. 术语表（唯一定义）

| 术语 | 定义 |
|---|---|
| Agent | 无状态配置体：model + tools + system_prompt + 限额的不可变组合；一种罐装执行语义 |
| Run | Agent 的一次执行：从 input 到终止事件（Completed/Failed/Cancelled）的完整过程，状态仅存在于 run 内部 |
| 轮次（Round） | 两次 `ModelEvent::Requested { purpose: Reasoning }` 之间的事件区间；推导而非存储 |
| Model | 被调用来做 LLM 推理的抽象（trait）；provider 是它的实现 |
| Tool | agent 的可调用能力单元（trait）；进程内代码与 MCP 桥接同契约 |
| 事件流 | run 的单一有序叙事（`AgentEvent` 序列）；可观测性的结构载体 |
| 规范消息（canonical Message） | 核心层定义的消息形态（Role + ContentBlock 块序列）；provider 差异被封死在翻译层 |
| 软失败 | 工具级失败：喂回模型，run 继续 |
| 硬失败 | run 级失败：终止事件，run 结束 |
| CallId | provider 生成的不透明 ID，配对 ToolCall 与 ToolResult |
| 双层 API | 事件流为核（run 系列）+ 便捷壳（ask）的交互模型 |
| 契约（Contract） | 原语层定义的可实现 trait，插件接口的唯一形态；按 ADR-0009 晋升标准治理 |
| 插件（Plugin） | 契约的实现：编译期 crate（v1）/ 进程外协议（MCP）/ 运行时加载（未来）；绑定形态与契约正交 |
