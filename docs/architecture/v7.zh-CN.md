## 1. 系统概览

### 1.1 框架身份（不变）

Synonz 是**显式、可控、可观测的 Agent 工程基础设施**（纯 Rust 库）。
四支柱（反过度抽象 / 行为可控 / 生命周期完备 / 内生可观测）与
High Level 优先原则（ADR-0010：80% 场景高层 API 解决，20% 原语自控）
共同构成一切设计的裁决标准。

### 1.2 分层结构（0.6.0 记忆管理面后）

```
┌─────────────────────────────────────────────────────────────┐
│ 模式层   ReAct / Research / Reflection 预设（应用模板：        │ ADR-0010
│          model+tools+引擎配方打包）                            │
├─────────────────────────────────────────────────────────────┤
│ 组合层   Agent（应用）：执行配置 + Context 引擎（Agent 级·具体） │ ADR-0007/0019
│          + Runtime 引用                                        │
├─────────────────────────────────────────────────────────────┤
│ 执行面   Execution：叙事流（ExecutionEvent 交付）+ 终点 Future  │ ADR-0014
│          + 控制器（cancel / with_timeout / rounds）             │
├─────────────────────────────────────────────────────────────┤
│ 会话层   Conversation（独立实体·1~N Agent 参与）：真相（Turn     │ ADR-0011/0017
│          全入史 + 生命周期状态）/ TurnInput                     │
├─────────────────────────────────────────────────────────────┤
│ 状态层   Context 引擎（Agent 级·具体类型）：读相位（改写→装配）   │ ADR-0017/0019
│          + 写相位（框架独占：归档/压缩/蒸馏）—— 窄策略槽          │
├─────────────────────────────────────────────────────────────┤
│ 记忆层   Memory 应用面（条目 list/get/edit/forget）+ 内部对象      │ ADR-0017/0020
│          （三存储契约位聚合，按 id 操作）—— L1 / L2 / L3          │
├─────────────────────────────────────────────────────────────┤
│ 运行时层 SynonzRuntime（系统）：五主位注册表 + 记忆内部对象组装   │ ADR-0012/0017
│          + 会话表 + 事件总线 + 系统调度器 + 终结收尾（init）     │ ADR-0018
├─────────────────────────────────────────────────────────────┤
│ 原语层   Model / Tool / SynonzEvent / canonical Message         │ ADR-0003/0005/0006/0017
├─────────────────────────────────────────────────────────────┤
│ 适配层   synonz-openai / synonz-anthropic / synonz-mcp         │ ADR-0008
└─────────────────────────────────────────────────────────────┘
  ═══════════════════════════════════════════════════════════
   事件总线（横切设施，非一层）：EventSource ──emit──→ EventBus
   ├ 观察车道（旁路·N 个 Observer·丢弃+lag）      ADR-0017
   └ 行动车道（同步·契约位立法，S3 预留）
   交付路（横切，非总线）：EventTap ──consumer──→ ExecutionEvent
   （背压·per-run——交付不是事件驱动）             ADR-0014/0017
```

**微操作系统图景**（irylex）：框架 = 微型操作系统——
- **Runtime = 系统**（全局单例——逻辑角色：一个应用一个系统环境；
  框架不强制单实例、不提供全局访问器，测试与嵌入场景可多实例并存
  且相互隔离）：系统资源（Memory 存储位、真相库、观测）+ 系统设施
  （会话表、事件总线、系统调度器、终结收尾 init）；
- **系统调度器 = 系统进程**（内核态）：时间生命随 build 启动；
  Monitor 空闲清扫为其首个注册任务；开发者至多只读其快照；
- **用户调度器 = 用户态组件**：公开 `Scheduler::new`——开发者自建、
  绑定自己的执行环境（共享池或自建池），与系统调度互不侵占；
- **Agent = 应用**（实例化）：自带状态引擎（Context）——**当 Agent
  实例化的时候，才有它的上下文引擎**；多应用策略各异；
- **Conversation = 独立实体**：1~N 个 Agent 参与（各自 run 各落
  Turn），S3 多 Agent 编排在此之上扩展；
- 后台维护任务 = 进程产生的 IO 任务，系统调度执行（策略来自产生
  它的 Agent 引擎，句柄登记进系统会话表）。

依赖方向永远向下；行为与数据分离（引擎经载荷接收存储句柄，见 §8）。

## 2. 运行时与主体

### 2.1 SynonzRuntime：系统装配（五主位 + 系统设施）

```rust
let runtime = SynonzRuntime::builder()
    .conversation_store(store)   // 系统资源：会话真相存取（缺省进程内）
    .memory_l1_store(l1)         // 系统资源：L1 工作记忆（缺省内置内存）
    .memory_l2_store(l2)         // 系统资源：L2 摘要层（缺省进程内；可换 Redis…）
    .memory_l3_store(l3)         // 系统资源：L3 知识层（缺省进程内；可换向量库…）
    .observer(exporter)          // 系统观测：总线观察位（可多个）
    .conversation_idle_timeout(duration) // 配置：会话空闲超时（Monitor 清扫阈值）
    .build();
```

> 方法名 = 类型指代名（`MemoryL1Store` → `memory_l1_store`）；
> `conversation_idle_timeout` 为系统空闲清扫的阈值——**配置即
> 点火**：build 时注册 Monitor 任务（系统调度器，Skip 策略、立即
> 首触发，见 §2.4）。

`build()` 内部一次性完成（系统装配）：

1. **记忆内部对象诞生**：三存储位 Arc 聚合，Runtime 唯一持有；
   `runtime.memory()` 暴露应用面（ADR-0020）；
2. **会话表创建**：会话归属登记 + `conversation_id → 后台维护任务
   句柄`（系统调度后台 IO；原维护表升级，见 §7）；
3. **事件总线常驻派发器 spawn**（随 Runtime 生灭）；
4. **系统调度器创建**：捕获宿主 Executor Handle（W1；在宿主 async
   上下文内 build 自动捕获，同步构建场景经 builder 显式注入；配置
   `conversation_idle_timeout` 而两者皆无 = 配置错误，build panic
   并指明修复方式）；配置 `conversation_idle_timeout` 时注册 Monitor
   空闲清扫任务（立即首触发）；计时线程随即启动（见 §2.4、§6）；
5. 终结收尾行为就绪（init 模式：drain 会话表 + 机械促进，见 §7）。

五主位各对应独立扩展轴；**零便捷位**（策略槽与楼层参数经
`Context` 构造链，见 §2.3）；契约位未注册即用进程内默认
实现（零注册即用）；Observer 不注册 = 观察位为空（总线照常工作）；
系统调度器不是注册位（内核态、不可注册；开发者只读快照）。

### 2.2 Subject：主体身份（不变）

`Subject = (SubjectType, id)`。`SubjectType::User` 现用；
`SubjectType::Agent` 为 S3 预留。会话必有主体。

### 2.3 Agent：应用装配（含 Agent 级状态引擎）

```rust
let agent = Agent::builder()
    .runtime(&runtime)          // 系统引用（必选）
    .model(model)               // 必选（缺省引擎模型 = agent 模型）
    .tool(my_tool)
    .context(context)           // ★ 状态引擎（Agent 级注册；缺省 = Context 全默认）
    .build()?;
// （总线无条件发布——observability 开关已退役）
// 预设 = 应用模板：Agent::react(&runtime, model, tools) 打包 react
// 配方的引擎（窗口/摘要/楼层），research / reflection 同构

// Context 引擎：纯行为配置（零 Runtime 依赖，可在 Agent 前创建）
let context = Context::new()             // 全默认（楼层 20/8·首段主题·提示词摘要·分层装配·无改写）
    .with_rewriter(my_rewriter)          // 读侧槽②：输入改写/指代消解（缺省 = 无改写）
    .with_assembler(my_assembler)        // 读侧槽①：装配策略（缺省内置）
    .with_topic_detector(my_detector)    // 写侧子钩子③（缺省内置）
    .with_summarizer(my_summarizer)      // 写侧子钩子②（缺省内置）
    .with_distiller(my_distiller)        // 写侧子钩子①（缺省机械提升）
    .with_model(context_model)           // 引擎模型（缺省 = agent 模型）
    .l1_window(30)                       // 楼层参数（默认 20）
    .l2_cap(12);                         // 楼层参数（默认 8）
```

- **Context 引擎 = 纯行为配置**：只有策略槽、子钩子与楼层参数，零
  Runtime 依赖——可以在 Runtime 之前创建（行为与数据分离，§8）；
- **多 Agent 策略差异**：每个 Agent 自带引擎（react 简洁窗口 /
  research 深度召回……）；多 Agent 参与同一会话时各自引擎交替
  维护同一记忆——**策略一致性是应用/编排层的责任**（框架提供
  机制不强制，no magic）；
- Agent 持有 `Arc<Context>`（**具体类型，无类型擦除**）——克隆廉价。

### 2.4 Scheduler：时间调度（系统调度器与用户调度器）

**组件边界**：Scheduler 是「时间驱动的任务调度组件」——决定「何时
产生执行机会」；执行交给宿主 Executor（决定「在哪运行」）；任务
客户端决定「执行什么」。Timer（时间等待）是 Scheduler 的内部机制；
线程池不属于 Scheduler；任务到达触发时间只意味着应被提交执行，
不意味着已开始运行（触发准时 ≠ 开始准时）。

**双层主权**（微 OS 内核态 / 用户态）：

| 形态 | 创建 | 注册 | 开发者接触面 |
|---|---|---|---|
| 系统调度器（内核态） | Runtime build 内部创建；计时生命随 build 启动 | 仅框架内部（Monitor 等系统任务） | 只读快照（/proc 风格：任务名/周期/策略/距下次触发/运行中） |
| 用户调度器（用户态） | 开发者自建（`Scheduler::new(executor)`） | 开发者自有任务 | 全部公开 API |

**时间模型**：计时线程（单条轻量系统线程：登记 / deadline / 等待 /
触发 / 提交，不执行任何业务；不形成 worker pool）；立即首触发
（注册即触发一次，之后每周期）；固定速率 + 追赶保护（过载后按
周期倍数跳到当前时间之后，不一次补发积压触发）；触发与提交为
非阻塞 handoff——执行慢不阻塞触发、任务 panic 不杀死计时线程。

**并发策略（OverlapPolicy，每任务一个）**：

| 策略 | 上次未完成时 | 积压上限 | 适用 |
|---|---|---|---|
| Skip | 丢弃本次触发 | — | 清扫/巡检（错过一次无妨） |
| Concurrent | 立即再起一层 | 无界（池容量兜底） | 每次都必须执行的独立作业 |
| Queue（合并） | 记一次 pending，完成即续跑 | **1** | 必须完成、不可自并发（自动保存等） |

**宿主模型（W1）**：执行提交经宿主的共享 Executor
（`tokio::runtime::Handle`）——Scheduler 不自持执行池、不与
应用形成双池。详见 ADR-0018 §2-5。

## 4. 公共 API 全景（0.6.0 形态）

### 4.1 执行（唯一入口，不变）

```rust
let mut execution = agent.run(conv.turn_input("北京天气？"));
let output: AgentOutput = execution.await?;      // 流自足
execution.cancel();
execution.with_timeout(Duration::from_secs(30));
execution.rounds();
```

`ExecutionEvent` 六变体不变——Turn 族事实的**交付投影**。

### 4.2 会话（生命周期三入口，全带环境）

```rust
let conv = Conversation::new(&runtime, &subject)?;       // 创建：构造+落库+emit Created
let conv = Conversation::with_id(&runtime, &subject, id)?;
let conv = Conversation::of(&runtime, &subject, id)?;    // 恢复（缺者报错）
conv.turn_input("...")            // 唯一执行入口的参数来源
let outcome = conv.end(&runtime).await;   // 终结：标记+落库+emit Ended（async，幂等）
conv.is_ended()                   // 生命周期状态查询
conv.export()?                    // 真相轮次导出（记忆层不随行）
conv.messages(); conv.turns(); conv.topic();
// push_turn / set_topic：pub(crate)——归框架
// 已删除：truncate_last / clear / fork / import / context()
```

三个生命周期入口同构（构造 / 恢复 / 终结 = 标记 + 持久化 + 发
事件——环境见证，非服务编排）。

### 4.3 Model 契约（不变）

`ModelRequest { messages, tools }`；params 绑定适配器构造。

### 4.4 Observer 契约（签名扩展）

```rust
pub trait Observer: Send + Sync + 'static {
    /// 全量事件目击（Turn/Conversation/Memory 三族）。实现必须快速返回。
    fn on_event(&self, ctx: &ObserverContext, event: &SynonzEvent);
    /// 观察队列溢出丢弃后，总线派发器追上时调用（累计丢弃数）。
    fn on_lagged(&self, ctx: &ObserverContext, dropped: u64) {}
}

#[non_exhaustive]
pub struct ObserverContext {
    /// run 源事件的执行归属（Turn 族=Some；run 外事实=None）。
    pub execution_id: Option<u64>,
}
```

### 4.5 Context 引擎与策略槽（Agent 级·具体类型）

> ADR-0019：退役开放 `trait Context`，改为**具体类型 `Context`** +
> 读写两相位策略；`Agent` 持 `Arc<Context>`（无类型擦除）；引擎入口
> `assemble` / `on_turn_completed` 收为 `pub(crate)`——用户不直接
> 驱动引擎（公开面 = 配置面 + 策略槽）。

```rust
/// Agent 的状态引擎（具体类型）：读相位（改写→装配）+ 写相位
/// （框架独占编排：归档/压缩/蒸馏）。纯行为配置（无实例状态）；
/// Memory 经载荷在行为时刻汇合。
pub struct Context { /* 读侧槽 + 写侧子钩子 + 楼层参数 + 引擎模型 */ }

impl Context {
    pub fn new() -> Self;                                   // 全默认
    // 读相位（整段可扩展）
    pub fn with_assembler(self, a: Arc<dyn ContextAssembler>) -> Self;
    pub fn with_rewriter(self, r: Arc<dyn TurnInputRewriter>) -> Self;
    // 写相位子钩子（框架独占编排，仅换零件）
    pub fn with_topic_detector(self, d: Arc<dyn ConversationTopicDetector>) -> Self;
    pub fn with_summarizer(self, s: Arc<dyn MemorySummarizer>) -> Self;
    pub fn with_distiller(self, d: Arc<dyn MemoryDistiller>) -> Self;
    // 配置
    pub fn with_model(self, model: Arc<dyn Model>) -> Self; // 引擎模型（缺省 = agent 模型）
    pub fn l1_window(self, n: usize) -> Self;               // 楼层参数（默认 20）
    pub fn l2_cap(self, n: usize) -> Self;                  // 楼层参数（默认 8）

    // 框架内部入口（唯一调用者 = agent 循环）
    pub(crate) async fn assemble(&self, input: ContextAssemblerInput<'_>)
        -> ContextAssemblerOutput;
    pub(crate) async fn on_turn_completed(
        &self,
        conversation: &Conversation,
        input: &str,
        messages: Vec<Message>,
        memory: &MemoryCore, // 占位名：crate 内部记忆对象（ADR-0020，命名实施时定）
        agent_model: Arc<dyn Model>,
        events: EventSink,
        task_spawner: ConversationTaskSpawner,
    ) -> Vec<MemoryFlowError>;
}

// —— 读侧槽（契约公开；默认实现内化 pub(crate)）——

/// 输入改写（预处理，发生在装配之前）：本轮输入 → 模型视图。
/// None = 保持原文；Err = 可见降级（保留原文并上报），绝不静默。
/// 只影响组装输入（召回）；模型可见消息仍由 agent 追加原始输入。
pub trait TurnInputRewriter: Send + Sync + 'static {
    fn rewrite<'a>(&'a self, input: &'a str, history: &'a [Message])
        -> BoxFuture<'a, Result<Option<String>, String>>;
}

/// 装配策略：组装输入 → 背景消息（LayeredMemoryContextAssembler 默认）
pub trait ContextAssembler: Send + Sync + 'static {
    fn assemble<'a>(&'a self, input: ContextAssemblerInput<'a>)
        -> BoxFuture<'a, ContextAssemblerOutput>;
}

#[non_exhaustive]
pub struct ContextAssemblerInput<'a> {      // 组装输入（原料域可扩展）
    pub reader: MemoryReader<'a>,           // 只读记忆门面（取代 memory: &Memory）
    pub subject: &'a Subject,
    pub conversation_id: &'a str,
    pub topic: &'a str,
    pub input: &'a str,                     // 本轮原始输入（真相域）
    pub rewritten_input: Option<&'a str>,   // 模型视图（引擎填充：rewriter 输出）
    // 感知/运行时原料位（未来非破坏扩展：环境快照/工具目录/…）
}

#[non_exhaustive]
pub struct ContextAssemblerOutput {         // 组装产物（与 0.4.0 形状一致）
    pub messages: Vec<Message>,             // 背景消息
    pub failures: Vec<AssemblyFailure>,     // 降级可见
}

// —— 写侧子钩子（契约公开；框架独占编排与写入）——

/// 摘要策略：L1 条目 → L2 摘要的内容变换（默认实现内化）
pub trait MemorySummarizer: Send + Sync + 'static {
    fn summarize<'a>(&'a self, entries: &'a [L1Entry], model: &'a dyn Model)
        -> BoxFuture<'a, Result<String, String>>;
}

/// 蒸馏策略：生成 L3 知识内容；可用 reader 读 L1/L2/既有 L3
/// （锚定与归一化）。只返回知识文本；L3Entry 的身份与时间由引擎补齐。
pub trait MemoryDistiller: Send + Sync + 'static {
    fn distill<'a>(
        &'a self,
        blocks: &'a [L2Entry],        // 本批待加工的 L2 溢出块
        conversation_id: &'a str,     // 供 reader 查 L1/L2
        topic: &'a str,
        reader: MemoryReader<'a>,
        model: &'a dyn Model,
    ) -> BoxFuture<'a, Result<Vec<String>, String>>;
}

/// 主题策略：判定轮次主题与漂移（默认实现内化）
pub trait ConversationTopicDetector: Send + Sync + 'static {
    fn detect(&self, input: &str, current: Option<&str>) -> TopicDecision;
}
```

- **读写不对称（ADR-0019 核心边界）**：读侧**整段可换**（只读、
  不触碰真相域，无法腐化状态）；写侧**框架独占编排与写入**（子钩子
  只换零件），写权限不外放——"不可越界"以类型约束而非文档；
- **读相位执行序**（引擎内部）：用 `input.reader` 取近期 L1 历史 →
  `TurnInputRewriter::rewrite` → 用 `rewritten_input` 重建 input →
  `ContextAssembler::assemble`。无 rewriter 时行为与 0.4.0 一致
  （`rewritten_input = None`，纯加性）；
- **模型解析与叙述**：`with_model ?? agent_model` 在引擎内部解析；
  交给子钩子的模型句柄是 crate 内部 `NarratedModel`（自动
  `Requested`/`Responded`、无 `StreamDelta`）；推理循环保持手动
  叙述不变；内容槽不持 `EventSink`（流程事实由引擎发）；
- **写侧契约中立**：方法只锚定状态维护事实（轮终态、L1/L2→内容
  变换），不泄漏 L1/L2/L3 与时序工程；L1→L2 的完整策略（何时压、
  压多少、原子序）是引擎职责（`l1_window`/`l2_cap`）；
- 维护编排：同步段（主题推进+L1 归档，即时感知档）→ 后台段 spawn
  （压缩+蒸馏，近期感知档，句柄登记会话表）；压缩改序：
  摘要→append→pop（无记忆空洞）；**蒸馏先变换后 pop**
  （失败保留 L2 + `FlowFailed{Distill}`，不丢数据）；
- **终结收尾不在引擎**（Runtime 结构行为，§7）。

### 4.6 Memory 应用面、内部分离与管理面（ADR-0020）

```rust
/// 应用面：记忆条目管理（subject 按调用传递）。runtime.memory() 返回它。
/// 分层原语与三存储槽聚合迁入 crate 内部对象（引擎/Runtime/后台任务用）。
pub struct Memory { /* 内部机制对象 */ }
impl Memory {
    pub fn list(&self, subject: &Subject, query: MemoryQuery)
        -> Result<MemoryPage<MemoryItem, MemoryListCursor>, MemoryStoreError>;
    pub fn get(&self, subject: &Subject, id: &str)
        -> Result<Option<MemoryItem>, MemoryStoreError>;
    pub fn edit(&self, subject: &Subject, id: &str, content: impl Into<String>)
        -> Result<MemoryItem, MemoryStoreError>;     // 原地更新，id 不变
    pub fn forget(&self, subject: &Subject, target: ForgetTarget)
        -> Result<ForgetOutcome, MemoryStoreError>;  // 单条（id）或批量（过滤）
}

/// 条目视图（应用面）：L2 情景摘要 + L3 知识，层无关。
pub struct MemoryItem {
    pub id: String,
    pub kind: MemoryType,          // Summary（L2 情景摘要）| Knowledge（L3 知识）
    pub content: String,
    pub source: MemorySource,      // { conversation_id, topic }
    pub created_at: u64,
    pub updated_at: u64,           // 新鲜度键（列表/游标/召回统一）
}

/// keyset 分页（与 ConversationStore 同构）；limit 必须有界（L3 无上限增长）。
pub struct MemoryQuery { /* kind / 会话 / 时间范围 / 关键字 / after / limit */ }
pub struct MemoryCursor { /* updated_at + id：单源位置（存储层原子） */ }
pub struct MemoryListCursor { /* phase: MemoryType（先 Summary 后 Knowledge）+ position: MemoryCursor */ }
pub struct MemoryPage<T, C = MemoryCursor> { pub items: Vec<T>, pub next: Option<C> }
// 存储层：MemoryPage<L2Entry> / MemoryPage<L3Entry>（默认单源游标）
// 应用层：MemoryPage<MemoryItem, MemoryListCursor>（阶段游标）
```

- **公开边界（ADR-0020）**：`Memory` = 应用面（管理动词）；分层原语
  （`l1_append` / `l1_pop_oldest` / `l2_append` / `l2_pop_oldest` /
  `l3_upsert` / `l3_query` / 各层 `len`/`window`/`read`）迁入 crate
  内部对象；应用不再按层读写（机制可自由演进；JVM 分代心智）；
- **`MemoryReader`**：类型公开（策略槽物料面，经 §4.5 的载荷获得），
  **构造入口内部化**——开发者只"使用"不"构造"；外部槽作者单测走
  `test-util`（种子 + reader 构造入口）；
- **管理语义（ADR-0020）**：同一身份槽一条条目；写入**不分来源**
  （用户编辑 / 系统蒸馏）都是**原地更新同一条**（id 不变）；内核
  不设内容优先级——错误覆盖归**策略质量**（算法/提示词/写前对账），
  框架以事实保证可发现；
- **保证边界（ADR-0020）**：操作返回后所有后续读路径不可见；在途
  维护**不回写**（引擎写入前按 id 重校验来源，§8.3）；重观测算
  **新证据**（遗忘不是永久黑名单）；物理删除/副本/备份归存储实现；
- **列表顺序（ADR-0020）**：结构序——L2 块（Summary）在 L3 块（Knowledge）
  之前，块内按 `updated_at` 倒序；页不满才跨源补拉（**跨界一次**，
  阶段游标）；非严格全局时间序（严格序为可加性后续）；
- **注入边界（ADR-0020）**：不提供日常新增（`add`）；新增恒来自
  对话沉淀；批量导入/迁移由应用自持存储句柄在框架外完成（文档化
  边界：框架不感知、无事实、无有序保证）;
- **新鲜度（ADR-0020）**：统一 `updated_at`（创建时 = `created_at`；
  任何更新刷新）；编辑过的条目即刻"浮上来"；
- **只读门面与命名（ADR-0019）不变**：策略槽的写与策展在类型上
  不存在；`L2Entry` / `L3Entry` / `L3Identity` 命名保持；ADR-0020
  追加 `id` 与 `updated_at` 字段。

存储契约（ADR-0020 扩展；**必选方法**，无默认实现）：

```rust
// 每层独立扩展，方法名不重复层名
pub trait MemoryL1Store: Send + Sync + 'static {
    /* append / window / len / pop_oldest —— 不参与条目管理，契约不变 */
}
pub trait MemoryL2Store: Send + Sync + 'static {
    /* 原有：append / read / len / pop_oldest */
    fn get(&self, subject: &Subject, id: &str)
        -> Result<Option<L2Entry>, MemoryStoreError>;
    fn update(&self, subject: &Subject, entry: L2Entry) -> Result<(), MemoryStoreError>;
    fn remove(&self, subject: &Subject, id: &str) -> Result<bool, MemoryStoreError>;
    fn list(&self, subject: &Subject, query: MemoryStoreQuery)
        -> Result<MemoryPage<L2Entry>, MemoryStoreError>;
}
pub trait MemoryL3Store: Send + Sync + 'static {
    /* 原有：upsert / query / len
       upsert 行为契约更新：同身份替换时保留原 id */
    /* ADR-0020 必选新增：get / update / remove / list（同 L2 形状） */
}
```

- **破坏项**：新增方法为必选（不用默认实现制造"声称支持却不支持"
  的半支持状态；pre-1.0 破坏波承载，迁移指南列清单）；
- 辅助类型名（`ForgetTarget`/`ForgetOutcome`/`MemorySource`/
  `MemoryStoreQuery` 等）按编码规范 §5 命名立法在实施时定；
- L1 默认内置内存实现；L2/L3 替换是真实场景（Redis / 向量库 /
  图库）；**存储位不得策展**（既有立法不变）。

### 4.7 事件总线与 SynonzEvent（词汇表全量）

impl EventBus {
    /// 入参类型锁死：非框架事件编译期无法上总线。

```rust
#[non_exhaustive]
pub enum SynonzEvent {
    Turn(TurnEvent),                 // 轮次执行叙事（原 AgentEvent）
    Conversation(ConversationEvent), // 会话生命周期
    Memory(MemoryEvent),             // 记忆流转与失败
}

pub enum TurnEvent {
    Lifecycle(LifecycleEvent),   // Started / Completed / Failed / Cancelled
    Model(ModelEvent),           // Requested / StreamDelta / Responded
    Tool(ToolEvent),             // CallRequested / CallCompleted
}

pub enum ModelEvent {
    Requested { purpose: CallPurpose, messages: Vec<Message>, round: Option<usize> },
    StreamDelta { delta: ModelDelta, round: Option<usize> },
    Responded { message: Message, usage: TokenUsage, round: Option<usize> },
}
pub enum ToolEvent {
    CallRequested { call: ToolCall, round: Option<usize> },
    CallCompleted { call_id: CallId, result: ToolResult, round: Option<usize> },
}
// round：推理循环序号（1-based）；None=循环外维护调用（与 purpose 互证）

pub enum ConversationEvent {
    Created { conversation_id: String, subject_id: String },
    Ended { conversation_id: String, subject_id: String, reason: ConversationEndReason },
    TopicShifted { conversation_id: String, from: String, to: String },
}
pub enum ConversationEndReason { Explicit, IdleSwept, Shutdown }

pub enum MemoryEvent {
    TurnArchived { conversation_id: String, subject_id: String, topic: String },
    Compacted  { conversation_id: String, count: usize },   // L1→L2
    Distilled  { conversation_id: String, count: usize },   // L2→L3
    Promoted   { conversation_id: String, count: usize },   // 终结促进
    Updated    { subject_id: String, kind: MemoryType, id: String },       // 管理：编辑
    Removed    { subject_id: String, kind: MemoryType, ids: Vec<String> }, // 管理：遗忘

                 moment: MemoryFlowFailedMoment },
}
pub enum MemoryFlowFailedMoment { AfterTurn, AtConversationEnd, Background, Creation }
```

全部 `Serialize + Deserialize`（两级 tag）；`non_exhaustive`；事件
需 `Clone`（重载荷用 `Arc` 包裹内部）。

- **叙述归属（ADR-0019）**：推理循环手动叙述不变（`Requested` 确定、
  `emit_turn` 消费端掉线终止）；引擎发起的辅助调用由 crate 内部
  `NarratedModel` 自动叙述（`Requested`/`Responded`、`round: None`、
  `purpose: ContextManagement`，**永不发 `StreamDelta`**）；内容策略槽
  不持 `EventSink`（流程事实由引擎发）。
- **管理事实（ADR-0020）**：`Updated` / `Removed` **不含内容**（id /
  kind / ids；批量 ids 受分页 `limit` 有界）；维护跳过被删来源复用
  `FlowFailed { moment: Background }`（不新增词汇）。

### 4.8 Scheduler 与生命周期 API（ADR-0018）

```rust
// 系统侧：只读快照（无注册入口——系统机制不接受开发者调度）
runtime.scheduler_snapshot();      // 任务名/周期/策略/距下次触发/运行中

// 退出期：显式收尾（应用以 select! 接线信号触发；框架不截获信号）
runtime.shutdown().await;          // 停调度 → 终结所属会话 → 观测 flush

// 用户侧：公开 Scheduler 组件（自建实例、绑定自己的执行环境）
let scheduler = Scheduler::new(executor_handle);
let handle = scheduler.schedule(
    Schedule::every(Duration::from_secs(30)),
    OverlapPolicy::Queue,
    || async { /* 执行体 */ },
);
handle.cancel();
scheduler.tasks();                 // 自有任务只读信息
```

- `shutdown()` 幂等（首次执行、并发调用等待完成）；终结本 runtime
  拥有的会话（`ConversationEndReason::Shutdown`）；不等待在途前台
  turn；崩溃孤儿由下次启动的 Monitor 对账；
- 用户调度器与系统调度器同实现类型；自建池 = 传入自己 runtime 的
  Handle（配套便利为后续项）。

## 5. 执行模型：单一执行面 + 交付/发布

### 5.1 一次交互的完整执行流

```
agent.run(conv.turn_input(input))
  ├─ emit Turn::Started（交付 + 总线发布）
  ├─ 时刻① 装配（run 开始，仅一次；引擎内部）：
  │     TurnInputRewriter 预处理（input → 模型视图，近期 L1 历史）
  │     → ContextAssemblerInput { reader（内部对象构造）,
  │         input, rewritten_input, … } → 背景 messages（降级可见）
  │     （模型可见的当前 user 消息仍为原始 input——见 §4.5）
  ├─ 推理循环（≤ max_rounds，缺省 16；round 序号 1-based 入载荷）：
  │    Model::Requested(Reasoning, round) → 流式调用
  │    StreamDelta(round) ×N → ToolCall → 并行执行（完成序事件 / 调用序回填）
  │    └ 结果回填 → 下一轮（round+1）
  ├─ 完成后：
  │    conv.push_turn(Turn { input, messages, outcome })           ← 真相归档（内存）
  │    runtime.conversation_store().save(conv.state())            ← 持久化（显式驱动）
  │    agent.context().on_turn_completed(                         ← 终态事件前
  │        conversation, input, messages,
  │        memory: <内部记忆对象>, agent_model,
  │        events, task_spawner,
  │    ).await
  │       同步段：主题推进（drifted → 冲刷 + TopicShifted 经总线）+ L1 归档
  │               （TurnArchived 经总线；FlowFailed{AfterTurn} 可见）
  │       后台段：task_spawner 登记 spawn（压缩 Compacted / 蒸馏 Distilled）
  ├─ emit 终态：Completed(output)（失败→Failed；中断→Cancelled）
  └─ 每次发射双路：交付路（背压→ExecutionEvent）+ 总线（先感知）
```

### 5.2 语义要点

- **流自足**：`Completed` 携带 `AgentOutput`；终态不变量不变；
- **round 载荷**：消费者免除推导（`None` 与 `ContextManagement` 互证）；
- **环境流向**：执行链服务全部来自 Agent 的 runtime；**行为与数据
  分离**——引擎（Agent 级）经载荷接收存储（Runtime 级），
  Runtime 为编排点；
- **取消四入口一信号**（不变）。

## 6. 对象生命周期与编程范式

事件视角的执行流见 §5.1；本节是**对象与范式**视角。两者合读即为
完整原理。

### 6.1 生命周期五阶段

**阶段一：Bootstrap（应用启动，一次）**

```rust
let runtime = SynonzRuntime::builder().build();      // 零注册即用
```

| 对象 | 诞生 | 寿命 | 死亡 |
|---|---|---|---|
| SynonzRuntime | `build()` | 应用全程 | 应用退出（推荐 `shutdown()` 显式收尾） |
| 记忆内部对象（三存储位组装） | build() | 同 runtime | 同 runtime |
| Memory（应用面：管理动词） | build()（内部对象之上） | 同 runtime | 同 runtime |
| 会话表 | build() | 同 runtime | 同 runtime |
| 事件总线 + 常驻派发器 | build() | 同 runtime | 同 runtime |
| 系统调度器 + 计时线程 | build()（宿主 Handle 捕获/注入） | 同 runtime | shutdown / Runtime 消亡 |
| 服务实例（store×4 / observers） | 注册或缺省 | 同 runtime | 同 runtime |

**阶段二：Configure（每个 Agent 角色，一次）**

```rust
let context = Context::new().l1_window(30);   // 引擎配方（纯行为配置）
let agent = Agent::react(&runtime, model, tools)
    .context(context)                                // Agent 级注册
    .build()?;                                       // （observability 开关已退役）
```

| 对象 | 诞生 | 寿命 | 死亡 |
|---|---|---|---|
| Context 引擎 | `Context::new()`（可先于 runtime） | 随 Agent（克隆共享） | 随 Agent——纯配置，无泄漏面 |
| Agent | `build()` | 长存（克隆廉价） | dropped |

**阶段三：Session（每个用户会话）**

```rust
let conv = Conversation::new(&runtime, &subject)?;   // 创建（三动作）
let conv = Conversation::of(&runtime, &subject, id)?; // 恢复
```

| 对象 | 诞生 | 寿命 | 死亡 |
|---|---|---|---|
| Conversation | new / of | 长存（克隆 = 同一会话） | dropped——落账状态在 store 里活得比它久 |

**阶段四：Turn（每次执行——对象最密集）**

```rust
let mut execution = agent.run(conv.turn_input("问题"));
```

| 对象 | 诞生 | 寿命 | 死亡 |
|---|---|---|---|
| TurnInput | `conv.turn_input()` | 一条语句 | 被 `run()` 消费（**可变借用**串行化同会话轮次） |
| Execution | `run()` 返回 | 消费者持有 | dropped（**drop = RAII 取消**） |
| AgentLoopTask | `run()` spawn | 单次 run | 终态 / 取消 |
| ContextAssemblerInput | 行为时刻构造（引擎内部） | 单次行为 | 行为返回（**载荷即汇合点**——引擎 × 系统资源） |
| 交付 tap | `run()` | run + 清空交付通道 | 消费者消失后退出 |
| Turn | run 终态 | **永存**（会话内 + store） | 数据删除 |

**阶段五：Teardown（运行期自动 + 退出期显式）**

```rust
// 运行期：Monitor 自动空闲清扫（系统调度器周期任务，Skip、立即首触发）
//   空闲超时会话 → end(IdleSwept)；崩溃孤儿由下次启动的立即首扫对账
conv.end(&runtime).await;          // 显式终结（三动作 + emit Ended，幂等）

// 退出期：应用（select! + 信号）显式收尾
runtime.shutdown().await;          // 停调度 → 收尾所属会话（Shutdown）→ 观测 flush
// 终结内部：Runtime 收尾（init）——drain 会话表（有界）+ 机械促进 L2→L3
```

| 对象 | 诞生 | 寿命 | 死亡 |
|---|---|---|---|
| 后台维护任务 | 引擎维护段 spawn（句柄登记会话表） | 压缩/蒸馏完成 | drain 时收口（有界）；失败经总线 Background 上报 |
| Monitor 任务 | build 注册（配置 idle_timeout） | 同 runtime | shutdown / Runtime 消亡 |
| 计时线程 | build 启动 | 同 runtime | shutdown / Runtime 消亡 |

### 6.3 退出路径全表（生命周期的"死法"）

| 路径 | 触发 | 落账 | 终态事件 | 观察面 |
|---|---|---|---|---|
| 完成 | 模型无工具调用收尾 | Turn::completed + 持久化 | Completed(output) | ✅ 全量含装配载荷 |
| 失败 | 模型流 Err / 无 Finish / max_rounds 耗尽 | Turn::failed | Failed | ✅ |
| 取消-1 | token / cancel() / timeout（三挂起点） | Turn::cancelled | Cancelled | ✅ |
| 取消-2 | 预循环抢跑（取消先于循环） | Turn::cancelled | Cancelled | ✅ |
| 取消-3 | **drop(Execution)**（RAII：消费者消失） | Turn::cancelled | 消费者已不在——仅观察面收到终态 | ✅ 终态不丢 |

### 6.4 编程范式

1. **声明式配置 + 命令式执行**：runtime / agent 是声明式长存配置，
   会话是数据，每个 turn 是一次命令式执行；
2. **借用检查器即轮次串行器**：同会话并发轮次在编译期被拒绝；
3. **组合自由**：多 Agent 续同一会话（各 run 各落账）/ 一个 Agent
   并行多会话——各 Agent 自带引擎，**策略一致性归应用/编排层**；
4. **RAII 即取消**；错误路径取向"错误不可表达"优先于"报错拦截"；
5. **反应即订阅**：观察位自由注册；扩展点按策略轴立法（新槽 =
   新 ADR）；
6. **行为与数据分离**：引擎不持有存储，Runtime 为编排点，载荷即
   汇合点——构造零耦合，时序自然正确。

所有权与并发规则：

| 规则 | 机制 |
|---|---|
| 同会话并发轮次 | 编译期拒绝（可变借用） |
| 一个 Agent × 多会话并行 | Agent 无状态（引擎纯配置），每次 run 独立 |
| 多 Agent × 同一会话续写 | 会话独立实体；每个 run 记录自己的轮次 |
| 跨 runtime 混用 | 结构上无法腐败 |
| 同一会话重复终结 | 结构上幂等（ended 状态 + 首次判定收口） |
| 取消 | 四入口一信号（§10.1） |

## 7. 会话与真相

| 语义 | 决策 |
|---|---|
| 落账 | **全入史**：`Turn { input, messages, output, outcome }`，outcome ∈ {Completed, Failed, Cancelled} |
| 写入点 | `push_turn` 唯一（pub(crate)，框架所有） |
| 记忆触发面 | **仅成功轮写入 L1**（失败轮不污染记忆层） |
| 持久化 | 经 ConversationStore 自动保存；失败可见（never-silent） |
| 生命周期 | 三入口全带环境：new/with_id（构造+落库+emit Created）/ of（恢复）/ end（终结三动作，幂等） |
| 状态 | `ConversationState` 含 ended——重复终结结构上收口，Monitor 过滤 |
| 三终结时机 | `ConversationEndReason::{Explicit, IdleSwept, Shutdown}`；终结收尾 = **Runtime 结构行为**（init 模式：drain 会话表（有界）+ 机械促进 L2→L3，无模型调用无策略）——与 Agent 无关 |
| 归属登记 | 会话表：new/with_id/of 登记，任何 end 路径移除；`shutdown` 的收尾名单 |
| 自动终结 | Monitor 空闲清扫（系统调度器 Skip 周期任务）：`list_stale` 下推 → end(IdleSwept)；崩溃孤儿由下次启动的立即首扫对账 |
| 退出期收尾 | `runtime.shutdown().await`：停调度 → 终结本 runtime 所属会话（Shutdown）→ 观测 flush；幂等 |
| 查询面 | `list_stale(before, cursor, limit)`（清扫下推）+ `list(ConversationQuery)`（元数据关键字 + 游标分页）→ `ConversationSummary`（不含 turns） |
| 自定义终结 | 走**观察位**（订阅 `ConversationEvent::Ended` 自行处理）——扩展走已有机制 |
| 导出 | export = 真相轮次（可迁移）；记忆层是三契约位事务，不随行 |
| 工厂 | new = 创建 / of = 恢复（缺者报错）/ ensure = get-or-create（S3） |

真相与背景的归档对称：**Conversation 归档真相（Turn，含失败），
Context 引擎归档背景（记忆层，仅成功）**——两种归档，互不越界。

> `sweep_stale` 公开入口已退役（ADR-0018 开放项决议）：Monitor 为
> 唯一清扫路径；内部 sweep 逻辑为任务体，不开公开面。

## 8. Agent 状态模型与状态引擎

### 8.1 上下文 = Agent 的状态（统合概念）

> **上下文（Context）= Agent 的状态 = 叙事背景——它是让 Agent
> 变成有状态的关键部分。**

```
Agent（有状态的运行体）
  = 决策循环（Loop） + 上下文（状态） + 运行时（环境服务）

上下文（Agent 状态 · 统合概念）
  ├── 记忆（L1+L2+L3 完整体）—— 沉淀的状态【持久部分】
  ├── 环境感知结果（Loop 内的模型响应、Tool 调用结果）—— 即时部分
  └── 运行时要素 —— 环境衍生的感知（未来原料位：工具目录/系统状态…）

状态的物化循环：
  上下文（状态流）──每轮物化──→ 工作载荷（run 内 messages·瞬时快照）
       ▲                              │ 循环增长（模型响应+工具结果=新感知）
       └── 沉淀维护（归档→L1→压缩→L2→蒸馏→L3）←──┘
```

- 记忆 ⊂ 上下文（包含关系，非并列）——记忆是上下文的持久沉淀；
- **装配 = 完整上下文的物化**：记忆为主原料 + 感知/运行时原料位
  （`ContextAssemblerInput` non_exhaustive 开放）；
- 编辑器对齐：编辑器的上下文 = 对话 + 文件感知 + 记忆的统合——
  同一个"Agent 状态"概念；其 compaction（上下文压缩）= 我们的
  L1→L2 流转（维护行为，非"记忆压缩"的窄义）；
- 感知延迟梯度 = 上下文新鲜度的分级沉淀（§8.4）。

### 8.2 Context 引擎（Agent 级·具体类型）

| 维度 | 决策 |
|---|---|
| 引擎形态 | **具体类型 `Context`**（ADR-0019 退役开放 trait）；`Agent` 持 `Arc<Context>`（无擦除）；入口 `assemble`/`on_turn_completed` 为 `pub(crate)` |
| 读相位 | **整段可扩展**：`TurnInputRewriter`（预处理）+ `ContextAssembler`（组装）；输入只读（`MemoryReader`）；顺序 = 先改写、后组装 |
| 写相位 | **框架独占编排与写入**；子钩子 `ConversationTopicDetector`/`MemorySummarizer`/`MemoryDistiller`（+ 楼层参数 `l1_window`/`l2_cap`） |
| 纯行为 | 引擎无实例状态（后台任务句柄登记 Runtime 会话表）；策略槽+子钩子+楼层参数即全部构造内容 |
| 默认实现内化 | `LayeredMemoryContextAssembler` / 内置摘要 / `FirstSegmentTopicDetector` / 机械蒸馏均 pub(crate)——**契约公开，默认实现内化**（公开面=扩展面） |
| 模型角色 | `with_model`（引擎模型，缺省 = agent 模型）；解析 `with_model ?? agent_model` 收口引擎；记忆跟随上下文（无独立记忆模型） |
| 命名族 | 契约 = 行动者（-er）；实现 = 特征 + 契约名对照；`Input ↔ Output` 对偶；主语 = 操作对象 |
| 行为时刻 | 框架编排：agent 循环经内部对象构造 reader 后调用 `context.assemble(Input{ reader, .. })`；轮末调用 `on_turn_completed(conversation, input, messages, memory, agent_model, events, task_spawner)`——引擎 × 系统资源经载荷汇合 |
| 终结 | 不在引擎（收尾无策略：drain + 机械促进 = Runtime 结构行为） |

**维护编排的时序语义**（内置维护）：

| 段 | 内容 | 感知档位 |
|---|---|---|
| 同步段（终态事件前 await） | 主题推进 + L1 归档 | 即时感知档：下一轮装配必见 |
| 后台段（spawn + 登记会话表） | 压缩（摘要→append→**按 id 删源**）+ 蒸馏（**先变换后 pop**；**写前按 id 重校验来源**） | 近期感知档：滞后生效，drain 时收口 |
| 终结（Runtime 结构行为） | drain 会话表（有界）+ 机械促进 L2→L3 | 终结语义：返回即收口完成 |

**维护写入的并发纪律（ADR-0020）**：写入前按 id 重读来源，只处理仍
存在的来源；写前再校验一次，来源集合有变则**丢弃本次产物**并发无
内容事实——策略槽零改动（见 §8.3）。

### 8.3 记忆存储、内部对象与 Memory 应用面

```
存储侧：三独立契约位（每层伴随自己的存储扩展）
  MemoryL1Store（默认：内置内存——纯内存是工作记忆唯一合理介质；
                 不参与条目管理，契约不变）
  MemoryL2Store（默认进程内；可换 Redis…）——ADR-0020 必选加
                 get/update/remove/list（按 id）
  MemoryL3Store（默认进程内；可换向量库/图库…）——同上；
                 upsert 契约更新：同身份替换保留原 id
  RuntimeBuilder 三个注册位 → build() 时组装为内部记忆对象

机制侧：crate 内部记忆对象（外部不可构造）
  三存储槽聚合 + 分层原语（append/pop/upsert/query/len/window/read）
  + MemoryReader 构造 + 维护写入的重校验纪律
  引擎 / Runtime / 后台维护任务使用；runtime.memory() 返回应用面

应用面：Memory（ADR-0020）
  管理动词 list/get/edit/forget（subject 按调用传递）
  条目 = L2 情景摘要（Summary）+ L3 知识（Knowledge）；L1 是原始材料
  新鲜度 updated_at；keyset 分页（结构序 + 不足补拉）
  事实 Updated/Removed（无内容）；不做日常新增（导入为框架外边界）
```

- **行为与数据分离**：引擎不持有存储（构造零耦合）；数据唯一
  权威源是 Runtime；无人能自行构造内部对象（字段私有）；
- **边界立法：存储位不得策展**——存储插件不得在 append 时压缩/
  蒸馏（策展时机由生命周期事实驱动；可见性立法在引擎层）；
- **只读纪律**：策略槽只见 `MemoryReader`（写与策展在类型上不存在）；
  写入永远由引擎收口；**管理写入与系统写入同权**（同身份槽原地
  更新、id 不变、无优先级；内容质量归策略质量）；
- **并发纪律（ADR-0020）**：维护写入前按 id 重校验来源（重读 →
  只处理幸存者 → 写前再校验 → 一致则写并按 id 删源，不一致则丢弃
  产物 + 事实）——"遗忘不回写"由机制保证，策略槽零改动；
- **注入边界（ADR-0020）**：不提供应用日常新增（`add`）；批量导入/
  迁移由应用自持存储句柄在框架外完成（框架不感知、无事实、无有序
  保证——文档化边界）；
- 扩展轴正交：读侧换策略槽 / 写侧换子钩子；逐层换存储改对应
  `MemoryL*Store` 位；互不影响。

### 8.4 感知延迟梯度（分层设计的核心 rationale）

记忆感知延迟 = 记忆产生后 Agent 感知到它的速度：

```
L1（即时感知）：本轮归档 → 下一轮装配即可读
L2（近期感知）：压缩完成后可读（分钟级滞后可接受）
L3（长期感知）：蒸馏/促进后可读（更慢）
```

各层 rustdoc 写明性能特征引导（插件自带非功能特征责任，同
Model/Tool 插件原则）；L2/L3 缺失时 L1 兜底最近记忆（记忆流软
失败立法的深层理由）。

## 9. 事件总线（ADR-0017 核心）

### 9.1 概念模型与术语立法

| 概念 | 定义 |
|---|---|
| **EventBus** | Runtime 持有的派发设施——感知事件（被 emit 通知）→ 派发给订阅位；与发射端是使用关系而非组成关系 |
| **EventSource** | 通知总线的主体（执行循环、`Conversation::new`/`end`、Monitor 清扫、`shutdown`、Context 引擎维护段）——**定义性动作只有一个：emit** |
| **EventListener（订阅位）** | 观察车道订阅者（N 个 Observer）与行动车道契约位（立法，S3 预留） |
| **Event（SynonzEvent）** | 总线承载的事实类型，入参类型锁死（封闭枚举） |

**术语立法（唯一性）**：

- **事件驱动模型 = 总线体系，有且仅有**。凡事件驱动皆经总线；
- **交付不是事件驱动**：产品消费者接收交付（ExecutionEvent 流，
  点对点、背压、per-run）是执行面固有的输出管道；
- 执行循环有两个无关身份：执行面交付叙事（非事件驱动）/ EventSource
  通知总线（事件驱动）；
- `ExecutionEvent` 是 Turn 族事实的**交付投影**（类型复用不是
  体系混淆）。

### 9.2 双车道与订阅位

```
EventSource ──emit──→ EventBus（Runtime 持有·常驻派发器）
                        ├── 观察车道：旁路·异步·丢弃+lag·N 个 Observer
                        │   （熔断隔离·保序·终态后 drain）
                        └── 行动车道：同步 await·契约位立法（S3 预留；
                            0.3.0 无派发点——终结收尾为 Runtime 结构行为）
```

- **观察车道语义**：绝不拖慢执行；通道内保序（跨事件族不承诺）；
  熔断隔离；终态后 drain；
- **后台失败可见性**：引擎后台段任务失败投
  `MemoryEvent::FlowFailed { moment: Background }`——观察位可见、
  交付流不可见（终态不变量保持）——分层可见性；
- **观测 flush（内部）**：`shutdown()` 返回前经队列屏障等待已发
  事实全部投递（终局事实不丢）；屏障是内部机制，不属公开面。

### 9.3 发射源 × 订阅位矩阵

| EventSource | emit | 观察位 | 行动位 | 交付 |
|---|---|---|---|---|
| 执行循环 | Turn 三子族 | ✅ | — | ✅ ExecutionEvent 投影 |
| 执行循环（同步段失败） | MemoryEvent::FlowFailed{AfterTurn} | ✅ | — | — |
| `Conversation::new`/`with_id` | ConversationEvent::Created | ✅ | — | — |
| `Conversation::end` / Monitor 清扫 / `shutdown` | ConversationEvent::Ended | ✅ | —（收尾=Runtime 结构行为） | — |
| Context 引擎（`ConversationTopicDetector` 判定漂移） | ConversationEvent::TopicShifted | ✅ | — | — |
| Context 引擎维护段/失败回收 | Memory 四流转/FlowFailed | ✅ | — | — |
| `Memory` 管理操作（list/get/edit/forget） | MemoryEvent::Updated / Removed（无内容） | ✅ | — | — |

治理原则：Turn 事件只被目击与交付；记忆反应锚在引擎契约的时刻上
（维护段）；终结收尾是系统行为（与 Agent 无关）。

### 9.4 扩展点生效时序（全景契约）

| 扩展点 | 调用时机 | 生效边界 | 失败语义 |
|---|---|---|---|
| `Model` | 推理循环每轮 | 直接决定本轮输出 | 终态 Failed |
| `Tool` | 模型请求时（并行） | 结果回喂，影响本轮后续 | 软失败回喂 |
| `TurnInputRewriter`（读侧槽②） | 每 run 装配前（引擎内） | 决定组装输入（召回模型视图） | 可见降级（保留原文） |
| `ContextAssembler`（读侧槽①） | 每 run 装配（引擎物化时） | 决定模型看到什么 | 降级可见（Output.failures） |
| `ConversationStore` | record! / 创建 / 终结时刻 | 真相持久化 | 软失败可见 |
| `MemoryL1/L2/L3Store` | 被引擎读/写（槽只见 reader）；管理经 `Memory` 应用面按 id 操作 | 跟随调用者时序 | MemoryEvent::FlowFailed |
| `Memory` 应用面（list/get/edit/forget） | 应用调用时（同步） | 立即对所有读路径生效；在途维护按 id 重校验不回写 | 单条失败不中断批（返回失败清单） |
| `ConversationTopicDetector` | 引擎同步段内 | 主题标签+漂移判定 | 纯计算无失败 |
| `MemorySummarizer` | 引擎维护段（含后台） | L2 内容 | 软失败（降级：原文入 L2 可见） |
| `MemoryDistiller` | 引擎维护段（含后台） | L3 内容（先变换后 pop） | 软失败：不丢 L2，FlowFailed 可见 |
| `Observer` | 事件 emit 时 | **永不影响执行** | 熔断+lag |
| Context 读相位（内部） | run 开始一次 | 决定本轮起点背景 | 降级可见 |
| Context 写相位（内部·框架独占） | 终态事件前 await | 同步段=下一轮必见；后台段=滞后 | 同步段返回值；后台段经总线 |
| 辅助模型调用（经 `NarratedModel`） | 引擎维护段 | 调用自动叙述（无 StreamDelta） | 各自槽的失败语义 |

## 10. 横切语义

### 10.1 取消与超时（不变）

四入口一信号（ADR-0004）。agent 级 `default_timeout`（显式
opt-in）+ per-run `with_timeout` 覆盖。

### 10.2 错误分诊

| 层级 | 形态 | 行为 |
|---|---|---|
| 工具级（软失败） | `ToolError` / `ToolResult::Err` | 喂回模型，run 继续 |
| run 级（硬失败） | `AgentError` | Failed 事件；await Err；入史（outcome=Failed） |
| 取消 | `AgentError::Cancelled` | Cancelled 事件；非失败；入史（outcome=Cancelled） |
| 记忆流失败 | `MemoryEvent::FlowFailed`（moment 载荷） | **不中断 run、不再静默**；经总线可见 |
| 装配失败 | 降级可见（Output.failures） | 背景缺失但 run 继续 |

### 10.3 序列化

`SynonzEvent`（全族）/ `Turn` / `ConversationState` 全 serde——
录制回放、真相迁移、确定性测试三大用途共享同一形状。版本演化
遵守 serde 兼容性惯例。

## 11. 扩展点与插件化（全景）

| 契约位 | 层级 | 职责 | 注册 | 缺省 |
|---|---|---|---|---|
| ConversationStore | Runtime | 会话真相存取 + 查询面（`list_stale` / `list`） | RuntimeBuilder | 进程内 |
| MemoryL1Store | Runtime | L1 工作记忆 | RuntimeBuilder | 内置内存 |
| MemoryL2Store | Runtime | L2 摘要层 + 按 id 的 `get`/`update`/`remove`/`list`（ADR-0020） | RuntimeBuilder | 进程内 |
| MemoryL3Store | Runtime | L3 知识层 + 按 id 的 `get`/`update`/`remove`/`list`（ADR-0020）；`upsert` 保 id | RuntimeBuilder | 进程内 |
| Observer（N 个） | Runtime | 全量事件旁路目击 | RuntimeBuilder | 无（观察位为空） |
| **Context**（引擎） | **Agent** | 读写两相位的具体基座 | **AgentBuilder** | `Context::new()` |
| └ TurnInputRewriter | Agent 引擎槽（读） | 输入预处理（模型视图） | 引擎构造链 | 无改写 |
| └ ContextAssembler | Agent 引擎槽（读） | 装配策略 | 引擎构造链 | 内置（内化） |
| └ ConversationTopicDetector | Agent 引擎槽（写） | 主题策略 | 引擎构造链 | 内置（内化） |
| └ MemorySummarizer | Agent 引擎槽（写） | L1→L2 内容变换 | 引擎构造链 | 内置（内化） |
| └ MemoryDistiller | Agent 引擎槽（写） | L2→L3 内容生成 | 引擎构造链 | 内置机械提升 |
| MemoryReader | 载荷门面 | 策略槽的只读记忆视图（**构造内部化**，ADR-0020） | （非注册位） | — |
| **Memory**（应用面） | 应用 | 条目管理 `list`/`get`/`edit`/`forget`（subject 按调用传，ADR-0020） | `runtime.memory()` | — |

统一模式：业务实体不耦合插件；**编排在框架，存取/决策在实现侧**；
系统资源 Runtime 级、策略引擎 Agent 级（微 OS 分层）。工具另有
`#[derive(Tool)]` 类型化壳。

**读写不对称（ADR-0019）**：读相位整段可换（只读、不可腐化状态）；
写相位框架独占编排与写入，只换窄子钩子（写权限不外放）。

**管理面（ADR-0020）**：`Memory` 应用面提供条目管理；分层原语与
存储槽聚合收进 crate 内部对象；不提供应用日常新增（批量导入/迁移
为框架外边界）；管理写入与系统写入同权（原地更新、id 不变）。

系统调度器不是注册位：内核态、不可注册（开发者只读快照）；开发者
自定义定时经公开 `Scheduler` 组件自建（用户态；共享池或自建池）。

## 14. 边界与未来

- **S3（多 Agent 编排）**：维持后置，无时间表；Conversation 独立
  实体（1~N Agent 参与）为编排奠基；预留面已标注触发条件
  （`CancelReason::Parent` / `CallPurpose::Classification` /
  `SubjectType::Agent`）；**总线行动车道**（同步反应契约位）立法
  保留，0.3.0 无派发点；**Turn 增加 Agent 标识** = S3 开放项（多
  Agent 会话的审计/编排需要）；Agent 间通信（④）另立 ADR——总线
  词汇表为其留缝（顶层加实体族变体，非破坏）；
- **控制流影响**（③：拦截/改写执行，middleware 性质）：另立 ADR，
  暂无场景（IDE 路由等按执行前普通代码处理）；
- **Monitor 机制**：由 ADR-0018 落地并并入正式架构（见 §2.4、§6、
  §7）——原延期记录关闭；资源状态监督拒收（无消费者）；后台维护
  任务健康并入前提工程（drain 有界化 + panic 可见化）；
- **调度扩展（ADR-0018 暂缓项）**：pause/resume/status、cron 类
  规则、一次性/延迟任务、自定义执行池配套便利、正文检索、
  Scheduler 专用事件词条——均为非破坏性可加；
- **引擎上下文模型（原“后台工作专用模型”）**：由 ADR-0019 落地——
  `Context::with_model`（缺省 = agent 模型）；**记忆跟随上下文**，
  不设独立记忆模型；
- **ADR-0019 边界（无当前需求，触发再立项）**：整段写侧扩展（写权限
  与三层记忆不变量不可兼得；如需再以“窄钩子：只读视野 + 结构化
  贡献”增量引入）；会话终结 flush 保证（应用层观察
  `ConversationEvent::Ended` + 幂等补偿归档）；远程存储不进默认
  Memory 管线（Redis/Neo4j/Milvus 类系统走自定义策略实现或外部
  编排）；自持模型客户端调用的可观测性由实现自担；辅助叙述
  `emit_deltas` 开关（当前辅助调用恒无 `StreamDelta`）；T2 主题
  （活跃主题=框架标签；多主题集合/切换轨迹归引擎态，见扩展指南）；
- **ADR-0020 边界（无当前需求，触发再立项）**：应用日常新增（`add`）
  ——新增恒来自对话沉淀，批量导入/迁移由应用自持存储句柄在框架外
  完成（无事实/无有序保证，文档化边界）；严格全局时间序（跨 kind
  持续归并 + 复合游标）为可加性后续；语义搜索（v1 由 `list` 关键字
  表达）；事实聚合/矛盾消解归策略层（可用查询 + 管理动词表达）；
  错误覆盖的内容质量归策略（内核不设优先级）；L1 留存与会话级清理
  另行立项；物理删除/副本/备份/加密擦除归存储实现；
- **ended 状态门**（终结后拒绝续写）：状态依据已就位，场景出现时
  带 ADR 立法；
- **刻意不做**（无触发不引入）：事件过滤/采样配置、动态观察者
  注销、无场景驱动的模式层抽象、下游自定义事件上总线（推迟——
  订阅位制下无反应者可认领）、组装策略覆灭入口；
- **纯回放配置**（L1 全窗 + L3 预算 0）：用户真实需求出现再表达。
