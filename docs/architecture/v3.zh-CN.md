## 1. 系统概览

### 1.1 框架身份（不变）

Synonz 是**显式、可控、可观测的 Agent 工程基础设施**（纯 Rust 库）。
四支柱（反过度抽象 / 行为可控 / 生命周期完备 / 内生可观测）与
High Level 优先原则（ADR-0010：80% 场景高层 API 解决，20% 原语自控）
共同构成一切设计的裁决标准。

### 1.2 分层结构（0.2.0 契约收敛后）

```
┌─────────────────────────────────────────────────────────────┐
│ 模式层   ReAct / Research / Reflection 预设（配方打包）          │ ADR-0010
├─────────────────────────────────────────────────────────────┤
│ 组合层   Agent：执行配置（model+tools+prompt+budget）           │ ADR-0007/0015
│          持有 Runtime 引用 + observability 开关                 │
├─────────────────────────────────────────────────────────────┤
│ 执行面   Execution：叙事流（ExecutionEvent）+ 终点 Future        │ ADR-0014
│          + 控制器（cancel / with_timeout / rounds）             │
├─────────────────────────────────────────────────────────────┤
│ 会话层   Conversation（真相：Turn + outcome 全入史）/ TurnInput  │ ADR-0011/0015
├─────────────────────────────────────────────────────────────┤
│ 背景层   Context：背景引擎（组装 / 归档 / 压缩，取材唯记忆）       │ ADR-0012/0015
├─────────────────────────────────────────────────────────────┤
│ 记忆层   Memory：主体拥有的分层记忆（L1 / L2 / L3）              │ ADR-0012
├─────────────────────────────────────────────────────────────┤
│ 运行时层 SynonzRuntime（Bootstrap + 四契约注册表）+ Subject      │ ADR-0012/0016
├─────────────────────────────────────────────────────────────┤
│ 原语层   Model / Tool / AgentEvent 事件流 / canonical Message   │ ADR-0003/0005/0006
├─────────────────────────────────────────────────────────────┤
│ 适配层   synonz-openai / synonz-anthropic / synonz-mcp         │ ADR-0008
└─────────────────────────────────────────────────────────────┘
  ═══════════════════════════════════════════════════════════
   可观测旁路（横切，非一层）：Observer ← 观察者派发器（每 run 后台任务）
   挂在执行发射点，接收全量 AgentEvent，永不阻塞热路径    ADR-0016
```

依赖方向永远向下。**Agent 持有 Runtime**（ADR-0015，取代 0012
"零环境知识"）：执行配置知道自己活在哪个容器，执行链的全部服务
（记忆、持久化、策略、装配）自顶向下流动；会话是纯数据实体（真相 +
身份），不持有环境——跨 runtime 混用在结构上无法造成分裂写入。
"致命且无报错"最终让位于"**错误不可表达**"。

**可观测旁路不是一层**：它挂在执行发射点、横切全部层、在独立任务
中投递——忠实表达"观测绝不影响执行"的架构语义。

## 2. 运行时与主体

### 2.1 SynonzRuntime：显式 Bootstrap + 四契约注册表

```rust
let runtime = SynonzRuntime::builder()
    .conversation_store(store)   // ① 会话真相存取（缺省进程内）
    .memory_store(memory)        // ② 分层记忆存取（缺省进程内）
    .context_assembly(strategy)  // ③ 组装策略（缺省 LayeredMemory）
    .observer(my_exporter)       // ④ 观察者（0.2.0 新增，可多个）
    .memory_policies(policies)   // L1 窗口 / L2 容量（缺省 20 / 8）
    .idle_timeout(duration)      // 空闲超时（sweep_stale 兜底用）
    .build();
```

- 显式构造、同源保证：全部环境在同一个 Runtime 上装配；
- 前三契约未注册即用进程内默认实现（零注册即用）；
- **Observer 不注册 = 观测面完全关闭**（与前三者不同——可观测由
  独立服务/进程承接，默认关闭，Agent 侧开关显式启用）；
- `sweep_stale`：应用调度的空闲兜底，对超时会话执行 ConversationEnd
  流（主体重建已修复——ADR-0015 决策十）。

### 2.2 Subject：主体身份

`Subject = (SubjectType, id)`。`SubjectType::User` 现用；
`SubjectType::Agent` 为 S3 预留（带触发条件标注，ADR-0015 决策九）。
会话必有主体（ADR-0012）。

### 2.3 Agent 与 Runtime 的容器关系

```rust
let agent = Agent::builder()
    .runtime(&runtime)      // 必选：Agent 知道自己活在哪个容器
    .model(model)           // 必选
    .tool(my_tool)
    .observability(true)    // 观测开关（默认 false）
    .build()?;
// 预设同构：Agent::react(&runtime, model, tools) / research / reflection
```

取代"零环境知识"的论证：无知挡住 Runtime 级服务的全量挂载、未消灭
环境分裂只是上移分裂（with_context 手动挂载即分裂口）；正解 =
持有容器 + 执行入口校验 + 显式报错。Agent 仍无运行时状态——持有的
是容器引用（ADR-0007"无状态配置体"的修订表述）。

## 4. 公共 API 全景（0.2.0 形态）

### 4.1 执行（唯一入口）

```rust
// 会话必选：唯一参数来源 conversation.turn_input(...)
let mut execution = agent.run(conv.turn_input("北京天气？"));
// 外部令牌：agent.run_with(conv.turn_input(...), token)

// 三合一句柄：叙事流 + 终点 Future + 控制器
while let Some(event) = execution.next().await { /* ExecutionEvent */ }
let output: AgentOutput = execution.await?;      // 流自足：Completed 已携带
execution.cancel();
execution.with_timeout(Duration::from_secs(30));
execution.rounds();
```

```rust
pub enum ExecutionEvent {
    Delta(ModelDelta),                          // 文本增量
    ToolRequested(ToolCall),                    // 工具卡片出现
    ToolCompleted { call_id, result },          // 工具卡片落定
    Failed(AgentError),                         // 失败终态
    Cancelled(CancelReason),                    // 中断终态
    Completed(AgentOutput),                     // 成功终态（携带结果）
}
```

### 4.2 会话（收敛后）

```rust
let mut conv = Conversation::new(&runtime, &subject)?;  // new=创建
let conv = Conversation::of(&runtime, &subject, id)?;   // of=恢复（缺者报错）
conv.turn_input("...")     // 唯一执行入口的参数来源
conv.end()                 // 显式结束（触发 ConversationEnd 流）
conv.export()?             // 真相轮次导出（记忆层不随行——边界明示）
conv.messages(); conv.turns(); conv.topic();
// push_turn：pub(crate)——真相归档唯一写入点，归框架
// 已删除：truncate_last / clear / fork / import
```

### 4.3 Model 契约（瘦身）

```rust
pub struct ModelRequest {
    pub messages: Vec<Message>,
    pub tools: Vec<ToolSpec>,
}   // params 字段删除
```

params 绑定适配器构造（不传 = 默认）：
`OpenAiModel::builder().api_key(k).temperature(0.3).build()`——
参数是 model 行为的一部分，不是执行配置（ADR-0015 决策八）。

### 4.4 Observer 契约（0.2.0 新增）

```rust
pub trait Observer: Send + Sync + 'static {
    /// 全量事件投递（含输入侧载荷）。实现必须快速返回。
    fn on_event(&self, ctx: &ObserverContext, event: &AgentEvent);
    /// 观测队列溢出丢弃后，观察者派发器追上时调用（累计丢弃数）。
    fn on_lagged(&self, ctx: &ObserverContext, dropped: u64) {}
}

#[non_exhaustive]
pub struct ObserverContext { pub execution_id: u64 }   // 进程内自增
```

## 5. 执行模型：单一执行面 + 三时刻委托

### 5.1 一次交互的完整执行流

```
agent.run(conv.turn_input(input))
  │ 派生背景：ctx = Context::for_conversation(conv, agent 的 runtime)
  ├─ 时刻① 组装：ctx.assemble(input) → 叙事背景（取材唯记忆）
  ├─ 发射 Lifecycle::Started
  ├─ 推理循环（≤ max_rounds，缺省 16）：
  │    Model::Requested(Reasoning) → 流式调用
  │    StreamDelta ×N → ToolCall → 并行执行（完成序事件 / 调用序回填）
  │    └ 结果回填 → 下一轮
  ├─ 完成后：
  │    conv.push_turn(Turn { input, messages, outcome })           ← 真相归档（内存）
  │    runtime.conversation_store().save(conv.state())            ← 持久化（显式驱动）
  │    ctx.on_turn_completed(&model, ...)                         ← 时刻②③
  │       归档：L1 写入（成功轮）+ 主题更新
  │       压缩：TurnCount / L2Overflow 保底 + 叠加策略
  ├─ 发射终态：Completed(output)（失败→Failed；中断→Cancelled）
  └─ 观测旁路全程并行接收全量 AgentEvent（永不阻塞主链）
```

### 5.2 语义要点

- **流自足**：`Completed` 携带 `AgentOutput`——纯流消费者无需补
  await；await 消费者拿到相同结果（终态缓存机制保证一致）；
- **终态不变量**（0003 延续）：终态事件必为最后一项，之后流关闭；
- **环境流向**：执行链服务全部来自 Agent 的 runtime；会话是纯数据
  （真相 + 身份），跨 runtime 混用结构上无法造成分裂写入；
- **取消四入口一信号**（0004）：cancel() / drop RAII / with_timeout /
  run_with(token) → 终态 `Cancelled(CancelReason)`。

## 6. 对象生命周期与编程范式

事件视角的执行流见 §5.1；本节是**对象与范式**视角——每个对象何时
诞生、何时消亡、应用代码如何组织。两者合读即为完整原理。

### 6.1 生命周期五阶段

**阶段一：Bootstrap（应用启动，一次）**

```rust
let runtime = SynonzRuntime::builder().build();      // 零注册即用
// 或注册持久实现：.memory_store(db_store).observer(exporter)…
```

| 对象 | 诞生 | 寿命 | 死亡 |
|---|---|---|---|
| SynonzRuntime | `build()` | 应用全程 | 应用退出 |
| 服务实例（store / memory / assembly / observers） | 注册或缺省 | 同 runtime | 同 runtime |

**阶段二：Configure（每个 Agent 角色，一次）**

```rust
let agent = Agent::react(&runtime, model, tools)
    .observability(true)
    .build()?;
```

| 对象 | 诞生 | 寿命 | 死亡 |
|---|---|---|---|
| Agent | `build()` | 长存（克隆廉价） | dropped——无运行时状态，无泄漏面 |

**阶段三：Session（每个用户会话）**

```rust
let mut conv = Conversation::new(&subject);            // 纯数据新建
let conv = Conversation::of(&runtime, &subject, id)?;  // 从 store 恢复
```

| 对象 | 诞生 | 寿命 | 死亡 |
|---|---|---|---|
| Conversation | new / of | 长存（克隆 = 同一会话） | dropped——**落账状态在 store 里活得比它久** |

**阶段四：Turn（每次执行——对象最密集）**

```rust
let mut execution = agent.run(conv.turn_input("问题")); // ①②③ 瞬时发生
```

`run()` 的同步部分瞬时完成三件事：拆包 TurnInput → 派生执行机器
（通道、tap、任务、runner）→ 返回句柄；随后后台任务开始推理循环。

| 对象 | 诞生 | 寿命 | 死亡 |
|---|---|---|---|
| TurnInput | `conv.turn_input()` | 一条语句 | 被 `run()` 消费（**可变借用**串行化同会话轮次） |
| Execution | `run()` 返回 | 消费者持有 | dropped（**drop = RAII 取消**） |
| AgentLoopTask | `run()` spawn | 单次 run | 终态 / 取消 |
| Context | 循环内派生 | 单次 run | run 结束（无状态绑定器，可随时重建） |
| AgentRunner | `run()` | 与 Execution 共生 | 双双 dropped |
| 派发器 | `run()`（开关开时） | run + 清空队列 | 队列排空后退出 |
| Turn | run 终态 | **永存**（会话内 + store） | 数据删除 |

**阶段五：Teardown（可选）**

```rust
conv.end(&runtime);       // ConversationEnd 流：L2→L3 促进
runtime.sweep_stale();    // 应用调度的空闲兜底
```

### 6.3 退出路径全表（生命周期的"死法"）

| 路径 | 触发 | 落账 | 终态事件 | 观测面 |
|---|---|---|---|---|
| 完成 | 模型无工具调用收尾 | Turn::completed + 持久化 | Completed(output) | ✅ 全量含装配载荷 |
| 失败 | 模型流 Err / 无 Finish / max_rounds 耗尽 | Turn::failed | Failed | ✅ |
| 取消-1 | token / cancel() / timeout（三挂起点） | Turn::cancelled | Cancelled | ✅ |
| 取消-2 | 预循环抢跑（取消先于循环） | Turn::cancelled | Cancelled | ✅ |
| 取消-3 | **drop(Execution)**（RAII：消费者消失） | Turn::cancelled | 消费者已不在——仅观测面收到终态 | ✅ 终态不丢 |

### 6.4 编程范式

1. **声明式配置 + 命令式执行**：runtime / agent 是声明式长存配置，
   会话是数据，每个 turn 是一次命令式执行；
2. **借用检查器即轮次串行器**：同会话并发轮次在编译期被拒绝
   （`turn_input` 的可变借用），不是运行时锁；
3. **组合自由**：多 Agent 续同一会话（各 run 各落账）/ 一个 Agent
   并行多会话（Agent 无状态、克隆廉价）；
4. **RAII 即取消**；错误路径的设计取向是"错误不可表达"优先于
   "报错拦截"。

所有权与并发规则：

| 规则 | 机制 |
|---|---|
| 同会话并发轮次 | 编译期拒绝（可变借用） |
| 一个 Agent × 多会话并行 | Agent 无状态，每次 run 独立 |
| 多 Agent × 同一会话续写 | 会话纯数据；每个 run 记录自己的轮次 |
| 跨 runtime 混用 | 结构上无法腐败（会话不带环境，服务来自操作者） |
| 取消 | 四入口一信号（§10.1） |

## 7. 会话与真相

| 语义 | 决策 |
|---|---|
| 落账 | **全入史**：`Turn { input, messages, output, outcome }`，outcome ∈ {Completed, Failed, Cancelled}（取代"仅 Completed 入史"） |
| 写入点 | `push_turn` 唯一（pub(crate)，框架所有）；完成 / 失败 / 取消时由执行循环调用 |
| 记忆触发面 | **仅成功轮写入 L1**（失败轮不污染记忆层） |
| 持久化 | 经 ConversationStore 自动保存；失败可见（0015 立法） |
| 导出 | export = 真相轮次（可迁移）；记忆层是 MemoryStore 事务，不随行 |
| 工厂 | new = 创建 / of = 恢复（缺者报错）/ ensure = get-or-create（S3） |

真相与背景的归档对称：**Conversation 归档真相（Turn，含失败），
Context 归档背景（记忆层，仅成功）**——两种归档，互不越界。

## 8. 背景与记忆

### 7.1 Context：背景引擎三行为

| 行为 | 时机 | 内容 |
|---|---|---|
| 组装 `assemble` | 模型调用前 | 按策略装配叙事背景（每次新鲜，非创建时一次性） |
| 归档 `on_turn_completed` | 轮完成后 | L1 写入（成功轮）+ 主题更新 |
| 压缩（同上内含） | 保底/策略触发时 | L1→L2 摘要（ContextManagement 事件可见）、L2→L3 蒸馏 |

- **取材唯记忆**：`AssemblyRequest { memory, subject, conversation_id,
  topic, input }`——策略读会话实体在**类型上不可表达**（0015 类型
  锁死）；
- 装配格式（不变）：`[System 人格] [System: Memory recall] [L2 摘要]
  [L1 窗口] [User 本轮输入]`——L3 注入为独立 System 消息（人格与
  记忆可辨识）；
- 压缩 LLM 句柄以参数传入（现状 = 该 agent 的模型；后台专用模型
  见推迟表）。

### 7.2 触发体系（不变）

| 流转 | 强制保底（确定性资源约束） | 可叠加（事件驱动） |
|---|---|---|
| L1→L2 | TurnCount(n) | TopicShift / ConversationEnd / 自定义 |
| L2→L3 | L2Overflow(n) | ConversationEnd / Demotion / Retrieval / Periodic / TopicShift / 自定义 |

- 保底不可移除、只能叠加；非确定性事件永不成为框架强加默认；
- 默认检测器 FirstSegmentDetector：首轮建立主题、此后恒不判定
  shift（文档化语义）——TopicShift 需注册自定义检测器激活；
- ConversationEnd：显式 `conv.end()`（发起方在控）+ `sweep_stale`
  空闲兜底（不依赖会话句柄存活）。

### 7.3 记忆流失败不得静默（0015 立法 / 0016 机制）

装配三层读取、L1 写入、主题更新、压缩——任何失败以**事件**可见
（LifecycleEvent 新增 non_exhaustive 变体），不再 `unwrap_or_default`
静默降级为"无记忆"。机制经观察者派发器同样流向观察者。

## 9. 可观测性：双面分工

| 面 | 载体 | 消费者 | 内容 |
|---|---|---|---|
| 产品叙事面 | `ExecutionEvent` 流 | 用户 / 界面渲染 | 文本增量、工具卡片、状态流转、终态结果 |
| 工程观测面 | Observer 旁路 | 独立服务 / exporter | 全量 `AgentEvent`（含 Requested 装配载荷、Responded 快照） |

### 8.1 观察者派发器（ADR-0016）

```
AgentLoopTask（执行热路径，永不等待观测）
  emit! ──┬─ ① 消费通道 → Execution 叙事流
          └─ ② try_send → 有界观测队列（满→丢弃+计数，O(1) 永不阻塞）
                              │
             ObserverDispatcher（每 run 一个后台投递任务）
               按序取出 → catch_unwind → 逐观察者（panic→本次 run 熔断）
               收尾：通道关闭后清空队列才退出（终态事件不丢）
               追上时 on_lagged(ctx, dropped) 显式告知丢弃
```

- 通道内有序（单观察者派发器 FIFO = 发射序）；与叙事流跨通道时序不承诺；
- 开关默认关（独立服务承接）；`ObserverContext.execution_id` 解决并发
  run 归属；
- 录制：`AgentEvent` 已 serde——录制型观察者直接序列化落盘。

## 10. 横切语义

### 9.1 取消与超时

四入口一信号（ADR-0004）：cancel() / drop RAII / with_timeout /
run_with(token) → `CancelReason::UserRequested | Timeout`
（Parent 为 S3 预留）。agent 级 `default_timeout`（显式 opt-in）
+ per-run `with_timeout` 覆盖。

### 9.2 错误分诊

| 层级 | 形态 | 行为 |
|---|---|---|
| 工具级（软失败） | `ToolError` / `ToolResult::Err` | 喂回模型，run 继续 |
| run 级（硬失败） | `AgentError` | Failed 事件；await Err；入史（outcome=Failed） |
| 取消 | `AgentError::Cancelled` | Cancelled 事件；非失败；入史（outcome=Cancelled） |
| 记忆流失败 | Lifecycle 新变体事件 | **不中断 run、不再静默**；可见（0015/0016） |
| 装配失败 | Failed（InvalidConfiguration） | 硬失败（既有可见路径，维持） |

### 9.3 序列化

`AgentEvent` / `Turn` / `ConversationState` 全 serde——录制回放、
真相迁移、确定性测试三大用途共享同一形状。

## 11. 扩展点与插件化（四兄弟契约）

| 契约 | 职责 | 注册 | 缺省 |
|---|---|---|---|
| ConversationStore | 会话真相存取 | RuntimeBuilder | 进程内 |
| MemoryStore | 三层记忆存取与检索 | RuntimeBuilder | 进程内 |
| ContextAssembly | 组装策略（只决定"发什么"） | RuntimeBuilder | LayeredMemory |
| **Observer** | 全量事件旁路观测（0016） | RuntimeBuilder | **无（默认关闭）** |

统一模式：业务实体不耦合插件；**编排在框架，存取/决策在实现侧**。
工具另有 `#[derive(Tool)]` 类型化壳（动态核心 + 编译期糖，MCP 运行时
schema 硬约束驱动）。

## 14. 边界与未来

- **S3（多 Agent 编排）**：维持后置，无时间表；预留面已标注触发
  条件（`CancelReason::Parent` / `CallPurpose::Classification` /
  `SubjectType::Agent`）；fork 完整设计（新 id + 记忆分叉）随 S3
  分支场景回归；
- **后台工作专用模型**（Runtime 注册，承担压缩/摘要/主题检测预算）：
  **已触发**（压缩预算护栏暂缺），0.2.0 后优先落地；
- **刻意不做**（无触发不引入）：组装策略覆灭入口、事件过滤/采样
  配置、动态观察者注销、会话级事件类别（0011 决策 9 维持）、
  无场景驱动的模式层抽象；
- **纯回放配置**（LayeredMemory L1 全窗 + L3 预算 0）：用户真实
  需求出现再表达。
