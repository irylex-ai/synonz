## 1. 总览

0.9.0 修复"持久化存储 + 正常重启"下维护不发生的问题：维护边界从
进程内状态改为 **L1 存储契约承载的持久化压实游标**，批次改为跨重启
权威的待压实集合；蒸馏增加**批次年龄门槛**（沉淀窗口，默认 1 天）；
维护按会话串行，崩溃窗口采用**至少一次**语义。框架零改动。

**范围**
- L1 契约：`uncompacted(scope)` / `mark_compacted(scope, through)`
  （必选，破坏性）+ 内置默认实现；
- 组件：删除进程内计数、触发缓存初始化、批次上限、按会话 busy、
  成功后推进；
- 蒸馏：W1′ 年龄门槛 + 沉淀窗口配置（默认 1 天，0 可显式退化）；
- 文档与迁移：组件 README、扩展指南、v8、CHANGELOG、0.8→0.9 迁移。

**非目标**
- 不改框架生命周期（不加 resume 钩子/事件）；
- 不引入第二个游标（滞后蒸馏边界）、不做跨存储恰好一次、不做启动期
  全量扫描；
- 不修 `touched` 持久化与管理编辑/在途压实的既有竞态（见 §5）。

## 2. 决策基线（ADR-0031）

- 游标与轮次日志同处 L1 存储；批次 = `uncompacted(scope)`；
- 压实总是执行；蒸馏仅当批次最早轮次达到沉淀窗口；主题切换/会话
  终结不受窗口约束；
- 游标仅在 L2 写成功后推进；蒸馏失败只上报 `Failed`；
- 同会话 busy 串行（运行中跳过、下轮重试）；单次至多 `l1_turns`
  条、逐段排空；崩溃/部分写入窗口为至少一次。

## 3. 里程碑明细

### M48 L1 契约与默认实现

- `L1MemoryStore` 增加 `uncompacted` / `mark_compacted`（必选，文档
  写明幂等语义与游标单调性）；
- `InProcessL1MemoryStore` 实现：每 scope 一个游标位置（内存），
  `uncompacted`=游标之后的轮次，`mark_compacted`=按 id 定位并推进；
- 契约文档说明持久化实现的职责（游标随日志持久化，需覆盖淘汰边界）；
- 单测：游标初始为空、幂等推进、未知 id no-op、淘汰后行为。

### M49 组件维护重写

- `L2Memory` 删除 `uncompacted` 计数与 `note_turn` 相关记账；
- 触发缓存：每进程每会话首次归档时以 `uncompacted(scope)` 初始化
  （一次读），之后逐轮本地自增；重启后首次触发即含积压；
- `spawn_task`：是否触发用缓存；批次 = `uncompacted(scope)`；单次
  截取至多 `l1_turns` 条；成功后 `mark_compacted(末条 id)`；
- 按会话 busy 守卫：任务运行期间跳过触发，下轮重试；
- `finalize`：批次 = `uncompacted(scope)`；压缩成功后推进；蒸馏
  （终结路径）不受窗口约束；
- 蒸馏守卫（W1′）：仅压实路径启用——批次最早轮次 ≥ 沉淀窗口才蒸馏；
- 配置：新增沉淀窗口字段（`l3_` 前缀、秒为单位、默认 86 400，
  文档写明 0 = 压实即蒸馏）；
- 失败语义：压缩失败不推进；蒸馏失败上报 `Failed`、不阻止推进。

### M50 测试、文档与发布准备

- 重启模拟：共享持久的测试 L1 存储（游标跨 provider 重建保留）；
  验证积压补做、批次正确、正常路径无重复；
- 崩溃窗口：模拟 L2 部分写入失败 → 游标不推进 → 重试（断言记录的
  重复语义）；
- 并发：同会话并发触发被串行化（一次运行、其余跳过并下轮重试）；
- 时间窗：默认 1 天（新鲜批次只压实）；达龄批次蒸馏；显式 0 退化
  为压实即蒸馏；主题切换/终结不受窗口影响；
- 默认实现回归：既有 280 用例不变；
- 文档：组件 README、扩展指南（可恢复维护、沉淀窗口、迁移）、v8
  （实施记录/里程碑）、CHANGELOG 0.9.0、0.8→0.9 迁移说明；
- 验证：fmt / clippy 0 / doc 0 / 全量测试 / 离线示例；
- 发布准备：版本 bump、dry-run、发布说明草稿（发布仍需人工确认）。

## 4. 兼容与迁移

- **破坏项（0.9.0）**：`L1MemoryStore` 新增两个必选方法。自定义持久化
  存储必须在快照/清单中持久化每会话游标（与既有 append 同一 fsync
  批次），并实现"游标之后的轮次"查询。
- 内置默认实现行为不变（内存游标，数据本就不跨进程）。
- 消费方（Valkyrie）：L1 存储增加游标字段与两个方法；配置沉淀窗口
  （建议 3 天；默认 1 天）。
- 框架：零改动。

## 5. 风险与开放项

- **至少一次**：崩溃/部分写入窗口内的重试可能重复 L2 条目或版本
  抖动；文档写明，`Failed` 事实可见；
- **默认行为变化**：沉淀窗口默认 1 天 → 活跃会话中未满一天的批次
  只压实不蒸馏，L3 按沉淀节奏滞后（预期效果，写入 release notes）；
- **`touched`**：仍为进程内尽力而为，重启后上一进程的终结向量修复
  不再执行（正常写入向量不受影响）；
- **管理编辑与在途压实竞态**：压实的 `existing` 快照可能覆盖刚完成
  的编辑（既有问题，另行决策）；
- **长期未打开的会话**：积压在该会话下次使用或终结时处理，不做启动
  扫描；
- **批次上限的排空节奏**：积压较大时每次触发处理一段，完全排空需要
  若干轮（可接受；如需一次性排空另行决策）。

## 6. 验收

- 重启模拟通过：跨进程批次正确、积压补做、正常路径无重复；
- 崩溃/并发用例通过且行为与文档一致；
- 时间窗行为符合默认 1 天与显式 0 的语义；主题/终结不受影响；
- 全量回归（280 + 新增）、clippy/doc 零警告、fmt 干净、离线示例
  实跑通过；
- 自定义持久化存储通过契约一致性用例。
