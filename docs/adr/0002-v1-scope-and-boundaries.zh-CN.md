# ADR-0002: v1 范围与系统边界

- 状态: APPROVED（2026-08-28，irylex 人工评审通过）
- 日期: 2026-08-28
- 决策者: irylex（人类确认）

## Context（背景）

ADR-0001 确立了"全部覆盖"的终态愿景（单 agent → 多 agent 编排）与
渐进增长纪律。项目路径选择了"先做架构设计，再写代码"。v1 需要一个
锚定场景（anchor scenario）作为架构的压力测试点——第一个必须做到
完美的场景。

候选场景盘点：

| 候选 | 内容 | 主要服务谁 |
|---|---|---|
| S1 单 agent 循环 | LLM + tools 的推理-行动-观察循环 | 所有用户的入口 |
| S2 有状态会话 | 多轮对话、会话状态、记忆 | 应用开发者 |
| S3 多 agent 编排 | 协作、任务分发、通信 | 平台/进阶用户 |
| S4 可嵌入基础设施 | 作为库嵌入、事件外露、可控运行时 | 平台/基建团队 |

## Problem（问题）

v1 的范围是什么？哪些能力进、哪些能力后置？provider 与工具生态的
边界在哪？

## Decision（决策）

### 锚定场景：S1 单 agent 循环

v1 把"LLM + tools 的单 agent 循环"做到完善：取消语义、事件流、
行为透明全部在这个场景上验证。理由：

- S1 是原子单元，S2/S3 都是它的组合，S1 做不好上层全是空中楼阁；
- S1 恰好是四支柱压力最大的地方——agent 循环正是取消语义、事件流、
  行为透明集中受考验的执行路径；
- S1 同时服务两类目标用户（应用开发者直接用，平台团队嵌入）。

### 系统形态：纯库

v1 = 库（core + adapter crates + 可运行 examples）。CLI、独立运行时
服务、服务端形态全部后置（S3/S4 范畴）。

### Provider 集：OpenAI 兼容 + Anthropic

- OpenAI 兼容协议覆盖面最广（含 vLLM、llama.cpp server 等本地服务）；
- Anthropic 能力结构与 OpenAI 差异大，足以压测 Model 抽象的普适性；
- 目的不是功能覆盖率，是**用两个结构不同的 provider 验证抽象**。

### Tool 范围：进程内工具 + MCP 桥接

v1 同时包含：

1. 进程内 Tool（用户以 Rust 代码实现 Tool trait，直接函数调用）；
2. MCP 桥接（adapter crate，把 MCP server 暴露的工具桥接为 Tool 实现）。

MCP 进 v1 的理由（人类决策）：MCP 生态已有大量现成工具，能给 v1 更
实用的开箱体验。此决策直接塑造了 Tool trait 的形态（见 ADR-0005：
核心 trait 必须动态化）。

### 明确后置的能力

- S2：有状态会话、记忆、Context 概念提升；
- S3：多 agent 编排、agent 间通信、模式层抽象；
- S4：服务化/嵌入形态的专门支持；
- 多模态内容块（Image 等）、重试策略 utility、embeddings。

后置决策在各相关 ADR 的 Consequences 中追踪，场景启动时升级为
独立 ADR。

## Alternatives Considered（备选方案）

### 锚定场景

- **S1 + S2 联合锚定**（无状态循环实用价值有限）：被否决——取消与
  事件语义应先在无状态场景收敛，会话状态引入第二批语义变量会稀释
  v1 的验证焦点。
- **S3 多 agent 优先**（差异化在编排层）：被否决——组合先于原子是
  次序错误，单 agent 核心未验证就编排多个，问题无法定位。

### Provider 集

- **仅 OpenAI 兼容**（快速验证）：被否决——单一 provider 无法验证
  抽象普适性，canonical 消息形态（ADR-0006）会变成单家 API 的复述。
- **三家及以上**（如加 Ollama 原生协议）：被否决——本地开发体验的
  收益抵不过 v1 维护面变宽；OpenAI 兼容已覆盖多数本地推理服务。

### Tool 范围

- **MCP 后置**（架构师原推荐：核心契约验证后再建桥）：被人类否决——
  MCP 生态的现成工具对 v1 实用价值更高。架构后果已被吸收：Tool trait
  从第一天起就按动态契约设计（ADR-0005）。

## Consequences（后果）

### 正面

- v1 焦点集中，四支柱在单一场景上完成端到端验证；
- 双 provider 从第一天证明翻译层隔离（ADR-0006）可行；
- MCP 桥接让 v1 具备真实生产力，不只是一部件。

### 成本与义务

- MCP 进 v1 强制 Tool 核心 trait 动态化（dyn 兼容、Value 参数），
  类型安全须由 derive 层恢复（ADR-0005）；
- 两个 provider 的翻译层是持续维护面，provider API 演进需跟进；
- v1 不含 S2/S3/S4，用户若有相应需求须自行组合或等待。

### 风险

- MCP 协议本身仍在演进，桥接层可能需要跟随调整；
- 锚定单场景可能遗漏跨场景需求——以"后置决策追踪"机制缓解。

### 关联

- 依赖 ADR-0001（四支柱与渐进纪律）；
- 被 ADR-0005（MCP 塑造 Tool 契约）、ADR-0006（双 provider 验证翻译层）、
  ADR-0008（crate 划分）引用。
