# ADR-0009: 插件化扩展架构——原则

- 状态: APPROVED（2026-08-28，irylex 人工评审通过）
- 日期: 2026-08-28
- 决策者: irylex（人类确认）
- 性质: 原则性 ADR——固化原则与治理框架；机制决策显式挂起（见
  Consequences），不做机制设计，不预定义契约清单

## Context（背景）

生态愿景：**契约稳定（范式不变）× 插件实现多样 × 组合自由**——框架的
"无限可能"来自三者相乘。目标场景四个：开发者扩展、终端用户装插件、
团队模块解耦、插件生态市场。

现有基础：v1 已有 2 个契约（`Model` / `Tool`，ADR-0005/0006）经 1 个
场景（S1）验证；适配层已有 4 个"官方插件"crate（synonz-openai /
synonz-anthropic / synonz-mcp / synonz-derive）。

讨论中确立的认知：

- 三角色模型：契约在原语层定义、插件在适配层实现、组合层消费插件；
- 能力维度与执行语义的插拔边界；
- 绑定形态（编译期/进程外/运行时加载）与契约模型正交。

同时确认的缺口——以下机制决策**现在无法做出**（依赖 S2+ 场景证据，
提前设计即投机抽象）：

| # | 缺口 | 依赖 |
|---|---|---|
| G3 | 循环 Hook 点（插件如何参与执行循环） | S2 context/memory 真实用例 |
| G4 | 契约粒度（Memory 是一个契约还是多个） | S2 |
| G5 | 跨插件状态与数据流 | S2 状态架构 |
| G6 | 契约版本与兼容策略 | semver 政策制定 |

## Problem（问题）

框架的扩展性如何在不落入"一切皆可插拔"陷阱（万能接口 = 过度抽象，
P1 反面）的前提下，以统一模型支撑生态演化？能力何时晋升为契约——
治理标准缺失则契约集合膨胀，公共 API 失守。

## Decision（决策）

### 原则一：三角色模型

```
┌─ 模式层    插件组合的"配方"（用哪些插件、怎么配）      ┐
│ 组合层    Agent 等：消费插件，把插件组装成成品          │ 消费者
│ 原语层    契约集合：Model / Tool /（随场景晋升的新契约） │ 定义者 ★
│ 适配层    插件的实现形态（官方与第三方 crate）           │ 实现者
└──────────────────────────────────────────────────────┘
```

"插件化架构"= 原语层的契约集合 + 适配层的实现形态；组合层是消费者，
不是插件机制本身。

### 原则二：能力维度可插拔，执行语义不可插拔

- **可插拔**：能力维度——模型、工具、记忆（S2）、上下文处理（S2）、
  将来的存储、观测后端等；
- **不可插拔**：执行语义——Agent 循环、事件类型的封闭性（ADR-0003）、
  核心生命周期语义（ADR-0004/0007）。重申 ADR-0007 对可插拔
  Executor 的否决；
- **生态承诺**：适配一个契约，永远不会碰到执行语义变更。

自定义执行引擎仍可行（原语公开，ADR-0007），但那是"自建"，不是
"插件"。

### 原则三：契约随场景晋升

契约不提前设计。每个新契约由真实场景触发：Memory/Context 契约随 S2
（有状态会话）晋升；运行时动态加载机制随终端用户插件场景（S3/S4）
评估。本原则是 ADR-0001"最小核心 + 渐进增长"在契约治理上的应用。

### 原则四：契约晋升标准

一个能力晋升为契约（进入原语层的公开 trait）须**同时**满足：

| # | 标准 | 反例（不晋升） |
|---|---|---|
| ① | **场景驱动**：至少一个真实场景需要该能力作为可替换维度 | "未来可能要" |
| ② | **实现多样性**：可预见至少两种实质不同的实现（如记忆：进程内 / 持久化 / 向量库） | 只有一种合理写法 |
| ③ | **消费点明确**：组合层有确定的消费位置（谁、在哪里调用它） | 定义了没人调用 |
| ④ | **无泄漏**：契约可定义而不泄漏任何实现/provider 概念（`Model` trait 不含 OpenAI 概念的同款纪律） | 契约里出现特定后端字段 |
| ⑤ | **演进算术已想清**：`#[non_exhaustive]` 增长路径明确（`ToolContext` 先例） | 加字段即破坏下游 |

**降级信号**：只有一个实现且看不到第二个的"契约"= 可能过早抽象，
重新评估是否回退为实现细节。

### 原则五：绑定形态正交（方向性）

| 绑定形态 | 说明 | 时序 |
|---|---|---|
| 编译期（Rust crate） | 实现契约的 crate 经 Cargo 组合 | v1 ✅ |
| 进程外（协议） | MCP 即 `Tool` 契约的进程外绑定 | v1 ✅（工具维度） |
| 运行时动态加载 | 加载宿主实现同一契约，框架视角 = 又一个适配器；需 ABI/安全/生命周期整套机制 | 真实场景出现时评估 |

契约模型不因绑定形态改变——这是生态演进的稳定性保证。

## Alternatives Considered（备选方案）

### 本 ADR 的定位

- **完整机制 ADR（含 Hook 点、粒度、状态流、版本策略）**：相当于替
  S2 的场景做设计，违背原则三（契约随场景晋升）——被自身原则否定。
  讨论中确认推迟到 S2 证据充分。被否决。
- **不立 ADR，仅补进架构设计文档**：原则级别的架构决策（插拔边界、
  晋升标准）应有 append-only 的决策记录；设计文档是推导物。被否决。

### 插件化范围

- **字面"全插件化"（一切皆可运行时替换，含循环与事件类型）**：万能
  接口 = 过度抽象（P1 反面）；与 ADR-0003（封闭事件集合）、ADR-0007
  （拒绝可插拔 Executor）正面冲突。被否决。

## Consequences（后果）

### 正面

- 生态心智模型稳定：适配者面向契约编程，不接触执行语义；
- 契约治理有标准可依（五标准 + 降级信号），防止契约集合投机膨胀；
- 三角色模型与既有 ADR 完全兼容（v1 的 Model/Tool 即首批契约，
  适配层 crate 即首批官方插件）；
- 绑定形态正交为终端用户插件/生态市场预留了不破坏契约的演进通道。

### 成本与义务

- 每个新契约的引入须走一遍晋升标准（评审检查项）；
- 挂起项（G3-G6）须在对应场景启动时兑现为决策，不得无限期搁置；
- "生态承诺"约束执行语义层的演进自由——语义变更需新 ADR 并视为
  对生态的破坏性事件。

### 风险

- 晋升标准执行过严可能延迟确实需要的契约——以降级信号机制反向
  平衡（可回退）；
- 标准执行过松的防线是评审（标准为检查清单，人为评审把关）。

### 挂起项与触发条件（显式记录）

| 挂起项 | 触发场景 | 兑现形式 |
|---|---|---|
| G3 循环 Hook 点 | S2（context/memory 用例） | 独立 ADR |
| G4 契约粒度 | S2 | 契约设计 ADR 内决策 |
| G5 跨插件状态/数据流 | S2 状态架构 | 独立 ADR |
| G6 契约版本与兼容 | semver 政策制定 | 与兼容性政策 ADR 联动 |

### 关联

- 依赖 ADR-0001（P1/渐进增长）、ADR-0003（事件封闭性）、
  ADR-0007（执行语义边界）；
- 首批契约实例：ADR-0005（Tool）、ADR-0006（Model）；
  插件实现形态见 ADR-0008（适配层）。
