# ADR-0026: 分层记忆组件——按《上下文记忆系统全链路技术方案》重定

- 状态: APPROVED（2026-09-20，irylex 人工评审通过）
- 日期: 2026-09-20
- 决策者: irylex（逐点确认；遵循 `.opencode/rules/architecture.md` §5–§9
  的渐进决策流程）
- 性质: 组件设计 ADR（官方分层记忆组件）——**取代 ADR-0024 的模型部分**
  （三层单元模型 / 身份与 `unit_key` / 时间片流与主题不变式 / 写侧
  契约 / 富管理面），**承接其边界纪律**（组件归属与公开面、读 / 消费
  分离、不丢数据、存储端口在组件、真实后端 + 进程内默认、embedding
  组件侧、观察面归属）
- 关联: 引用 ADR-0022/0023/0025（核心契约族、读通道、默认实现、
  作用域寻址）；**设计基线 = 《上下文记忆系统全链路技术方案》**；
  ADR-0024 已转 SUPERSEDED（由本 ADR 取代）
- 版本承载: 0.7.0
- 前提: 无旧数据迁移；scope 的获取属应用层（框架不规定）；观察事件
  清单与命名、L2 缓存 / 持久化拆分等属实现细节，随文记录

## Context（背景）

ADR-0024 以框架旧的 in-process 记忆实现为蓝本定义了组件模型（L2
时间片摘要段、L3 知识单元按键集合、`unit_key` 身份、主题不变式）。
但实际设计基线是《上下文记忆系统全链路技术方案》——一套服务端上下文
记忆系统的设计：其**分层模型**（L1/L2/L3）为框架所借鉴，其**实现
逻辑与算法**是组件要落地的目标。两者在 L1/L2/L3 的单元语义、写侧
流程、读侧管线上均不一致，故本 ADR 按文档重定组件模型。

本 ADR 取代 ADR-0024 的模型部分；其边界纪律承接：组件归属与公开面、
读 / 消费分离、不丢数据、存储端口在组件、真实后端 + 进程内默认、
embedding 组件侧、观察面归组件。

## Problem（问题）

1. **层次模型不符**：文档 L1 = 双轨原始消息（10 轮、会话级）；L2 =
   事件摘要（LLM 判断更新 / 创建、≤5 事件、content 数组）；L3 = 实体
   关系图谱 + 向量（锚点先行多跳、归一化、隔离）——与 ADR-0024 的
   "回合队列 / 时间片摘要段 / 知识单元键集"不同；
2. **管线映射缺失**：文档四阶段（前置 / 召回评分 / 改写 / 保存与
   异步写）需要落到核心契约（rewriter / `detect_topic` / assembler /
   `archive_turn` / `spawn_task` / `finalize_conversation`）；
3. **端口、策略、观察面、管理映射与 scope 处理**需要按文档定形。

## Decision（决策）

### 1. 层次模型（按文档）

- **L1 工作记忆**：原始对话消息（user / agent **双轨分存**）；最近
  10 轮 FIFO；会话级、不随主题切换清空；写入 = `archive_turn` 钩子
  （仅成功轮）；
- **L2 事件摘要**：以**事件**为单元——`event_id` / `event`（≤30 字
  核心摘要）/ `event_vector` / `last_update_time` / `content`（历史
  摘要数组 ≤5 条、时间倒序）；每会话 ≤5 事件；**LLM 判断更新 / 创建**；
  **仅 user_track**；写入 = `spawn_task` 后台；会话隔离；
- **L3 长期记忆（跨会话）**：**实体关系图谱 + 实体向量**——实体
  （`canonical_name` / `aliases` / `entity_type`）+ 三元组
  （`subject` / `relation` / `object`）；类型 Schema（PERSON / PRODUCT /
  BRAND / LOCATION / PREFERENCE / TOPIC / EVENT / OTHER）与关系 Schema
  （LIKES / DISLIKES / OWNS / WANTS / BELONGS_TO / RELATED_TO）约束；
  **alias 合并**（embedding 候选 + LLM 判断）；写入由**主题切换 /
  会话结束**触发（异步）；来源仅 user_track 摘要；**锚点先行 + 1–2 跳
  链路扩展**召回；**冷启动门槛**（L1 + L2 为空时 L3 不参与）；
- **范围**：L1 / L2 = **会话级**（不跨会话）；**L3 = 跨会话**（用户级 /
  项目级等分区由 scope 表达）；
- **双轨**：user_track（记忆，加权 ×1.2）/ agent_track（上下文，仅
  L1，×1.0）。

### 2. 管线映射（四阶段 → 核心契约）

- **阶段 1 指代消解** → 核心 `TurnInputRewriter`（组件经
  `RewriterProvider` 提供；`history` 由核心从真相域提供，ADR-0025 §7）；
- **阶段 1 主题切换检测** → 核心 `detect_topic` 钩子（组件策略：
  embedding 相似度 / 轮次 / 信息熵；核心写回 topic 并发事实）；
- **阶段 2 三层召回 + 统一评分 + 去重 + 冷启动** →
  `LayeredMemoryContextAssembler`（读组件端口）：评分 = 语义 0.5 +
  时间衰减 0.3 + 重要性 0.2，乘双轨加权与意图 source boost；去重 =
  content_hash + 向量相似度；Top-N（默认 5）；冷启动门槛剔除 L3；
- **阶段 3 上下文改写** → assembler 内（叙述 LLM，ADR-0025 §1）；
  产物 = **完整消息帧**（ADR-0025 §2；文档实现 = `[user(增强输入)]`）；
- **阶段 4 保存 + 异步写** → `archive_turn`（L1 双轨）+
  `spawn_task`（L2 事件更新；主题切换时结构化摘要（summary +
  key_facts + importance + topic_tag）→ 持久化；实体提取 → 归一化 →
  图谱 + 向量）+ `finalize_conversation`（会话结束批量同步）。

### 3. 存储端口（四端口）

- **L1 消息 / L2 事件 / L3 图 / L3 向量** 四端口（按数据对象）；
- 各端口**进程内默认实现**（离线 / 开发可用）+ **真实后端适配**
  （Redis / MongoDB / Neo4j / Milvus；可独立成包，ADR-0023 决策 4）；
- 端口内以 **scope 键 / 过滤**分区（scope 由数据携带）；
- L2 的缓存与持久化在同一端口实现内组合（可再分，实现细节）。

### 4. 策略与配置

- **语义环节策略化**：主题检测 / 事件判断 / 摘要 / 实体提取 /
  上下文改写（提示词随策略）；
- **参数集中配置**：容量（10 轮 / ≤5 事件 / content ≤5）、Top-N、
  阈值（相似度 / 锚点 / 去重）、权重（0.5 / 0.3 / 0.2、双轨 1.2 / 1.0、
  source boost）、`HOP_DECAY` 等；
- 评分 / 去重 / 归一化流程固定（参数可配）。

### 5. embedding（组件侧端口）

- 组件 provider 配置 embedding 实现（真实后端 / 进程内默认）；
  调用归组件观察面；核心零改动。

### 6. 观察面

- 组件 trait（provider 注入；可与 runtime observer 同对象双注册）；
- 进展事件：事件更新 / 摘要生成 / 图谱写入 / 归一化 / 跳过（+ scope
  + count；清单与命名随实现）；
- 失败经 `report_failure` → 核心 `Failed` 事实。

### 7. 管理映射

- **L2 事件 → `MemoryType::Summary` 条目**；**L3 实体 →
  `MemoryType::Knowledge` 条目**；
- 核心动词按 `(subject, scope)` 寻址（ADR-0025 §5）；
- 富面暴露文档类型（`EventSummary` / `Entity` / `Triple`）。

### 8. scope 与写入

- **不做内容路由**：数据自带 scope，按 scope 分组逐 scope 操作；
  隔离由 scope 键保证；
- scope 如何获得属**应用层**（框架不规定）；
- **scope 转换 = 边界**（后续经组件富面加性引入 `move` / `promote` /
  `demote`）。

### 9. 小项

- 无回合序号概念（队列语义足够；去重按 content_hash + 向量相似度，
  范围重叠去重如需由组件内部近似）；
- 主题切换的摘要与图谱更新走后台（写操作全量后置）；
- 轻量预判（极短输入 / 确认性回复跳过事件更新）与合并 LLM 调用属
  实现。

## Alternatives Considered（备选与否决）

1. **沿用 ADR-0024 旧模型**（时间片摘要段 / 知识单元键集）——否决：
   与实际设计基线不符；
2. **端口：三端口（L3 图 + 向量合一）**——否决：向量库与图库需各自
   可换；
3. **端口：单一整库**——否决：不可分层替换；
4. **扩展面：全环节策略化**——否决：接口面过大（评分 / 去重 / 归一化
   是确定性逻辑）；
5. **扩展面：仅端口 + 参数**——否决：LLM 语义环节无法按产品调优；
6. **观察面：事件通道**——否决：背压 / 丢失语义成本高、无需求；
7. **观察面：仅 tracing**——否决：无程序化订阅；
8. **写入 scope：内容路由 / 双写判断 / 应用配置**——否决：数据自带
   scope 即可，按 scope 分组操作（隔离天然保证）；
9. **管理映射：只 L3 / 最小实现**——否决：L2 与 L3 都是记忆条目
   （既有决策）；
10. **scope 转换现在做**——否决：无已验证需求（列边界）。

## Consequences（后果）

**破坏项（0.7.0）**

- 取代 ADR-0024 模型部分：`unit_key` / 主题不变式 / 时间片摘要段 /
  知识单元键集不再成立；L2 / L3 语义与写侧流程按文档重定；
- ADR-0024 待本 ADR 批准后转 SUPERSEDED（有效边界部分在本 ADR 承接）。

**加性项**

- 组件按文档的层次模型与四阶段管线；
- 四端口（L1 消息 / L2 事件 / L3 图 / L3 向量）；
- 语义环节策略 + 参数集中配置；embedding 端口；组件观察面；
- 富面文档类型（`EventSummary` / `Entity` / `Triple`）。

**边界（本 ADR 明确不做）**

- scope 转换（后续加性）；scope 获取机制（应用层）；
- 观察事件清单与命名、L2 缓存 / 持久化拆分（实现细节）；
- 策略覆盖主题、L1 参与管理、语义搜索 / 矛盾消解（既有边界保持）。

**文档义务**

- v8（组件章节、扩展点全景、管理面）；0.7.0 实施计划重排；
- CHANGELOG 与 API 适配说明；扩展指南（组件用法、策略与端口）。

**验证要求**

- L1 双轨（user / agent 分存、10 轮、不随主题清空）；
- L2 事件（LLM 判断更新 / 创建、≤5 事件、content ≤5、仅 user_track）；
- L3（锚点先行 + 多跳、类型 / 关系 Schema、alias 合并、隔离、冷启动
  门槛）；
- 四阶段管线（指代消解 → 召回评分 → 改写成帧 → 异步写入）；
- 评分 / 去重 / Top-N / 双轨加权；
- 管理映射（L2→Summary、L3→Knowledge；按 scope 列表 / 批量遗忘）；
- 观察面进展事件；失败经 `Failed` 可见。
