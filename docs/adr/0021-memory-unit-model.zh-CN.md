# ADR-0021: 记忆单元模型与策略槽写侧契约——主题不变式、L3 单元身份与 L2 分组压实（0.6.0 记忆面补正）

- 日期: 2026-09-19
- 决策者: irylex（人类评审；本 ADR 承接 2026-09-19 的"记忆单元模型"

- 性质: 记忆写入模型补正 + 公开契约破坏（`L3Identity` 构成、策略槽

## Context（背景）

0.6.0 发布了记忆管理面（ADR-0020）：条目获得稳定 id，应用可以
`list` / `get` / `edit` / `forget`，L3 以身份三元组 upsert（同身份替换
保 id）。管理面解决的是"**读与管**"，而"**写**"侧的模型缺口在随后
的实际产品开发（AI 原生 IDE 的项目记忆，"记忆单元/记忆点"诉求）中
暴露出来。

三处缺口（均已用代码核对）：

**缺口一：策略槽无法表达"一次产出多个知识单元"。**
`MemoryDistiller::distill` 只返回 `Vec<String>`（内容文本），引擎对
每个字符串盖同一身份 `(subject, conversation, topic)` 后逐一 upsert
（context.rs:733-741）；同身份替换意味着 **N 块只活最后一块**——
策略明明能产出多个单元，写回却互相覆盖，且 `Distilled { count }` 按
upsert 次数上报（报 N 实存 1）。默认 `MechanicalMemoryDistiller` 与
会话终结的机械促进同样逐块覆盖（runtime.rs:493-527）。该塌缩自
0.5.0 即存在，0.6.0 的管理面让它显形。

**缺口二：主题语义在层间不一致，且与"L3 跨会话"矛盾。**
- L2 的 `topic` 是"产生摘要时刻的会话话题"：话题切换刷写会把
  **跨主题的整段 L1**（旧话题回合 + 切换当轮）压成一条 L2 并盖
  **新话题**（context.rs:453-465、474-501、589-592）——一条记录的
  内容与其主题标签可以不一致；
- 蒸馏与促进只看"当前会话话题"（context.rs:733-741；runtime.rs:491，
  后者还丢弃了 `L2Entry.topic`）——批次跨主题时下游归属不可信；
- `L3Identity` 含 `conversation_id`，而 L3 的定位是
  "cross-conversation" 的长期知识（memory.rs:4-17）——同一知识单元
  在不同会话各立一条，永远无法原位演进。

**缺口三（管理面连带）：** `MemoryQuery` / `MemoryStoreQuery` 没有
topic 过滤（memory.rs:250-264、514-531）——"某个主题下的记忆"无法
列出，而单元模型的核心操作正是"按主题管理单元"。

**模型澄清（本轮讨论的结论，作为本 ADR 的语义基础）：**
每一层的每条记录都是**该层的记忆单元**；L1/L2 是**队列**（时间片
事件，顺序与消费语义），L3 是**按键集合**（知识单元会反复出现，需
要"同键原地更新、异键并存"）。conversation 对 L1/L2 是作用域，对
L3 只是溯源。

**前提与边界：** 0.6.0 发布后没有任何生产数据沉淀（本 ADR 讨论时
确认），因此本波不提供数据迁移——0.6.0 序列化数据不支持，迁移
文档只讲 API 适配；这使公开契约可以放开手脚修正。

## Problem（问题）

1. **策略输出无单元判别**：`Vec<String>` 无法表达"这是哪个单元"，
   引擎只能盖同一身份——同主题多单元无法并存（后写覆盖）；
2. **单元无法原位演进**：同一知识单元跨蒸馏、跨会话的更新被表达成
   "又写了一条/被覆盖"，id 不稳定（身份含会话时）或内容被覆盖
   （身份不含单元时）；
3. **主题不变式被破坏**：L2 记录的内容可以跨主题而标签取一端；蒸馏、
   促进的主题盖章取自"当前会话话题"而非内容——下游（召回过滤、
   管理分组、单元身份）全部不可信；
4. **L3 身份与跨会话语义矛盾**：`conversation_id` 在身份里，同一
   单元跨会话分身；
5. **主题寻址缺失**：管理面无法按主题列/忘；
6. **计数事实失真**：覆盖发生时 `Distilled` / `Promoted` 的 count
   仍报写次数。

## Decision（决策）

### 1. 术语与三层单元模型：记录统一、更新语义分层

- **记忆条目（entry）**：各层的记录（`L1Entry` / `L2Entry` /
  `L3Entry`）；每条记录即该层的一个**记忆单元（unit）**；
- **作用域（frame）**：单元所属的坐标——L1/L2 是
  `(conversation, topic)`，L3 是 `(subject, topic)`；
- **单元键（unit key）**：同一作用域内区分"是哪个单元"的稳定判别；
  **仅 L3 需要**（知识单元会反复出现）：同键 = 同一单元（原地更新、
  id 不变）；异键 = 不同单元（并存）；
- **更新语义分层**：L1/L2 是**队列**（追加、消费式迁移；id/位置即
  句柄，不需要语义键）；L3 是**按键集合**（按键寻址、原地更新、
  不排空；回收靠管理/遗忘）；
- **conversation 的角色**：L1/L2 是作用域；L3 是**溯源**（移入
  `source` 字段，见 §2）；
- L1 仍不参与管理面（ADR-0020 §9 保持）；"记忆点"是产品词汇，
  框架侧即"知识单元"。

| | L1 | L2 | L3 |
|---|---|---|---|
| 作用域 | conversation + topic | conversation + topic | **subject + topic** |
| 单元 | 回合 | 摘要段（时间片） | 知识单元 |
| 单元键 | 无 | 无 | **有** |
| 集合形态 | 有界队列 | 队列 | **按键集合** |
| 更新语义 | 追加、最老弹出 | 追加、按 id 认领 | **同键原地更新** |
| conversation | 作用域 | 作用域 | **溯源（source）** |

### 2. L3 身份与条目：`(subject, topic, unit_key)` + `source`

- `L3Identity` 字段改为 **`subject_id` + `topic` + `unit_key`**
  （移除 `conversation_id`）；
- `L3Entry` 增加 **`source: MemorySource`**（复用既有公开类型；记录
  **最近一次写入**的来源会话与该次写入的主题）；
- `upsert` 语义不变：**同身份替换、保留原 id**（`updated_at` 刷新、
  `source` 更新为最近写入者）；不同 `unit_key` 并存；
- **框架不解释键的语义**：`unit_key` 是不透明判别，策略负责其稳定性
  （同一单元跨蒸馏、跨会话给出同一个键）；**空键 = 主题默认槽**
  （退化为"一主题一单元"，供简单策略使用）；
- 管理面：`MemoryItem`（L3）的 `source` 取自 `entry.source`；新增
  **`unit_key: Option<String>`**（`Summary` 为 `None`，`Knowledge`
  为 `Some`）供列表展示（标题即键）；
- 依据：L3 是跨会话知识——会话属于溯源、不属于身份；同主题多单元
  必须有一维判别，否则回到覆盖语义（ADR-0020 §6 的粒度修正）。

### 3. L2：时间片流 + 主题不变式（分组压实）

- L2 保持队列（追加、按 id 认领移除）；**不加单元键**——摘要段是
  时间片事件，"同一段"不会再次出现，标识由 id + topic 已足够；
  知识单元的合并/更新归 L3（§1/§2）；
- **压实按主题切分（主题不变式）**：引擎把待压实的 L1 批按
  `L1Entry.topic` 的**连续段**分组，每组一次
  `MemorySummarizer::summarize`（**契约保持"一批 L1 → 一段文本"**，
  分组是引擎的确定性行为，不依赖模型），每组产出一条 L2 条目并盖
  **组主题**；
- **话题切换刷写只压当前话题之外的段**：切换当轮保留在 L1 窗口，
  不再并入旧话题摘要；
- **`L2Entry.topic` 语义改为"内容所属主题"**（被摘要回合的主题），
  不再是"产生时刻的会话话题"；
- 降级路径（总结失败 → 原文兜底）仍按组执行、盖组主题；
- 依据：一个 L1 窗口可以含多个主题（探测器未报切换、或默认探测器
  不切换）；记录的内容与主题必须一致，否则下游（蒸馏分组、促进、
  召回过滤、管理分组）全部不可信；L2 合并会丢失时段结构并与 L3
  职责重叠（见 Alternatives）。

### 4. 写侧契约：策略输出记忆单元草案

- `MemoryDistiller::distill` 输出从 `Vec<String>` 改为
  **`Vec<MemoryDistilledUnit>`**；`MemoryDistilledUnit` 为公开输出类型
  （`new(unit_key, content)`，`non_exhaustive`），字段
  **`unit_key: String`** 与 **`content: String`**；
- **引擎分组**：把本批来源 L2（L2 队列中超限的最老前缀）按
  `L2Entry.topic` **归组**（同主题合并，允许非连续），**每组一次
  `distill` 调用**，参数 `topic` = 组主题；
- **引擎盖章**：`L3Identity { subject_id, topic: 组主题, unit_key:
  draft.unit_key }`、`L3Entry.source { conversation_id, topic: 组主题 }`、
  id 与时间；策略不接触身份、时间、溯源；
- **读 / 消费严格分离**：
  - **读**：策略经 `reader` 可读任意层（L1/L2/L3），只读不动；
  - **消费**：只消费"本组来源"——**逐组**"变换 → 按 id 重校验该组
    来源 → 认领（按 id 移除）→ 写入"；某组失败只保该组来源、其余组
    继续，失败经 `FlowFailed` 可见（无损降级纪律，ADR-0020 §13
    的组内形式）；
- **机械默认蒸馏**（`MechanicalMemoryDistiller`）：每条来源块产出一个
  草案，**`unit_key = 来源块 id`**（确定性、无模型调用）——N 块 N 条，
  不再塌缩，计数真实；
- **会话终结促进**：同形——每条 L2 块一条 L3 单元，
  **`unit_key = block.id`**、`topic = block.topic`（修正现状丢弃块主题
  的缺陷）；
- **对账走既有检索面**：策略用
  `reader.l3_query(源内容, 组主题, budget)` 检索既有单元（内置实现
  按主题命中 + 新鲜度排序；向量库按相似度），据此复用键或提新键；
  **不新增枚举方法**——键的复用质量属策略质量（同 ADR-0020 §6
  "错误覆盖归策略质量"），完备枚举留待真实需求出现时以加性方式补。
- 同批内重复键 = 后写生效（策略质量，可观测）。

### 5. 管理面与存储寻址加项

- `MemoryStoreQuery` / `MemoryQuery` 增加 **`topic` 过滤**（`Option<
  Topic>`）：按主题列出 / 批量遗忘——"主题记忆管理"的寻址基础；
- `MemoryItem.unit_key`（§2）；
- 契约义务：`MemoryL3Store::list` 的实现需支持 topic 过滤
  （自定义存储按 API 适配说明更新）。

### 6. 主题来源与归一职责（边界）

- 主题仍由**会话侧**（`ConversationTopicDetector`）产生、**引擎盖章**；
  策略**不可覆盖** topic（本波）；
- 跨会话主题归一（同一领域在不同会话给出稳定标签）是**探测器 /
  策略职责**；策略经 `l3_query` 检索既有单元作为对账材料；
- 若后续真实需求证明"策略覆盖 topic"必要，以**加性**方式引入
  （输出草案加可选 topic），不纳入本波。

### 附：小项

- `Distilled { count }` / `Promoted { count }` 的语义明确为**成功写入
  的单元数**；
- 数据兼容：移除 0.6.0 为旧数据保留的 `serde` 兜底（`id` /
  `updated_at` 缺省回退）——0.6.0 序列化数据不支持，缺失字段应直接
  失败而非静默补造；
- `L2Entry.index`（恒为 0、无消费者）移除；
- `L3Entry` 构造入口随之调整（`source` 由引擎盖章；实现细节）。

## Alternatives Considered（备选与否决）

**身份与单元**

1. **点在主题里**（把单元编码为细分主题，如"登录/启动方式"）——否决：
   主题是 L1/L2/L3 共享的会话级字段（压实触发、召回过滤、管理分组），
   点级路径会让 L2 与 L3 的主题语义分裂、召回匹配需要新的层级语义；
   且策略输出仍必须携带判别（只是改名为 topic），问题原样存在；
2. **L2 主题记忆**（一个 `(conversation, topic)` 一条、合并式更新）——
   否决：L2 是时间片事件流，合并会丢失时段结构、装配顺序被迫变为
   `updated_at`，`summarize` 契约变为"旧单元 + 新回合 → 新内容"，
   并与 L3 的单元合并职责重叠；
3. **L2 加语义单元键（不合并，仅标识）**——否决：时间片不会"再次
   出现"，标识由 id + topic 已足够，键无消费方；
4. **L1 加 id / 身份并参与管理**——否决：L1 是原始材料（ADR-0020 §9），
   编辑 L1 = 改历史；L1 留存/清理是已记录的独立边界项，届时再立项；
5. **id 化写回**（策略输出"新建（键+内容）/ 修改（既有 id + 内容）"）——
   否决：把去重/合并责任完全推给策略且指向可能失效（id 不在草案
  契约里）；身份键 + 单元键已覆盖"同单元更新、异单元并存"；
6. **conversation 保留在 L3 身份**——否决：与"跨会话知识"语义矛盾，
   同一单元跨会话分身，无法原位演进；
7. **身份 = `(subject, topic)`（一主题一单元）**——否决：同主题多个
   知识单元无法并存（本波要解决的核心诉求）。

**写侧契约**

8. **保留单主题盖章 + 多块输出**（现状修正版：输出多条文本但仍盖
   同一身份）——否决：同主题多单元仍互相覆盖；
9. **输出 `{topic, key, content}`（策略可覆盖 topic）**——本波否决
   （边界）：主题归引擎，跨会话归一属探测器职责；未来如需求成立
   以加性方式引入；
10. **一次 `distill` 调用处理整批（跨主题）**——否决：主题归属需要
    策略输出 topic 或引擎猜测；分组调用让主题归属确定、提示词聚焦，
    且与按组传主题的 `l3_query` 对账自然匹配；
11. **终结促进保持无键覆盖**——否决：仍会塌缩；机械键（块 id）无
    模型成本且不塌缩。

**主题不变式**

12. **维持切换刷写整段**（内容跨主题、标签取新话题）——否决：违反
    主题不变式，L2 记录内容与标签不一致，下游归属不可信；
13. **切换时重标旧段**（修改既有 L2 记录的主题）——否决：改历史、
    审计语义混乱；按连续段分组压实已足够且不改既有记录；
14. **L2 保留"产生时刻话题"语义**——否决：与分组压实后的事实不符，
    且管理面按主题过滤会错配。

**管理面**

15. **不暴露 `unit_key`**——否决：产品侧"列出单元（标题 + 内容）"
    需要键作标题；`Option` 加性、不影响 `Summary`；
16. **不加 topic 过滤**——否决：单元模型的核心寻址是"按主题管理"，
    没有过滤就无法列出/批量遗忘一个主题；
17. **新增 reader 枚举方法（`l3_units` / `l3_list`）**——本轮否决
    （加性后续）：唯一调用者是策略侧对账，而 `l3_query` 已覆盖检索式
    对账（内置实现按主题命中）；有界枚举的完备性也不完全，等真实
    需求出现再以加性方式补，公开面保持最小。

## Consequences（后果）

**破坏项（0.7.0 单波）**

- `L3Identity` 构成变化：`conversation_id` → `unit_key`（公开类型，
  所有构造点、策略与测试随之改）；
- `L3Entry` 增加 `source`（`non_exhaustive` 加字段；构造入口调整）；
- `MemoryDistiller::distill` 输出类型 `Vec<String>` →
  `Vec<MemoryDistilledUnit>`（所有自定义蒸馏策略必须适配）；
- `MemoryL3Store::upsert` 的身份语义随 `L3Identity` 变化；自定义 L3
  存储的身份索引键按新身份重建；
- L2 压实行为与 `L2Entry.topic` 语义变化：分组压实、切换刷写只压
  旧话题段（观察行为变化）；
- 机械促进不再覆盖：每块一条、`topic = block.topic`；
- 数据兼容：0.6.0 序列化数据不支持（无迁移）；移除旧 `serde` 兜底；
- `L2Entry.index` 移除。

**加性项**

- `MemoryQuery` / `MemoryStoreQuery.topic` 过滤；
- `MemoryItem.unit_key: Option<String>`；
- 公开类型 `MemoryDistilledUnit`（策略槽签名）。

**边界（本 ADR 明确不做）**

- 策略覆盖 topic（跨会话归一的策略侧改写）——归探测器/策略职责，
  未来可加性；
- L2 主题记忆（合并式更新）——L2 保持时间片流；
- L1 加 id / 参与管理（L1 留存与会话级清理另行立项）；
- 语义搜索、跨单元矛盾消解、事实聚合——策略层能力（ADR-0020 §5
  边界保持）；
- 数据迁移工具与数据迁移章（无旧数据）。

**文档义务**

- v8 架构文档（记忆单元模型、策略槽写侧契约、管理面寻址；v7 转
  SUPERSEDED）；
- 0.7.0 实施计划；
- 扩展指南更新：distiller 单元草案与键复用配方（`l3_query` 对账）、
  探测器主题稳定要求、分组压实说明；
- CHANGELOG（破坏项 + API 适配说明）；README 指针更新（v8 + 计划）；
- API 适配说明（短篇，替代迁移指南）：自定义 distiller（输出类型）、
  自定义 L3 存储（身份构成、`list` 的 topic 过滤）、探测器（主题
  稳定建议）；数据兼容边界声明。

**验证要求**

- **多单元并存**：一次蒸馏多块 → 多个 L3 单元（不同键）并存，不
  再塌缩；`Distilled { count }` 与实际写入单元数一致；
- **同单元原位演进**：同键跨批次、跨会话（同 subject/topic）写入
  → 同一条、id 不变、`updated_at` 刷新、`source` 更新为最近写入者；
- **L2 主题不变式**：含多主题的 L1 批 → 多条 L2 单元、各盖组主题；
  切换刷写不把切换当轮并入旧话题摘要；`L2Entry.topic` = 内容主题；
- **促进**：按 `block.topic` 盖章、每块一条、计数真实；
- **读/消费分离**：策略读 L1/L2/L3 不改变任何层；仅本组来源被按 id
  认领；来源在途变化 → 丢弃该组产物并可见（确定性竞态测试）；
- **管理面**：按 topic 列出 / 批量遗忘；`MemoryItem.unit_key` 对
  `Knowledge` 可见、对 `Summary` 为 `None`；
- **存储契约**：内置 L2/L3 实现通过新身份与 topic 过滤回归；
- **公开面**：策略无法构造/覆盖身份、时间、溯源（编译期检查）。
