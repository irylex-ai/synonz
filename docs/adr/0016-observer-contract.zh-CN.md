# ADR-0016: Observer 可观测契约——旁路事件派发

- 状态: APPROVED（2026-09-07，irylex 人工评审通过）
- 日期: 2026-09-07
- 决策者: irylex（人类确认）
- 性质: 新增公开扩展契约（非破坏）——可观测性从消费面解耦为旁路
  订阅；与 ADR-0014、ADR-0015 同发 0.2.0

## Context（背景）

事件流是框架的可观测性底座（ADR-0003）：两级事件模型、可序列化、
终态不变量。其承载方式经历了三段演变：

1. ADR-0003 时代：双层 API（ask/run），"事件流是唯一信息通道"，
   观测由 `run` 消费面承载；
2. ADR-0014：单一执行面收敛，旧 `Run` 废弃——观测失去消费面承载；
3. ADR-0014/0015 讨论确立核心原则：**观测是执行的旁路属性，不能
   绑定在任何消费面上**——LLM 是概率的，无法用第二次执行观测第一次，
   观测必须与执行同时发生，且**绝不拖慢执行**（irylex 硬要求）。

ADR-0015 提供了两个前提：会话必选 + Agent 持有 Runtime → **全量
run 可达 Runtime 注册表**；并立法"**记忆流失败不得静默**"，机制
留给本 ADR 承接。

需求（AGENTS.md §16 可观测性 + 社区扩展）：OTel exporter、会话
录制、metrics、调试 tracer 等由下游开发者以插件形式接入。

## Problem（问题）

1. 单一执行面之后，全量事件（含输入侧装配载荷）没有任何入口——
   调试"Agent 为什么看到了文件 X"、录制回放、生产审计无承载；
2. 观测投递不能阻塞执行热路径——需要非阻塞架构；
3. 观察者故障不得影响执行；
4. 并发 run 的事件归属需要执行标识；
5. 慢观察者导致的丢弃需要显式可见，不能静默；
6. 记忆流失败的可见性机制（0015 决策六的机制承接）。

## Decision（决策）

### 一、Observer 契约：同步回调

```rust
pub trait Observer: Send + Sync + 'static {
    /// 每个事件投递一次（全量 AgentEvent，含输入侧载荷）。
    /// 实现必须快速返回——重活（批量、网络导出）自行内部排队。
    fn on_event(&self, ctx: &EventContext, event: &AgentEvent);

    /// 观测队列溢出发生丢弃后，派发器追上时调用一次，
    /// `dropped` 为本次 run 累计丢弃数。默认空实现；
    /// 关注数据完整性的录制型观察者必须覆写。
    fn on_lagged(&self, ctx: &EventContext, dropped: u64) {}
}
```

- **同步签名**：`dyn` 兼容零障碍（`async fn` + `dyn` 至今未稳定，
  需宏或手写 BoxFuture）；重活自管队列/工作线程是成熟模式
  （tracing 的 `Layer::on_event` 同款）；
- **非阻塞契约写入 trait 文档**：实现快速返回是义务，不是建议。

### 二、派发器架构：同步回调、异步投递

```
AgentLoopTask（执行热路径，永不等待观测）
  emit! ──┬─ ① 消费通道 → Execution 叙事流（不变）
          └─ ② try_send → 有界观测队列（固定容量；满→丢弃+计数，
                                          O(1) 永不阻塞）
                              │
             Dispatcher（每 run 一个后台任务，tokio::spawn）
               按序取出 → catch_unwind → 逐个调用已启用观察者
```

- 热路径成本 = 一次 `try_send`——"同步回调的里面是异步执行"：
  回调签名同步（`dyn` 兼容），投递在独立任务，执行方永不等待；
- **通道内有序**：观测通道内部严格保持发射序（单派发器 FIFO）；
  与叙事流的跨通道时序不承诺同步；
- **收尾保证**：执行结束、通道关闭后，派发器**清空队列才退出**——
  终态事件绝不因观察者存在而截断丢失；
- 观察者看到的是**全量 `AgentEvent`**（含 `Requested` 装配消息、
  `Responded` 快照）——工程观测面；产品叙事面（`ExecutionEvent`）
  是它的对偶，两者职责互补（0014 确立）。

### 三、注册：Runtime 注册表 + Agent 开关

```rust
RuntimeBuilder::observer(impl Observer + 'static)   // 注册表（对齐
                                                    // memory 注册模式）
AgentBuilder::observability(bool)                    // 默认 false
```

- 开关语义：`false` = 零派发零开销；`true` 且注册表非空 → 该
  agent 的每次 run 启动派发器。可观测通常由独立服务/进程承接，
  因此**不默认开启**（irylex 判断）；
- Agent 经自身持有的 runtime（ADR-0015）读取注册表——**全量 run
  覆盖，无边界例外**（0015 已消灭无会话 run）。

### 四、执行标识：EventContext 信封

```rust
#[non_exhaustive]
pub struct EventContext {
    /// 进程内自增的执行标识（每次 run 分配）。
    pub execution_id: u64,
}
```

- 信封参数，**不侵入 `AgentEvent`**（serde 形状不变，录制格式
  稳定）；
- u64 进程内自增（零新依赖）；跨进程聚合是 exporter 自己的事务
  （如 OTel 的 trace id 生成）。

### 五、故障隔离

- 每次投递 `catch_unwind`：观察者 panic → **该观察者本次 run 内
  熔断**（不再被调用），执行与派发器均不受影响；
- 框架当前无日志栈（AGENTS.md §16 推迟选型）——panic 的记录钩子
  随观测栈选型落地，当前仅熔断（诚实标注：可见性有限，机制后置）。

### 六、丢弃可见性：on_lagged

- 队列满 → 丢弃事件 + 累计计数；派发器追上进度时以
  `on_lagged(ctx, dropped)` 显式告知——**丢弃不是静默的**
  （0015 "失败不得静默"立法的观测域延伸）。

### 七、记忆流失败的可见性机制（承接 0015 决策六）

- 记忆流（归档/压缩）失败以**事件**进入事件流：`LifecycleEvent`
  新增变体（`#[non_exhaustive]`，字段为阶段标识 + 详情，具体形状
  实施时定）——失败经派发器同样流向观察者，与"装配失败走既有
  Failed 硬失败路径"（已可见）分工明确；
- 由此 0015 的静默回退消单（装配三层吞错、压缩全文转写、
  soft_errors 无终点）获得统一的可见性出口。

### 八、不做的事

- 不提供框架侧过滤/采样配置——观察什么、怎么筛，观察者自决；
- 不引入日志/tracing 依赖——栈选型另行决策（AGENTS.md §16）；
- 不做动态注册/注销——观察者随 Runtime 构建期注册；
- 不改 `AgentEvent` 的 serde 形状——执行标识走信封。

## Alternatives Considered（备选方案）

| 备选 | 否决理由 |
|---|---|
| `async fn` 观察者 | `dyn` + async 未稳定（需宏/BoxFuture）；循环驱动复杂度：阻塞执行或每事件 spawn |
| broadcast channel 订阅 | 契约感弱（"订阅通道"≠"实现契约"）；动态注册管理复杂；需事件 Clone 语义 |
| 发射点内联同步调用 | 慢观察者阻塞热路径——违反"观测绝不影响执行"（irylex 硬要求） |
| 框架侧缓冲 + 背压配置族 | 配置爆炸（0012 已否决 enable 配置族）；固定有界 + 丢弃 + on_lagged 已覆盖 |
| 无 on_lagged（静默丢弃） | 违反 0015 "失败不得静默"立法的延伸 |
| 无执行标识 | 并发 run 的事件无法归属，录制/审计不可用 |
| 侵入 AgentEvent 加 id 字段 | 破坏 serde 形状与录制格式；信封参数零侵入 |
| 观测继续由 run 消费面承载 | 消费面已被 0014 收敛；概率性禁止重执行观测——旁路是唯一正解 |

## Consequences（后果）

### 正面

- 工程观测（调试、录制、回放、审计、成本分析）有了正式的社区
  扩展点——框架承诺的可观测支柱从"消费面兼差"变为独立契约；
- 执行热路径零影响（`try_send` O(1)，永不阻塞）；
- 与 0014 单一执行面互补：**叙事面（ExecutionEvent，产品消费）+
  观测面（Observer 旁路，工程扩展）**职责清晰；
- 0015 "记忆流失败不得静默"获得机制出口；
- 公开面增量最小：一个 trait + 一个信封结构 + 一个注册方法 +
  一个开关。

### 成本与义务

- 0.2.0 新增公开契约；`LifecycleEvent` 新增变体（non_exhaustive
  演进）；
- 无日志栈期间观察者 panic 的可见性有限（熔断即处理，记录钩子
  后置）——诚实标注；
- 派发器为每 run 一个后台任务：实现含注册表扩展、开关与 spawn
  管道、有界队列、收尾清空语义，测试覆盖投递顺序 / 丢弃计数 /
  熔断 / 收尾不丢终态；
- 实施顺序 **0014 → 0015 → 0016**，同发 0.2.0。

### 关联

- 前置 ADR-0014（执行面收敛——观测从消费面解耦的前提）；
- 前置 ADR-0015（Agent 持 Runtime = 注册表全量可达；记忆流失败
  立法 = 本文机制承接）；
- 修订 ADR-0003 的"事件流是唯一信息通道"论证（旁路扩展，0003
  已补注）。
