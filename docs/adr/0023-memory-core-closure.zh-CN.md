# ADR-0023: 记忆核心契约收口——条目级读通道、进程内默认实现、失败事实与扩展轴归属

- 状态: APPROVED（2026-09-20，irylex 人工评审通过）
- 日期: 2026-09-20
- 决策者: irylex（逐点确认；遵循 `.opencode/rules/architecture.md` §5–§9
  的渐进决策流程）
- 性质: 核心契约补充与细化 + 公开面破坏（读通道语义、事件词汇、默认
  能力）；随 0.7.0 单波承载
- 关联: **补充/细化 ADR-0022**（§5 读通道的接口形态、§7 失败事实的
  事件形态、§9 默认能力、§1/§2 边界的核心侧表述）；不改写 ADR-0022
- 版本承载: 0.7.0（"0.6.0 记忆面补正"；无数据迁移）
- 前提: 无旧数据迁移——0.6.0 序列化数据不支持；本 ADR 只做**核心侧
  收口**——分层类型与存储契约的去向、组件内部形态、条目视图与单元
  语义均不在本 ADR（组件 ADR）；装配机制（构建器形态）属实现细节

## Context（背景）

ADR-0022 批准了记忆子系统的组件边界与核心契约族（三抽象 + 两工厂），
并明确：分层机制归官方组件、核心只持契约与内置引擎。批准后仍留有
四处**核心侧未竟项**，它们都落在 ADR-0022 已批准的决策面之内：

1. **读通道的接口形态**：§5 定了 `reader` 是 `Memory` 的只读代理并
   放入载荷，但未定代理暴露什么；当时核心公开的 `MemoryReader` 暴露
   的是分层原语（`l1_window` / `l2_read` / `l3_query`），依赖分层
   类型；
2. **默认能力**：§9 定了 `runtime.memory()` 与"Runtime 在 build 时从
   provider 取得"，但未定未配置 provider 时的语义——0.6.0 核心自带
   默认记忆，组件拆分后"默认那套"必须重新表态；
3. **失败事实的事件形态**：§7 定了 `MemoryFailure { stage: String,
   detail: String }` 与"核心转成统一失败事实"，但未定该事实的变体
   形态与旧词汇（`MemoryFlowStage` / `MemoryFlowFailedMoment`）的
   处置；
4. **扩展轴的归属**：模型（业务/语义）与存储（持久化）两个可扩展
   面，其扩展点各在哪一层未定。

本 ADR 逐项收口，不引入新的架构方向。

## Problem（问题）

- 读通道若保留分层原语，核心公开面将长期驻留分层词汇，与 ADR-0022
  "分层机制归组件"的边界自相矛盾；
- 未配置 provider 若语义为空缺，裸 agent 会失去基本会话上下文（今天
  模型可见的最近回合窗口由记忆 L1 承载），无法真实多轮运行；
- 事件词汇若不做收口，`FlowFailed` / `MemoryFlowFailedMoment` 等
  "flow" 术语在 `MemoryFlowStage` / `MemoryFlowError` 移除后成为孤儿，
  且分层机制事件（`Compacted` / `Distilled` / `Promoted`）由谁发出
  不明；
- 扩展轴若不表态，模型与存储的扩展点可能被混为一谈。

## Decision（决策）

### 1. 读通道：`reader` = `Memory` 的条目级只读投影

- 载荷中的 `reader` 是 `Memory`（条目级管理抽象）的**只读投影**：
  只暴露条目级读取（`list` / `get` / 条目查询），不暴露分层读原语；
- 核心公开面**不含分层读词汇**：`MemoryReader` 的分层读方法
  （`l1_window` / `l2_read` / `l3_query`）与 `L1Entry` / `L2Entry` /
  `L3Entry` / `L3Identity` / `MemoryStoreQuery` 等不再出现在核心公开面
  （其去向属组件 ADR）；
- 各实现的 assembler / pipeline 读取自身状态由实现内部自持；
- 依据：分层机制归组件（ADR-0022 §1/§2）；条目级代理与核心管理抽象
  同源，边界自洽。

### 2. 默认能力：核心提供进程内默认 provider（非分层）

- 核心在 `inprocess.rs` 提供**一套默认 `MemoryProvider`**（进程内、
  非分层：默认 memory + assembler + pipeline），即"进程内默认记忆
  模型"；
- **未配置 provider 时使用该默认**；应用配置 provider 即替换（模型轴
  扩展）；`runtime.memory()` 恒可用（保持 ADR-0022 §9 形态）；
- 默认实现与分层模型无关；分层机制（L1/L2/L3、压实/蒸馏/促进）仍归
  官方组件；
- 装配机制（构建器形态）属实现细节，不在本 ADR。

### 3. 事实面：统一失败事实与核心词汇表

- **核心 `MemoryEvent` 词汇**：`TurnArchived`、`Updated`、`Removed`、
  `Failed { stage: String, detail: String, moment }`；
- **统一失败事实**：读侧（assembler / rewriter）与写侧（pipeline
  模板、钩子、后台任务）失败统一走 `Failed`；`stage` 为字符串（核心
  不解释实现方阶段）；`moment` 保留（枚举随改名，如
  `MemoryFailedMoment`；命名细节）；
- **分层机制进展不在核心词汇**：`Compacted` / `Distilled` /
  `Promoted` 移出核心——后台分层进展的观测归组件观察面（ADR-0022
  后果）；核心只发核心可知的事实（归档、管理动作、失败）；
- `TopicShifted` 仍在 `ConversationEvent`（topic 状态在核心）。

### 4. 扩展轴：模型 = provider；存储 = 组件侧

- **模型轴（业务/语义扩展）**：扩展单位是 `MemoryProvider`——怎么记、
  怎么维护、怎么召回由实现决定；
- **存储轴（持久化扩展）**：扩展点定义在**组件侧**（各实现族按自己
  的数据结构定义存储端口，如分层组件的 L1/L2/L3 存储；持久化实现
  可独立成包）；核心**不定义 store 契约**；
- 依据：存储接口必须贴合数据结构才有复用价值；通用契约要么过薄
  （blob）要么过厚（分层结构入核心）；当前持久化需求落在分层模型。

## Alternatives Considered（备选与否决）

**读通道**

1. **核心保留分层读契约**（`MemoryReader` 继续暴露 `l1_window` /
   `l2_read` / `l3_query`，分层读类型留核心）——否决：核心公开面
   长期驻留分层词汇，与 ADR-0022 §1/§2 边界冲突；
2. **核心不提供读通道**（撤销 §5 载荷 `reader` 与 §6"数据读取"）——
   否决：修订已拍板内容；实现者需自备读通道，表达力不统一。

**默认能力**

3. **可选空缺**（未配置 = 读无背景、写不运行）——否决：裸 agent
   失去基本会话上下文，无法真实多轮运行；
4. **必需显式配置**（未配置 = 构建错误）——否决：不需要记忆的 agent
   也被迫装配；且失去与 0.6.0 一致的默认体验。

**事实面**

5. **核心保留全部分层机制事件**（组件经上下文回报进展、模板统一
   发出）——否决：核心不应持有分层机制词汇，观测归属与 ADR-0022
   后果冲突；
6. **保留 `FlowFailed` 名**——否决：flow 词汇已随 `MemoryFlowStage` /
   `MemoryFlowError` 退役，成为孤儿术语；
7. **`PipelineFailed`**——否决：该事实统一承载读+写两侧失败，按写侧
   命名偏窄；最终取 `Failed`。

**扩展轴**

8. **核心通用存储契约（模型 × 存储正交）**——否决：契约须同时覆盖
   分层特化查询与默认模型，过薄或过厚；无当前需求（§2）；
9. **核心仅为默认模型定义 store**——否决：默认模型"进程内"即其
   定义；无已验证需求。

## Consequences（后果）

**破坏项（0.7.0 单波）**

- 核心公开面移除分层读方法、分层读类型与分层机制事件；
- `reader` 语义收窄为条目级只读投影；
- `MemoryEvent::FlowFailed` → `Failed`（变体改名）；`moment` 枚举
  改名；
- 未配置 provider 的默认能力从"分层默认"变为"进程内默认模型"
  （能力与行为不同）。

**加性项**

- 核心进程内默认 provider（非分层）；
- 条目级只读读通道；
- 统一失败事实 `Failed { stage: String, detail: String, moment }`。

**边界（本 ADR 明确不做）**

- 分层类型与存储契约的去向、组件内部形态（组件 ADR）；
- 装配机制与构建器 setter 替代（实现细节 / 迁移说明）；
- 条目视图与单元语义（组件 ADR）。

**文档义务**

- v8 架构文档（v7 转 SUPERSEDED）；0.7.0 实施计划；迁移说明（API
  适配）；CHANGELOG。

**验证要求**

- 公开面（编译期）：核心公开面不含分层读方法与分层类型/机制事件；
- 默认能力：未配置 provider 时 agent 可多轮运行（默认实现承载基本
  会话上下文）；
- 失败事实：读/写两侧失败均以 `Failed` 上报，不静默；
- 扩展性：替换 provider 后记忆行为随之替换。
