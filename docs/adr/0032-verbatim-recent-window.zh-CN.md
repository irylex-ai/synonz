# ADR-0032: 逐字近期窗口——读相位帧的近期连续性通道

- 状态: APPROVED（2026-10-27，irylex 人工评审通过）
- 日期: 2026-10-27
- 决策者: irylex（逐项决策；遵循 `.opencode/rules/architecture.md` §3–§9
  的渐进决策流程）
- 性质: 读相位与公开配置 ADR——扩展 ADR-0025 §2（完整消息帧）与
  ADR-0026 §2（读相位实现）的帧构成；不改记忆分层、维护与写相位
- 关联: 上游消费反馈（Valkyrie 0.6.0：长编码会话的近期连续性）；与
  决策 #24（框架不做主动压缩）不冲突——本能力在组件内
- 版本承载: 0.10.0（核心输入纯增量、组件配置默认关闭，无迁移）

## Context（背景）

组件当前的读相位是**召回式再构造**：assembler 把最近 `l1_turns` 轮
L1、L2 条目、L3 实体统一评分、去重、取 `recall_top_n`（默认 5），
交给改写模型折叠为**一条用户消息**；模型可见帧 = 系统提示 + 这一条
消息（ADR-0025 §2 的完整帧契约；ADR-0026 §2 的"文档实现 =
`[user(增强输入)]`"）。L1 是**逐字存储的工作记忆与召回单元**
（ADR-0026 §1 / ADR-0028 §1），但在帧里只是候选池：近期轮次不会被
原样回放，可能被语义相近的 L2/L3 挤出，改写还会压缩细节。

长任务 coding 会话需要稳定的"近期进展"通道（跨轮决定、约束、结论），
纯召回无法保证。消费方（Valkyrie 0.6.0）提出"近期逐字 + 召回补充"
的共存假设，并明确不废弃召回、要求可配置、默认向后兼容。

框架的读相位输入是 `MemoryContextAssembleInput`（`#[non_exhaustive]`，
文档明确"材料域对增长开放：未来的感知/运行期材料以新字段加入，不
破坏实现者"）；运行时的 `Context::assemble` 已经拿到最近成功轮的
真相消息（`user(原始输入) + assistant(最终回答)`），目前只供输入
改写器使用。

## Problem（问题）

帧必须同时承载两类材料：**近期连续**（最近若干轮逐字，稳定可见）与
**历史召回**（更早的 L1/L2/L3，按相关性）。当前只有后者；配置只能
偏向近期（`recall_top_n`、时间权重、`l1_turns`），不能保证逐字连续，
且改写会进一步压缩。需要一个可配置、默认关闭、与召回共存的逐字通道，
且不把实现语义塞进核心。

## Decision（决策）

### 1. 应用级全局配置，默认关闭

新增组件配置 `context_recent_turns`（默认 `0` = 现状；文档写明这些
最近轮次以**逐字**形式进入帧；下文 K 指该配置值）：

- **应用级全局**：帧构成模式属于该应用的"记忆形态"，由 provider
  构建时的配置决定；**不提供按会话/按任务类型的开关**。需要不同
  形态的应用组合不同的 provider/runtime。
- `K = 0` 时行为与 0.9.0 逐字节一致（不进入新路径）。
- **材料上界由注入的 `MemoryProvider` 声明**：`MemoryProvider` 增
  默认方法 `context_recent_turns()`（默认 20，非破坏），读相位按此
  数量从 Runtime 获取最近轮次；组件 provider 返回
  `min(context_recent_turns, l1_turns)`（K = 0 时返回 0，Runtime 不
  构建任何材料）。它不是 Runtime 配置，也不是隐藏常量。
- **生效窗口 = `min(K, l1_turns, 材料)`**；推荐包络
  **`K ≤ l1_turns`**；越界部分被夹取（不报错，文档写明）。

### 2. 核心：复用 `Turn`，以 `Arc` 共享最近轮次

`MemoryContextAssembleInput` 增加 `recent: &'a [Arc<Turn>]`——最近
成功轮（旧→新）的**共享真相记录**（`Turn` 已在核心公开面：input /
messages / outcome）：

- 结构为 `#[non_exhaustive]` 且文档预留字段增长，属**纯增量**；
  自定义 assembler 只需读取新字段（构造仍由框架经 `new` 完成）。
- **不新增读相位视图类型**（一概念一名）：沿用 `Turn`，通过 `Arc`
  共享避免深拷贝与跨 await 持锁。`Conversation` 内部改为存储
  `Vec<Arc<Turn>>`，公开 API（`turns()` / `state()` / 序列化）行为
  不变；读取最近轮次只克隆句柄、立即释放锁（`MutexGuard` 不跨
  await）。
- 运行时在构建时向注入的 `MemoryProvider` 取一次
  `context_recent_turns()`（默认 20），按此数量提供最近轮次的
  `Arc` 共享材料（`Arc` 使成本可忽略）；改写器继续使用同一批轮次的
  3 轮尾部（不重复计算）。
- 本版组件只读 `turn.input.text` 与 `turn.output().message`；将来
  工具转录直接使用 `turn.messages`（排除旧合成帧），核心零改动。
- 核心不解释"逐字/召回"的业务语义，只提供材料。

### 3. 组件帧构成（生效窗口 `K > 0` 时）

- **帧布局**：最近 K 轮成对消息（`user(原始输入)` / `assistant(最终
  回答)`）+ 末尾 `user(本轮输入 + 折叠补充)`；本轮输入必须在帧内
  （ADR-0025 §2 的契约义务）。
- **分工**：逐字 = 最近 K 轮；召回补充 = 其余 L1（K+1..`l1_turns`）
  + L2 + L3，沿用现有评分/去重/`recall_top_n`/改写。
- **去重**：按序排除最近 K 条 L1 候选（逐字窗口与 L1 的成功轮顺序
  一致）；不做额外语义过滤（默认流程下最近 K 轮尚未压实，摘要重叠
  概率低；backlog 场景的少量重叠记为已知边界）。
- **改写**：仅当补充非空时调用改写器；无补充时跳过（省一次模型调用），
  帧 = 逐字历史 + 原始输入。

### 4. 可观测：组件观察事件

`LayeredMemoryEvent` 增 `Assembled { scope, verbatim_turns,
recalled_l1, recalled_l2, recalled_l3, rewritten }`，每次组帧后经
组件观察面上报（未注册观察者则无开销）。失败仍以核心 `Failed` 事实
暴露，不变。

### 5. 范围边界

- **工具消息本轮不做**：逐字材料 = 用户输入 + 最终回答（与现有
  history 一致）。工具级连续（文件细节/命令输出）需要真相域完整
  转录视图，属后续、由真实数据驱动的独立决策；本 ADR 的输入口子
  为其预留。
- **上下文压缩（`/compact`）解耦**：窗口实现为"最近 K 轮**后缀**"，
  未来加入"每会话压缩起点 marker"即可变为"marker 之后的最近 K 轮"
  （同构扩展，不改帧布局与事件形态）；组件级压缩命令另立决策。

## Alternatives Considered（备选与否决）

1. **L1 作为窗口来源（零核心改动）**——对成对模式与真相源等价，但
   失去"规范消息 + 未来工具转录"的扩展基础；核心口子本就是为材料
   增长预留的，故采用核心 `recent`（复用 `Turn` + `Arc` 共享）。
2. **新增窄视图 `RecentTurn { input, answer }`**——材料最小，但多一个
   公开类型，且将来工具转录还要改核心契约；复用现有 `Turn` 更符合
   "一概念一名"（`Arc` 共享零深拷贝，公开 API 不变）。
3. **窗口 = 未压实轮次（绑定压实游标）**——自动压实（每 `l1_turns`
   轮）会周期性清空窗口，与连续性目标相反；否决。
4. **不排除召回（依赖现有去重）**——逐字前缀不参与候选去重，帧内
   可能重复同一轮；否决。
5. **召回按时间过滤（只取窗口之前）**——丢弃语义相关的旧知识；
   否决。
6. **核心 assembler 输出携带帧报告**——核心承载实现细节、且 `new`
   签名破坏性；否决（改用组件观察面）。
7. **应用自定义 assembler**——需重写召回评分/去重（assembler 未
   导出），等于要求私有知识；否决。
8. **同版做显式上下文压缩**——范围显著变大（组件 API、持久化 marker、
   契约扩展）；解耦，后续另立决策。

## Consequences（后果）

**加性项**

- 核心输入新增 `recent: &'a [Arc<Turn>]`（`#[non_exhaustive]`，
  非破坏；复用 `Turn`，无新公开类型）；`Conversation` 内部轮次存储
  改为 `Arc` 共享（公开 API 与序列化行为不变，读取最近轮次零深拷贝）；
- `MemoryProvider` 增默认方法 `context_recent_turns()`（默认 20，
  非破坏；内置默认 provider 覆写为 0，它不使用该材料）；
- 组件配置新增 `context_recent_turns`（默认 0，行为不变）；
- 组件观察面新增 `Assembled` 事件（非破坏）。

**行为项（K > 0）**

- 帧包含最近 K 轮逐字对 + 召回补充；最近 K 轮不再进入召回候选；
- 无补充时跳过改写（成本下降）；
- 前缀为 append-only 历史（跨轮稳定），比现状的单条折叠消息更利于
  prompt 缓存；尾部消息每轮变化；
- prompt 随 K 线性增长（有界，K ≤ 核心最近窗口）。

**已知边界**

- 工具结果/文件细节不进帧（本轮范围外）；
- 逐字材料是"输入 + 最终回答"，不是完整轮次；
- 生效窗口受 `min(K, l1_turns, provider 声明的材料上界)` 约束（内置
  默认 20；组件 provider 返回 `min(K, l1_turns)`）；
- backlog 压实场景可能与 L2 摘要少量重叠；
- 上下文压缩（`/compact`）与工具转录为后续能力。

## 验证要求

- `K = 0`：帧与 0.9.0 逐字节一致，既有全量用例不变；
- `K > 0`：帧布局正确（成对消息 + 末尾用户消息）、最近 K 轮不重复、
  其余 L1/L2/L3 正常补充、无补充时改写被跳过；
- 生效窗口夹取：`K > l1_turns` 或 `K > 材料` 时按
  `min(K, l1_turns, 材料)` 截断，推荐包络内行为正确；
- 材料来源：`MemoryProvider::context_recent_turns()` 的默认 20 与
  组件 provider 的 `min(K, l1_turns)` 均生效；K = 0 时不构建材料；
- 核心材料契约：`recent` 为 `Arc<Turn>` 共享（内容 = 最近成功轮、
  旧→新；读取不深拷贝工具消息）；`Conversation` 的 `turns()` /
  `state()` / 序列化行为不变；
- `Assembled` 事件字段准确（含 `verbatim_turns = 0` 的上报）；
- 核心输入纯增量：自定义 assembler 编译不受影响；
- 与重启恢复（ADR-0031）、冷启动门槛、压实/蒸馏互不影响；
- 观察者未注册时无额外行为。
