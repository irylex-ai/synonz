# ADR-0024: 分层记忆组件——单元模型、写侧契约与组件公开面

- 状态: APPROVED（2026-09-20，irylex 人工评审通过）
- 日期: 2026-09-20
- 决策者: irylex（逐点确认；遵循 `.opencode/rules/architecture.md` §5–§9
  的渐进决策流程）
- 性质: 组件设计 ADR（官方分层记忆组件）+ 跨边界核心公开面修订；
  随 0.7.0 单波承载
- 关联: **承接 ADR-0021**（已废弃草案的有效决策——单元模型、主题
  不变式、写侧契约在此重新承载）；**实现 ADR-0022 的组件侧**
  （`LayeredMemory` / `LayeredMemoryContextAssembler` /
  `LayeredMemoryPipeline`）；**引用 ADR-0023**（核心收口：条目级读
  通道、进程内默认实现、`Failed` 事实、存储轴归组件）；**修订
  ADR-0020 相应部分**（`MemoryType`、相位列表、`memory_type` 过滤
  移出核心）；细化 ADR-0012（三层模型保持）
- 版本承载: 0.7.0（"0.6.0 记忆面补正"；无数据迁移）
- 前提: 无旧数据迁移——0.6.0 序列化数据不支持；本 ADR 定组件的模型
  与公开面；provider 装配方式、观察面接口形态、组件包装属实现设计
  （不阻塞，记为后续）

## Context（背景）

ADR-0021 曾以"核心框架"的口径定义记忆单元模型与写侧契约，因分层
机制随后被划入官方组件（ADR-0022）而废弃；但其**决策内容依然有效**
——它们是组件（而非核心）的决策。ADR-0022/0023 完成了边界收口：
核心只持契约与内置引擎、条目级读通道与进程内默认模型；分层机制
（L1/L2/L3、压实、蒸馏、促进、策略、存储）全部归组件
`synonz-layered-memory`。

本 ADR 把 ADR-0021 的有效决策在组件边界内重新承载，补齐边界变化
带来的重表达（类型归属、读接口、观测、失败名），并决定组件的公开
管理面。

0.6.0 的三处缺口（写回塌缩、主题语义层间不一致、按主题寻址缺失）
已用代码核对，是本次组件设计的直接动因：

- `MemoryDistiller::distill -> Vec<String>` + 引擎逐条盖同一身份
  （`context.rs:733-741`）→ 一次蒸馏多块只活最后一块，`Distilled`
  计数按 upsert 次数上报（报 N 实存 1）；
- L2 的 `topic` 是"产生摘要时刻的会话话题"：切换刷写把跨主题的
  整段 L1（旧话题回合 + 切换当轮）压成一条并盖新话题
  （`context.rs:453-501、589-592`）；蒸馏与促进只看当前会话话题
  （`runtime.rs:493-527`，后者还丢弃了 `L2Entry.topic`）；
- `L3Identity` 含 `conversation_id`（`memory.rs:44-51`）→ 同一知识
  单元跨会话分身，无法原位演进。

## Problem（问题）

1. **策略输出无单元判别**：`Vec<String>` 无法表达"这是哪个单元"，
   引擎只能盖同一身份——同主题多单元无法并存（后写覆盖）；
2. **单元无法原位演进**：跨蒸馏、跨会话的更新被表达成"又写了一条/
   被覆盖"，id 不稳定（身份含会话时）或内容被覆盖（身份不含单元时）；
3. **主题不变式被破坏**：L2 记录内容可以跨主题而标签取一端；蒸馏、
   促进的主题盖章取自"当前会话话题"而非内容——下游（召回过滤、
   管理分组、单元身份）全部不可信；
4. **管理面缺按主题寻址**；
5. **边界重表达**：分层类型、策略契约、存储契约需要组件侧的归属
   与公开形态；
6. **核心视图最小化后的产品面**：按主题列出记忆点、键作标题、按
   类型查看，需要组件富管理面承载（ADR-0023 已把 `memory_type` /
   `unit_key` 移出核心）。

## Decision（决策）

### 1. 组件归属与公开面

- `synonz-layered-memory` 实现 ADR-0022 的三契约：`LayeredMemory`
  （`Memory`）、`LayeredMemoryContextAssembler`
  （`MemoryContextAssembler`）、`LayeredMemoryPipeline`
  （`MemoryPipeline`，四个业务钩子）；
- 组件公开面：分层条目类型（`L1Entry` / `L2Entry` / `L3Entry` /
  `L3Identity`）、策略契约（摘要 / 蒸馏 / 主题探测）、存储契约
  （L1/L2/L3 端口）、in-process 存储实现、富管理面、组件观察面、
  test-util；
- 存储扩展点定义在组件侧（ADR-0023 决策 4）：持久化 / 向量库等
  实现挂在组件的存储端口下，可独立成包；
- 核心公开面不含分层类型、策略契约与存储契约（ADR-0023）。

### 2. 三层单元模型：记录统一、更新语义分层（承接 ADR-0021 §1）

- **记忆条目（entry）**：各层的记录（`L1Entry` / `L2Entry` /
  `L3Entry`）；每条记录即该层的一个**记忆单元（unit）**；
- **作用域（frame）**：单元所属的坐标——L1/L2 是
  `(conversation, topic)`，L3 是 `(subject, topic)`；
- **单元键（unit key）**：同一作用域内区分"是哪个单元"的稳定判别；
  **仅 L3 需要**（知识单元会反复出现）：同键 = 同一单元（原地更新、
  id 不变）；异键 = 不同单元（并存）；
- **更新语义分层**：L1/L2 是**队列**（追加、消费式迁移；id/位置即
  句柄，不需要语义键）；L3 是**按键集合**（按键寻址、原地更新、
  不排空；回收靠管理 / 遗忘）；
- **conversation 的角色**：L1/L2 是作用域；L3 是**溯源**（移入
  `source` 字段，见 §3）；
- L1 不参与管理面（ADR-0020 §9 保持）；"记忆点"是产品词汇，框架
  侧即"知识单元"。

| | L1 | L2 | L3 |
|---|---|---|---|
| 作用域 | conversation + topic | conversation + topic | **subject + topic** |
| 单元 | 回合 | 摘要段（时间片） | 知识单元 |
| 单元键 | 无 | 无 | **有** |
| 集合形态 | 有界队列 | 队列 | **按键集合** |
| 更新语义 | 追加、最老弹出 | 追加、按 id 认领 | **同键原地更新** |
| conversation | 作用域 | 作用域 | **溯源（source）** |

### 3. L3 身份与条目：`(subject, topic, unit_key)` + `source`（承接 §2）

- `L3Identity` 字段为 **`subject_id` + `topic` + `unit_key`**（不含
  `conversation_id`）；
- `L3Entry` 增加 **`source: MemorySource`**（复用核心公开类型；记录
  **最近一次写入**的来源会话与该次写入的主题）；
- `upsert` 语义不变：**同身份替换、保留原 id**（`updated_at` 刷新、
  `source` 更新为最近写入者）；不同 `unit_key` 并存；
- **组件不解释键的语义**：`unit_key` 是不透明判别，策略负责其稳定
  性（同一单元跨蒸馏、跨会话给出同一个键）；**空键 = 主题默认槽**
  （退化为"一主题一单元"，供简单策略使用）；
- 依据：L3 是跨会话知识——会话属于溯源、不属于身份；同主题多单元
  必须有一维判别，否则回到覆盖语义（ADR-0020 §6 的粒度修正）。

### 4. L2：时间片流 + 主题不变式（分组压实）（承接 §3）

- L2 保持队列（追加、按 id 认领移除）；**不加单元键**——摘要段是
  时间片事件，"同一段"不会再次出现，标识由 id + topic 已足够；
  知识单元的合并 / 更新归 L3（§2/§3）；
- **压实按主题切分（主题不变式）**：引擎把待压实的 L1 批按
  `L1Entry.topic` 的**连续段**分组，每组一次
  `MemorySummarizer::summarize`（**契约保持"一批 L1 → 一段文本"**，
  分组是引擎的确定性行为，不依赖模型），每组产出一条 L2 条目并盖
  **组主题**；
- **话题切换刷写只压当前话题之外的段**：切换当轮保留在 L1 窗口，
  不再并入旧话题摘要；
- **`L2Entry.topic` 语义改为"内容所属主题"**（被摘要回合的主题），
  不再是"产生时刻的会话话题"；
- 降级路径（总结失败 → 原文兜底）仍按组执行、盖组主题；
- 依据：一个 L1 窗口可以含多个主题；记录的内容与主题必须一致，
  否则下游（蒸馏分组、促进、召回过滤、管理分组）全部不可信。

### 5. 写侧契约：策略输出记忆单元草案（承接 §4）

- `MemoryDistiller::distill` 输出从 `Vec<String>` 改为
  **`Vec<MemoryDistilledUnit>`**；`MemoryDistilledUnit` 为组件公开
  输出类型（`new(unit_key, content)`，`non_exhaustive`），字段
  **`unit_key: String`** 与 **`content: String`**；
- **引擎分组**：把本批来源 L2（L2 队列中超限的最老前缀）按
  `L2Entry.topic` **归组**（同主题合并，允许非连续），**每组一次
  `distill` 调用**，参数 `topic` = 组主题；
- **引擎盖章**：`L3Identity { subject_id, topic: 组主题, unit_key:
  draft.unit_key }`、`L3Entry.source { conversation_id, topic: 组主题 }`、
  id 与时间；策略不接触身份、时间、溯源；
- **读 / 消费严格分离**：
  - **读**：策略经组件内部读接口可读任意层（L1/L2/L3），只读不动；
  - **消费**：只消费"本组来源"——**逐组**"变换 → 按 id 重校验该组
    来源 → 认领（按 id 移除）→ 写入"；某组失败只保该组来源、其余组
    继续，失败经 `report_failure` 上报（核心 `Failed` 事实，
    ADR-0023）；
- **机械默认蒸馏**：每条来源块产出一个草案，**`unit_key = 来源块
  id`**（确定性、无模型调用）——N 块 N 条，不再塌缩，计数真实；
- **会话终结促进**：同形——每条 L2 块一条 L3 单元，
  **`unit_key = block.id`**、`topic = block.topic`（修正现状丢弃块
  主题的缺陷）；
- **对账走既有检索面**：策略用
  `l3_query(源内容, 组主题, budget)` 检索既有单元（内置实现按主题
  命中 + 新鲜度排序；向量库按相似度），据此复用键或提新键；
  **不新增枚举方法**——键的复用质量属策略质量，完备枚举留待真实
  需求出现时以加性方式补；
- 同批内重复键 = 后写生效（策略质量，可观测）。

### 6. 管理面：核心最小视图与组件富管理面

**核心最小视图（ADR-0023 收口 + 本 ADR 修订）**

- `MemoryItem` = `id` / `content` / `source { conversation_id, topic }`
  / `created_at` / `updated_at`；
- `MemoryQuery` = `conversation_id` / `topic` / `from` / `to` /
  `keyword` / `after` / `limit`；
- 核心列表**扁平**（新鲜度 + id keyset）；`MemoryType`、相位列表
  （`MemoryListCursor.memory_type`）、`memory_type` 过滤**移出核心**
  → **修订 ADR-0020 相应部分**；
- 依据：核心公开契约只含框架可解释、跨实现可担保的内容；
  `memory_type` / `unit_key` 是分层语义，核心默认（非分层）模型
  无法填充（ADR-0023）。

**组件富管理面**

- **单一富条目类型**：核心条目字段语义 + `memory_type: MemoryType`
  + `unit_key: Option<String>`（`Summary` 为 `None`，`Knowledge` 为
  `Some`）——供列表展示（标题即键）；
- **富查询**：核心过滤（conversation / topic / 时间 / 关键字）+
  `memory_type` / `unit_key` 过滤 + 分区列表（摘要段与知识单元）；
- **取用路径**：组件 provider 的富句柄（应用构造 provider 时自然
  持有）；`runtime.memory()` 仍给核心最小视图（ADR-0022 §9 不变，
  组件面为附加）；
- L1 不参与管理面（ADR-0020 §9 保持）。

### 7. 主题来源与归一职责（承接 §6）

- 主题仍由**会话侧**产生（组件实现核心 `detect_topic` 钩子，内部
  使用主题探测策略）、**引擎盖章**；策略**不可覆盖** topic（本波）；
- 跨会话主题归一（同一领域在不同会话给出稳定标签）是**探测器 /
  策略职责**；策略经 `l3_query` 检索既有单元作为对账材料；
- 若后续真实需求证明"策略覆盖 topic"必要，以**加性**方式引入
  （输出草案加可选 topic），不纳入本波。

### 8. 小项（承接附）

- 组件进展事件（分层观测，ADR-0022 后果 / ADR-0023）的 count 语义
  明确为**成功写入的单元数**；
- 数据兼容：移除 0.6.0 为旧数据保留的 `serde` 兜底（`id` /
  `updated_at` 缺省回退）——0.6.0 序列化数据不支持，缺失字段应直接
  失败而非静默补造；
- `L2Entry.index`（恒为 0、无消费者）移除；
- `L3Entry` 构造入口随 `source` 调整（实现细节）。

## Alternatives Considered（备选与否决）

**单元模型与身份**（承接 ADR-0021）

1. **点在主题里**（把单元编码为细分主题）——否决：主题是 L1/L2/L3
   共享的会话级字段（压实触发、召回过滤、管理分组），点级路径会让
   L2 与 L3 的主题语义分裂；策略输出仍必须携带判别，问题原样存在；
2. **L2 主题记忆**（一个 `(conversation, topic)` 一条、合并式更新）
   ——否决：L2 是时间片事件流，合并会丢失时段结构、装配顺序被迫
   变为 `updated_at`，并与 L3 的单元合并职责重叠；
3. **L2 加语义单元键**——否决：时间片不会"再次出现"，标识由 id +
   topic 已足够，键无消费方；
4. **L1 加 id / 身份并参与管理**——否决：L1 是原始材料，编辑 L1 =
   改历史；L1 留存/清理是已记录的独立边界项；
5. **id 化写回**（策略输出"新建/修改（既有 id）"）——否决：把去重/
   合并责任完全推给策略且指向可能失效；身份键 + 单元键已覆盖
   "同单元更新、异单元并存"；
6. **conversation 保留在 L3 身份**——否决：与"跨会话知识"语义矛盾，
   同一单元跨会话分身，无法原位演进；
7. **身份 = `(subject, topic)`（一主题一单元）**——否决：同主题多个
   知识单元无法并存（本波要解决的核心诉求）。

**写侧契约**（承接）

8. **保留单主题盖章 + 多块输出**——否决：同主题多单元仍互相覆盖；
9. **输出 `{topic, key, content}`（策略可覆盖 topic）**——本波否决
   （边界）：主题归引擎，跨会话归一属探测器职责；未来如需求成立
   以加性方式引入；
10. **一次 `distill` 调用处理整批（跨主题）**——否决：主题归属需要
    策略输出 topic 或引擎猜测；分组调用让主题归属确定、提示词聚焦；
11. **终结促进保持无键覆盖**——否决：仍会塌缩；机械键（块 id）无
    模型成本且不塌缩。

**主题不变式**（承接）

12. **维持切换刷写整段**——否决：违反主题不变式，L2 记录内容与
    标签不一致；
13. **切换时重标旧段**——否决：改历史、审计语义混乱；按连续段
    分组压实已足够；
14. **L2 保留"产生时刻话题"语义**——否决：与分组压实后的事实不符，
    管理面按主题过滤会错配。

**核心视图与组件富面**（本轮新增）

15. **`unit_key` / `memory_type` 留在核心 `MemoryItem`**——否决：
    核心公开契约必须可解释、跨实现可担保；组件语义（单元/分层
    类型）进核心即边界泄漏，且默认（非分层）模型填不出真实语义；
16. **核心条目用 opaque attributes 透传**——否决：弱类型、
    stringly-typed；通用透传机制无广泛需求（§2）；
17. **组件富面直接公开内部条目类型**（`L2Entry` / `L3Entry`）——
    否决：内部结构（队列/键集细节）成为公开契约，两套字段需同步
    演进；
18. **不提供组件富面**——否决：产品需求（按主题列点、键作标题、
    按类型查看）落空。

**管理面寻址**（承接）

19. **不暴露 `unit_key`**——否决：产品侧"列出单元（标题 + 内容）"
    需要键作标题；`Option` 加性、不影响 `Summary`；
20. **不加 topic 过滤**——否决：单元模型的核心寻址是"按主题管理"；
21. **新增 reader 枚举方法**（`l3_units` / `l3_list`）——本轮否决
    （加性后续）：唯一调用者是策略侧对账，`l3_query` 已覆盖检索式
    对账；有界枚举的完备性也不完全。

## Consequences（后果）

**破坏项（0.7.0 单波）**

- **核心公开面**：`MemoryItem` 最小化（`memory_type` / `unit_key`
  不在核心）；`MemoryQuery` 去 `memory_type` 过滤；`MemoryType`、
  相位列表（`MemoryListCursor.memory_type`）移出核心；核心列表扁平
  ——**修订 ADR-0020 相应部分**；
- **组件公开面（原核心公开）**：分层条目类型、策略契约、存储契约、
  in-process 存储实现从核心迁入组件（自定义实现者改为依赖组件）；
- `L3Identity` 构成变化：`conversation_id` → `unit_key`；`L3Entry`
  增加 `source`（构造入口调整）；
- `MemoryDistiller::distill` 输出类型 `Vec<String>` →
  `Vec<MemoryDistilledUnit>`（自定义蒸馏策略必须适配）；
- `MemoryL3Store::upsert` 的身份语义随 `L3Identity` 变化；自定义
  L3 存储的身份索引键按新身份重建；
- L2 压实行为与 `L2Entry.topic` 语义变化：分组压实、切换刷写只压
  旧话题段（观察行为变化）；
- 机械促进不再覆盖：每块一条、`topic = block.topic`；
- 数据兼容：0.6.0 序列化数据不支持（无迁移）；移除旧 `serde` 兜底；
- `L2Entry.index` 移除。

**加性项**

- 组件富管理面：单一富条目类型（`memory_type` + `unit_key`）、富
  查询（类型 / 单元键过滤）、组件句柄取用；
- 核心 `MemoryQuery.topic` 过滤（承接 ADR-0021 §5）；
- 组件进展事件（count = 成功写入单元数）；
- 组件公开类型 `MemoryDistilledUnit`（策略签名）。

**边界（本 ADR 明确不做）**

- 策略覆盖 topic（跨会话归一的策略侧改写）——归探测器 / 策略职责，
  未来可加性；
- L2 主题记忆（合并式更新）——L2 保持时间片流；
- L1 加 id / 参与管理（L1 留存与会话级清理另行立项）；
- 语义搜索、跨单元矛盾消解、事实聚合——策略层能力；
- provider 装配方式、观察面接口形态、组件包装——实现设计；
- 数据迁移工具与数据迁移章（无旧数据）。

**文档义务**

- v8 架构文档（记忆单元模型、组件公开面、核心最小视图；v7 转
  SUPERSEDED）；
- 0.7.0 实施计划；
- 扩展指南更新：distiller 单元草案与键复用配方（`l3_query` 对账）、
  探测器主题稳定要求、分组压实说明、组件富管理面用法；
- CHANGELOG（破坏项 + API 适配说明）；README 指针更新（v8 + 计划）；
- API 适配说明（短篇，替代迁移指南）：自定义 distiller（输出类型）、
  自定义 L3 存储（身份构成、`list` 的 topic 过滤）、探测器（主题
  稳定建议）、核心最小视图迁移（类型 / 单元键改用组件富面）；
  数据兼容边界声明。

**验证要求**

- **多单元并存**：一次蒸馏多块 → 多个 L3 单元（不同键）并存，不再
  塌缩；进展事件的 count 与实际写入单元数一致；
- **同单元原位演进**：同键跨批次、跨会话（同 subject/topic）写入
  → 同一条、id 不变、`updated_at` 刷新、`source` 更新为最近写入者；
- **L2 主题不变式**：含多主题的 L1 批 → 多条 L2 单元、各盖组主题；
  切换刷写不把切换当轮并入旧话题摘要；`L2Entry.topic` = 内容主题；
- **促进**：按 `block.topic` 盖章、每块一条、计数真实；
- **读 / 消费分离**：策略读 L1/L2/L3 不改变任何层；仅本组来源被
  按 id 认领；来源在途变化 → 丢弃该组产物并可见（确定性竞态测试）；
- **管理面**：核心最小视图不含类型 / 单元键（编译期）；组件富视图
  按 topic / `memory_type` / `unit_key` 列点与批量遗忘；`unit_key`
  对 `Knowledge` 可见、对 `Summary` 为 `None`；
- **存储契约**：组件 L1/L2/L3 端口通过新身份与 topic 过滤回归；
- **公开面**：策略无法构造 / 覆盖身份、时间、溯源（编译期检查）。
